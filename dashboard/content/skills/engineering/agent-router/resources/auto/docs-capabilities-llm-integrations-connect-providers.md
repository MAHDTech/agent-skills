tocCollapsibleButton_TO0P">On this page</button></div><div class="theme-doc-markdown markdown">\<header\>\<h1\>Connecting to AI Providers</h1></header>
<p>Agent Router provides a unified interface for connecting to multiple AI providers through a standardized configuration approach. This page explains the fundamental concepts, resources, and relationships required to establish connectivity with any supported AI provider.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="overview">Overview<a href="#overview" class="hash-link" aria-label="Direct link to Overview" title="Direct link to Overview" translate="no">​</a></h2>
<p>Establishing connectivity with an AI provider involves configuring three key Kubernetes resources that work together to enable secure, scalable access to AI services:</p>
\<ol\>
<li class=""><strong>AIServiceBackend</strong> - Defines the backend service and its API schema</li>
<li class=""><strong>BackendSecurityPolicy</strong> - Configures authentication credentials</li>
<li class=""><strong>AIGatewayRoute</strong> - Routes client requests to the appropriate backends</li>
</ol>
<p>These resources provide a consistent configuration model regardless of which AI provider you&#x27;re connecting to, whether it&#x27;s OpenAI, AWS Bedrock, Azure OpenAI, or any other <a class="" href="/docs/capabilities/llm-integrations/supported-providers">supported provider</a>.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="core-resources-for-provider-connectivity">Core Resources for Provider Connectivity<a href="#core-resources-for-provider-connectivity" class="hash-link" aria-label="Direct link to Core Resources for Provider Connectivity" title="Direct link to Core Resources for Provider Connectivity" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="aiservicebackend">AIServiceBackend<a href="#aiservicebackend" class="hash-link" aria-label="Direct link to AIServiceBackend" title="Direct link to AIServiceBackend" translate="no">​</a></h3>
<p>The <code>AIServiceBackend</code> resource represents an individual AI service backend and serves as the bridge between your gateway and the AI provider&#x27;s API.</p>
<h4 class="anchor anchorTargetStickyNavbar_Vzrq" id="purpose-and-configuration">Purpose and Configuration<a href="#purpose-and-configuration" class="hash-link" aria-label="Direct link to Purpose and Configuration" title="Direct link to Purpose and Configuration" translate="no">​</a></h4>
\<ul\>
<li class=""><strong>API Schema Definition</strong>: Specifies which API format the backend expects (OpenAI v1, AWS Bedrock, Azure OpenAI, etc.)</li>
<li class=""><strong>Backend Reference</strong>: Points to the Envoy Gateway Backend resource</li>
<li class=""><strong>Security Integration</strong>: Links to authentication policies for upstream services</li>
</ul>

<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="resource-relationships-and-data-flow">Resource Relationships and Data Flow<a href="#resource-relationships-and-data-flow" class="hash-link" aria-label="Direct link to Resource Relationships and Data Flow" title="Direct link to Resource Relationships and Data Flow" translate="no">​</a></h2>
<p>Understanding how these resources work together is crucial for successful provider connectivity:</p>
<!-- -->
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="data-flow-process">Data Flow Process<a href="#data-flow-process" class="hash-link" aria-label="Direct link to Data Flow Process" title="Direct link to Data Flow Process" translate="no">​</a></h3>
\<ol\>
<li class=""><strong>Request Reception</strong>: Client sends a request to the AI Gateway with the OpenAI-compatible format</li>
<li class=""><strong>Route Matching</strong>: AIGatewayRoute examines request headers (like <code>x-ai-eg-model</code>) to determine the target backend</li>
<li class=""><strong>Backend Resolution</strong>: The matching rule identifies the appropriate AIServiceBackend</li>
<li class=""><strong>Authentication</strong>: The AIServiceBackend&#x27;s security policy provides credentials for upstream authentication</li>
<li class=""><strong>Schema Transformation</strong>: If needed, the request is transformed from the input schema to the backend&#x27;s expected schema</li>
<li class=""><strong>Provider Communication</strong>: The request is forwarded to the actual AI provider with proper authentication</li>
<li class=""><strong>Response Processing</strong>: The provider&#x27;s response is transformed back to the unified schema format</li>
<li class=""><strong>Client Response</strong>: The standardized response is returned to the client</li>
</ol>

<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="provider-specific-considerations">Provider-Specific Considerations<a href="#provider-specific-considerations" class="hash-link" aria-label="Direct link to Provider-Specific Considerations" title="Direct link to Provider-Specific Considerations" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="openai-compatible-providers">OpenAI-Compatible Providers<a href="#openai-compatible-providers" class="hash-link" aria-label="Direct link to OpenAI-Compatible Providers" title="Direct link to OpenAI-Compatible Providers" translate="no">​</a></h3>
<p>Many providers offer OpenAI-compatible APIs:</p>
\<ul\>
<li class="">Use OpenAI schema configuration</li>
<li class="">Adjust the version field if the provider uses custom paths</li>
<li class="">Standard API key authentication typically applies</li>
</ul>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="cloud-provider-integration">Cloud Provider Integration<a href="#cloud-provider-integration" class="hash-link" aria-label="Direct link to Cloud Provider Integration" title="Direct link to Cloud Provider Integration" translate="no">​</a></h3>
<p>Cloud providers like AWS Bedrock and Azure OpenAI require:</p>
\<ul\>
<li class="">Cloud-specific credential types (AWS IAM, Azure Service Principal, GCP Workload Identity)</li>
<li class="">Region specification for multi-region services</li>
<li class="">Custom schema configurations for native APIs</li>
</ul>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="self-hosted-models">Self-Hosted Models<a href="#self-hosted-models" class="hash-link" aria-label="Direct link to Self-Hosted Models" title="Direct link to Self-Hosted Models" translate="no">​</a></h3>
<p>Self-hosted models using frameworks like vLLM:</p>
\<ul\>
<li class="">Often compatible with OpenAI schema</li>
<li class="">May not require authentication (internal networks)</li>
<li class="">Custom endpoints through Envoy Gateway Backend resources</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="validation-and-troubleshooting">Validation and Troubleshooting<a href="#validation-and-troubleshooting" class="hash-link" aria-label="Direct link to Validation and Troubleshooting" title="Direct link to Validation and Troubleshooting" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="configuration-validation">Configuration Validation<a href="#configuration-validation" class="hash-link" aria-label="Direct link to Configuration Validation" title="Direct link to Configuration Validation" translate="no">​</a></h3>
<p>The AI Gateway validates configurations at deployment time:</p>
\<ul\>
<li class=""><strong>Schema Compatibility</strong>: Ensures input and output schemas are compatible</li>
<li class=""><strong>Resource References</strong>: Validates that referenced resources exist</li>
<li class=""><strong>Credential Access</strong>: Verifies that secrets are accessible</li>
</ul>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="status-conditions">Status Conditions<a href="#status-conditions" class="hash-link" aria-label="Direct link to Status Conditions" title="Direct link to Status Conditions" translate="no">​</a></h3>
<p>All resources provide status conditions to monitor their health:</p>
\<ul\>
<li class=""><strong>Accepted</strong>: Resource is valid and has been accepted by the controller</li>
<li class=""><strong>NotAccepted</strong>: Resource has validation errors or configuration issues</li>
</ul>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="common-issues-and-solutions">Common Issues and Solutions<a href="#common-issues-and-solutions" class="hash-link" aria-label="Direct link to Common Issues and Solutions" title="Direct link to Common Issues and Solutions" translate="no">​</a></h3>
<p><strong>Authentication Failures (401/403)</strong></p>
\<ul\>
<li class="">Verify API keys and credentials are correct</li>
<li class="">Check secret references and key names</li>
<li class="">Ensure credentials have necessary permissions</li>
</ul>
<p><strong>Schema Mismatch Errors</strong></p>
\<ul\>
<li class="">Confirm the backend schema matches the provider&#x27;s API</li>
<li class="">Check version specifications for provider-specific paths</li>
<li class="">Review API documentation for schema requirements</li>
</ul>
<p><strong>Routing Issues</strong></p>
\<ul\>
<li class="">Verify header matching rules in AIGatewayRoute</li>
<li class="">Check that model names match expected values</li>
<li class="">Ensure backend references point to existing AIServiceBackends</li>
</ul>
<p><strong>Backend Reference Errors</strong></p>
\<ul\>
<li class="">Ensure backendRef points to Envoy Gateway Backend resources</li>
<li class="">Verify the Backend resource exists and is properly configured</li>
<li class="">Check that the group field is set to <code>gateway.envoyproxy.io</code></li>
</ul>
