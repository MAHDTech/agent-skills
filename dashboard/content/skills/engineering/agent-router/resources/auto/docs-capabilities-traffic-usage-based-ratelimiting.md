<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="overview">Overview<a href="#overview" class="hash-link" aria-label="Direct link to Overview" title="Direct link to Overview" translate="no">​</a></h2>
<p>AI Gateway leverages Envoy Gateway&#x27;s Global Rate Limit API to provide token-based rate limiting for LLM requests. Key features include:</p>
\<ul\>
<li class="">Token usage tracking based on model and user identifiers</li>
<li class="">Configuration for tracking input, output, and total token metadata from LLM responses</li>
<li class="">Model-specific rate limiting using AI Gateway headers (<code>x-ai-eg-model</code>) which is inserted by the AI Gateway filter with the model name extracted from the request body.</li>
<li class="">Support for custom token cost calculations using CEL expressions</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="token-usage-behavior">Token Usage Behavior<a href="#token-usage-behavior" class="hash-link" aria-label="Direct link to Token Usage Behavior" title="Direct link to Token Usage Behavior" translate="no">​</a></h2>
<p>AI Gateway has specific behavior for token tracking and rate limiting:</p>
\<ol\>
<li class="">
<p><strong>Token Extraction</strong>: AI Gateway automatically extracts token usage from LLM responses that follow the OpenAI schema format. The token counts are stored in the metadata specified in your <code>llmRequestCosts</code> configuration.</p>
</li>
<li class="">
<p><strong>Rate Limit Timing</strong>: Token usage is charged after the response completes. When a request is received:</p>
\<ul\>
<li class="">Envoy checks the token budget using usage that has already been charged</li>
<li class="">If the existing charged usage is over the limit, the request is rejected with a 429 status code</li>
<li class="">If the request is admitted, AI Gateway extracts token usage from the completed response and charges it towards the total</li>
</ul>
</li>
<li class="">
<p><strong>Token Types</strong>:</p>
\<ul\>
<li class=""><code>InputToken</code>: Counts tokens in the request prompt</li>
<li class=""><code>CachedInputToken</code>: Counts <em>cached</em> input tokens in the request prompt</li>
<li class=""><code>OutputToken</code>: Counts tokens in the model&#x27;s response</li>
<li class=""><code>TotalToken</code>: Combines both input and output tokens</li>
<li class=""><code>CEL</code>: Allows custom token calculations using CEL expressions</li>
</ul>
</li>
<li class="">
<p><strong>Multiple Rate Limits</strong>: You can configure multiple rate limit rules for the same user-model combination. For example:</p>
\<ul\>
<li class="">Limit total tokens per hour</li>
<li class="">Separate limits for input and output tokens</li>
<li class="">Custom limits using CEL expressions</li>
</ul>
</li>
<li class="">
<p><strong>Per Route Custom Token Calculation</strong>: The <code>llmRequestCosts</code> defined in your <code>AIGatewayRoute</code> spec are scoped exclusively to that specific route. This means multiple <code>AIGatewayRoute</code> resources can define the exact same metadata keys, but the gateway will independently apply the correct calculations based on the route&#x27;s name and namespace.</p>
</li>
</ol>
<p>To map the request to the correct calculation, the AI Gateway parses the route from the Envoy Gateway Metadata. If that metadata is not present, it falls back to parsing the route name from the route configuration, assuming Envoy Gateway has generated the name in the following format: <code>httproute/\<namespace\>/\<name\>/rule/<index></code>.</p>
<div class="theme-admonition theme-admonition-note admonition_xJq3 alert alert--secondary"><div class="admonitionHeading_Gvgb"><span class="admonitionIcon_Rf37"><svg viewBox="0 0 14 16"><path fill-rule="evenodd" d="M6.3 5.69a.942.942 0 0 1-.28-.7c0-.28.09-.52.28-.7.19-.18.42-.28.7-.28.28 0 .52.09.7.28.18.19.28.42.28.7 0 .28-.09.52-.28.7a1 1 0 0 1-.7.3c-.28 0-.52-.11-.7-.3zM8 7.99c-.02-.25-.11-.48-.31-.69-.2-.19-.42-.3-.69-.31H6c-.27.02-.48.13-.69.31-.2.2-.3.44-.31.69h1v3c.02.27.11.5.31.69.2.2.42.31.69.31h1c.27 0 .48-.11.69-.31.2-.19.3-.42.31-.69H8V7.98v.01zM7 2.3c-3.14 0-5.7 2.54-5.7 5.68 0 3.14 2.56 5.7 5.7 5.7s5.7-2.55 5.7-5.7c0-3.15-2.56-5.69-5.7-5.69v.01zM7 .98c3.86 0 7 3.14 7 7s-3.14 7-7 7-7-3.12-7-7 3.14-7 7-7z"></path></svg></span>note</div><div class="admonitionContent_BuS1"><p>For model providers with OpenAI schema transformations (like AWS Bedrock), AI Gateway automatically captures token usage through its request/response transformer. This enables consistent token tracking and rate limiting across different AI services using a unified OpenAI-compatible format.</p></div></div>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="streaming-responses">Streaming responses<a href="#streaming-responses" class="hash-link" aria-label="Direct link to Streaming responses" title="Direct link to Streaming responses" translate="no">​</a></h3>
<p>For streaming responses, token usage is only known after the stream completes and the final usage
data has been observed. AI Gateway does not interrupt an already admitted stream if that stream
pushes the token count over the configured limit. Instead, the stream completes, its token usage is
charged at stream end, and later matching requests are rejected with <code>429 Too Many Requests</code> until
enough usage expires from the rate-limit window.</p>
<p>For example, with a 1,000-token hourly limit, a request that is admitted while the bucket is empty
can stream 1,200 tokens successfully. The bucket is then 200 tokens over the limit, and subsequent
matching requests are limited until the window has enough capacity again.</p>

<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="per-tenant-limits-without-per-tenant-policies">Per-Tenant Limits Without Per-Tenant Policies<a href="#per-tenant-limits-without-per-tenant-policies" class="hash-link" aria-label="Direct link to Per-Tenant Limits Without Per-Tenant Policies" title="Direct link to Per-Tenant Limits Without Per-Tenant Policies" translate="no">​</a></h2>
<p>The rate limits above use a static limit value defined in the <code>BackendTrafficPolicy</code> (for example <code>requests: 1000</code>). If each tenant needs a different number, that forces a policy per tenant — and, because the policy attaches to routes, often a set of routes per tenant too. At a few thousand tenants that is the dominant cost of the configuration.</p>
<p>Envoy can instead read the limit value from <strong>dynamic metadata</strong> on each request, so one shared policy serves every tenant and the tenant&#x27;s own number arrives with the request. Envoy Gateway exposes this as <code>limit.fromMetadata</code> on the rate limit rule.</p>
<p>Nothing about this requires AI Gateway. Any Envoy filter that writes dynamic metadata can supply the number, and the policy points directly at whatever namespace that filter writes to. AI Gateway&#x27;s part is the other half — turning the LLM&#x27;s token usage into the <strong>cost</strong> charged against the budget, which is covered above and is the piece nothing else can do.</p>
<div class="theme-admonition theme-admonition-note admonition_xJq3 alert alert--secondary"><div class="admonitionHeading_Gvgb"><span class="admonitionIcon_Rf37"><svg viewBox="0 0 14 16"><path fill-rule="evenodd" d="M6.3 5.69a.942.942 0 0 1-.28-.7c0-.28.09-.52.28-.7.19-.18.42-.28.7-.28.28 0 .52.09.7.28.18.19.28.42.28.7 0 .28-.09.52-.28.7a1 1 0 0 1-.7.3c-.28 0-.52-.11-.7-.3zM8 7.99c-.02-.25-.11-.48-.31-.69-.2-.19-.42-.3-.69-.31H6c-.27.02-.48.13-.69.31-.2.2-.3.44-.31.69h1v3c.02.27.11.5.31.69.2.2.42.31.69.31h1c.27 0 .48-.11.69-.31.2-.19.3-.42.31-.69H8V7.98v.01zM7 2.3c-3.14 0-5.7 2.54-5.7 5.68 0 3.14 2.56 5.7 5.7 5.7s5.7-2.55 5.7-5.7c0-3.15-2.56-5.69-5.7-5.69v.01zM7 .98c3.86 0 7 3.14 7 7s-3.14 7-7 7-7-3.12-7-7 3.14-7 7-7z"></path></svg></span>Requires Envoy Gateway with <code>limit.fromMetadata</code></div><div class="admonitionContent_BuS1"><p><code>limit.fromMetadata</code> was added in <a href="https://github.com/envoyproxy/gateway/pull/9216" target="_blank" rel="noopener noreferrer" class="">envoyproxy/gateway#9216</a>. <h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="behavior-to-plan-for">Behavior to plan for<a href="#behavior-to-plan-for" class="hash-link" aria-label="Direct link to Behavior to plan for" title="Direct link to Behavior to plan for" translate="no">​</a></h3>
<table><thead><tr><th>Metadata value</th><th>Effect</th></tr></thead>\<tbody\><tr><td>a valid <code>{ requests_per_unit, unit }</code> struct</td><td>becomes the limit for that request</td></tr><tr><td>absent</td><td>the static <code>requests</code>/<code>unit</code> on the rule applies</td></tr><tr><td><code>requests_per_unit: 0</code></td><td>a real limit of <code>0</code> — see below</td></tr></tbody></table>
<div class="theme-admonition theme-admonition-warning admonition_xJq3 alert alert--warning"><div class="admonitionHeading_Gvgb"><span class="admonitionIcon_Rf37"><svg viewBox="0 0 16 16"><path fill-rule="evenodd" d="M8.893 1.5c-.183-.31-.52-.5-.887-.5s-.703.19-.886.5L.138 13.499a.98.98 0 0 0 0 1.001c.193.31.53.501.886.501h13.964c.367 0 .704-.19.877-.5a1.03 1.03 0 0 0 .01-1.002L8.893 1.5zm.133 11.497H6.987v-2.003h2.039v2.003zm0-3.004H6.987V5.987h2.039v4.006z"></path></svg></span>Missing metadata fails open to the static default</div><div class="admonitionContent_BuS1"><p>When the metadata is absent — the auth server didn&#x27;t set it, or was bypassed — the request falls back to the static <code>requests</code>/<code>unit</code>. Because that direction is permissive, keep the static value a <strong>conservative ceiling</strong> rather than a placeholder.</p></div></div>
<div class="theme-admonition theme-admonition-caution admonition_xJq3 alert alert--warning"><div class="admonitionHeading_Gvgb"><span class="admonitionIcon_Rf37"><svg viewBox="0 0 16 16"><path fill-rule="evenodd" d="M8.893 1.5c-.183-.31-.52-.5-.887-.5s-.703.19-.886.5L.138 13.499a.98.98 0 0 0 0 1.001c.193.31.53.501.886.501h13.964c.367 0 .704-.19.877-.5a1.03 1.03 0 0 0 .01-1.002L8.893 1.5zm.133 11.497H6.987v-2.003h2.039v2.003zm0-3.004H6.987V5.987h2.039v4.006z"></path></svg></span>A <code>requests_per_unit</code> of <code>0</code> suspends the tenant</div><div class="admonitionContent_BuS1"><p><code>0</code> is a real limit, and it is the deliberate way to suspend a tenant. Exactly when it starts denying depends on how you charge cost:</p>\<ul\>
<li class=""><strong>Token cost</strong> (<code>cost.request.from: Number, number: 0</code>, charged from the response) — the budget is checked before anything is charged, so the request already in flight is admitted and everything after it is denied.</li>
<li class=""><strong>Request count</strong> (no <code>cost</code> block, one unit per request) — denied immediately, including the first request.</li>
</ul><p>So a source meaning <em>"I have no opinion about this request"</em> must <strong>omit</strong> the field entirely. Emitting <code>0</code> from an uninitialized field, a failed lookup, or a tenant record with no quota set suspends that tenant instead of falling back.</p></div></div>
<div class="theme-admonition theme-admonition-note admonition_xJq3 alert alert--secondary"><div class="admonitionHeading_Gvgb"><span class="admonitionIcon_Rf37"><svg viewBox="0 0 14 16"><path fill-rule="evenodd" d="M6.3 5.69a.942.942 0 0 1-.28-.7c0-.28.09-.52.28-.7.19-.18.42-.28.7-.28.28 0 .52.09.7.28.18.19.28.42.28.7 0 .28-.09.52-.28.7a1 1 0 0 1-.7.3c-.28 0-.52-.11-.7-.3zM8 7.99c-.02-.25-.11-.48-.31-.69-.2-.19-.42-.3-.69-.31H6c-.27.02-.48.13-.69.31-.2.2-.3.44-.31.69h1v3c.02.27.11.5.31.69.2.2.42.31.69.31h1c.27 0 .48-.11.69-.31.2-.19.3-.42.31-.69H8V7.98v.01zM7 2.3c-3.14 0-5.7 2.54-5.7 5.68 0 3.14 2.56 5.7 5.7 5.7s5.7-2.55 5.7-5.7c0-3.15-2.56-5.69-5.7-5.69v.01zM7 .98c3.86 0 7 3.14 7 7s-3.14 7-7 7-7-3.12-7-7 3.14-7 7-7z"></path></svg></span>When the source can&#x27;t produce the struct</div><div class="admonitionContent_BuS1"><p>Some sources emit their own shape and can&#x27;t be changed — <code>jwt_authn</code> writes claims verbatim, and a third-party auth sidecar may only return a string like <code>"100000/HOUR"</code>. Envoy&#x27;s override reads only the <code>{ requests_per_unit, unit }</code> struct, so in that case you need a filter in between to transcode it, such as a small Lua filter writing the struct into its own metadata namespace and pointing <code>fromMetadata</code> there.</p></div></div>
