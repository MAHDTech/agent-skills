<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="environment-variables">Environment variables<a href="#environment-variables" class="hash-link" aria-label="Direct link to Environment variables" title="Direct link to Environment variables" translate="no">​</a></h2>
<p>Named submodules cannot declare a nonempty <a class="" href="/docs/databases/environment-variables">environment</a>. Such declarations cause composition or publication to fail. A module with environment declarations can still be published independently as a root module.</p>
<p>In C#, dependencies registered in the default <code>public</code> scope are an exception: their declarations contribute to the root environment schema.</p>
<p>Named submodules have no separate environment-variable namespace, and their host-dispatched entry points cannot read the root module&#x27;s environment. Root module code can pass configuration values to helpers explicitly. Ordinary helper calls retain the calling entry point&#x27;s access, including calls to helpers defined in submodules.</p>

<p>Both parts of the wire name are canonical: the namespace prefix and the function name after <code>.</code>.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="namespace-name-rules">Namespace Name Rules<a href="#namespace-name-rules" class="hash-link" aria-label="Direct link to Namespace Name Rules" title="Direct link to Namespace Name Rules" translate="no">​</a></h2>
<p>Each accessor and canonical namespace segment must be a valid SpacetimeDB identifier: start with a letter or underscore, continue with letters, digits, or underscores, maximum 63 UTF-8 bytes, case-insensitive for resolution. Two submodules in the same parent scope cannot share a canonical name, so <code>myAuth</code> and <code>my_auth</code> cannot both be registered there under the default policy. Different parent scopes can reuse the same child namespace name.</p>
<p>The reserved namespaces <code>st</code>, <code>spacetimedb</code>, and names starting with <code>pg_</code> cannot be used. <code>public</code> is the default scope, not a named submodule namespace.</p>
<div class="theme-tabs-container tabs-container tabList_duiv"><ul role="tablist" aria-orientation="horizontal" class="tabs"><li role="tab" tabindex="0" aria-selected="true" class="tabs__item tabItem_a1H9 tabs__item--active">TypeScript</li><li role="tab" tabindex="-1" aria-selected="false" class="tabs__item tabItem_a1H9">C#</li></ul><div class="margin-top--md"><div role="tabpanel" class="tabItem_w6aI"><p>The schema key is the accessor name. The canonical name is derived from it unless explicitly set with <code>name</code>. A submodule can be registered under at most one namespace per consumer module.</p></div><div role="tabpanel" class="tabItem_w6aI" hidden=""><p><code>Accessor</code> sets the accessor name. The canonical name is derived from it unless explicitly set with <code>Name</code>. Use <code>Accessor = "public"</code> to register a dependency in the default scope with flat accessors.</p><p>Accessors must also be valid C# identifiers. For a keyword, use its plain spelling in the attribute (<code>Accessor = "class"</code>) and escape it in expressions (<code>ctx.Db.@class.User</code>).</p></div></div></div>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="limitations">Limitations<a href="#limitations" class="hash-link" aria-label="Direct link to Limitations" title="Direct link to Limitations" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="submodule-routers-are-not-applied-automatically">Submodule routers are not applied automatically<a href="#submodule-routers-are-not-applied-automatically" class="hash-link" aria-label="Direct link to Submodule routers are not applied automatically" title="Direct link to Submodule routers are not applied automatically" translate="no">​</a></h3>
<p>Routes from named submodules are ignored. Register handlers explicitly on the root router, as shown in the <a href="#from-an-http-handler" class="">HTTP handler section</a>. In C#, dependencies registered in <code>public</code> can contribute routes to root-level routing.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="row-level-security-belongs-in-the-root">Row-level security belongs in the root<a href="#row-level-security-belongs-in-the-root" class="hash-link" aria-label="Direct link to Row-level security belongs in the root" title="Direct link to Row-level security belongs in the root" translate="no">​</a></h3>
<p>Define <a class="" href="/docs/how-to/rls">row-level security</a> filters in the root, referring to canonical qualified table names. Filters declared inside named submodules do not protect their tables.</p>
<div class="theme-tabs-container tabs-container tabList_duiv"><ul role="tablist" aria-orientation="horizontal" class="tabs"><li role="tab" tabindex="0" aria-selected="true" class="tabs__item tabItem_a1H9 tabs__item--active">TypeScript</li><li role="tab" tabindex="-1" aria-selected="false" class="tabs__item tabItem_a1H9">C#</li></ul><div class="margin-top--md"><div role="tabpanel" class="tabItem_w6aI"><p>Submodule filter declarations are accepted by the SDK, but the host does not install them. Export filters from the root schema instead, using qualified table names such as <code>myauth.users</code>.</p></div><div role="tabpanel" class="tabItem_w6aI" hidden=""><p>Named dependencies cannot declare filters; the source generator rejects them. Define filters in the root instead, using qualified table names such as <code>auth_data.auth_users</code>.</p></div></div></div></div><footer class="theme-doc-footer docusaurus-mt-lg"><div class="row
