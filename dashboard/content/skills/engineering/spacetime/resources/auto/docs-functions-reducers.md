<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="transactional-execution">Transactional Execution<a href="#transactional-execution" class="hash-link" aria-label="Direct link to Transactional Execution" title="Direct link to Transactional Execution" translate="no">​</a></h2>
<p>Every reducer runs inside a database transaction. This provides important guarantees:</p>
\<ul\>
<li class=""><strong>Isolation</strong>: Reducers don&#x27;t see changes from other concurrent reducers</li>
<li class=""><strong>Atomicity</strong>: Either all changes succeed or all are rolled back</li>
<li class=""><strong>Consistency</strong>: Failed reducers leave the database unchanged</li>
</ul>
<p>If a reducer throws an exception or returns an error, all of its changes are automatically rolled back.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="accessing-tables">Accessing Tables<a href="#accessing-tables" class="hash-link" aria-label="Direct link to Accessing Tables" title="Direct link to Accessing Tables" translate="no">​</a></h2>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="reducer-isolation">Reducer Isolation<a href="#reducer-isolation" class="hash-link" aria-label="Direct link to Reducer Isolation" title="Direct link to Reducer Isolation" translate="no">​</a></h2>
<p>Reducers run in an isolated environment and <strong>cannot</strong> interact with the outside world:</p>
\<ul\>
<li class="">❌ No network requests</li>
<li class="">❌ No file system access</li>
<li class="">❌ No system calls</li>
<li class="">✅ Only database operations</li>
</ul>
<p>If you need to interact with external systems, use <a class="" href="/docs/functions/procedures">Procedures</a> instead. Procedures can make network calls and perform other side effects, but they have different execution semantics and limitations.</p>
<div class="theme-admonition theme-admonition-warning admonition_Ph9R alert alert--warning"><div class="admonitionHeading_kG9t"><span class="admonitionIcon_VA_f"><svg viewBox="0 0 16 16"><path fill-rule="evenodd" d="M8.893 1.5c-.183-.31-.52-.5-.887-.5s-.703.19-.886.5L.138 13.499a.98.98 0 0 0 0 1.001c.193.31.53.501.886.501h13.964c.367 0 .704-.19.877-.5a1.03 1.03 0 0 0 .01-1.002L8.893 1.5zm.133 11.497H6.987v-2.003h2.039v2.003zm0-3.004H6.987V5.987h2.039v4.006z"></path></svg></span>Global and Static Variables Are Undefined Behavior</div><div class="admonitionContent_STxx"><p>Relying on global variables, static variables, or module-level state to persist across reducer calls is <strong>undefined behavior</strong>. SpacetimeDB does not guarantee that values stored in these locations will be available in subsequent reducer invocations.</p><p>This is undefined for several reasons:</p>\<ol\>
<li class=""><strong>Fresh execution environments.</strong> SpacetimeDB may run each reducer in a fresh WASM or JS instance.</li>
<li class=""><strong>Module updates.</strong> Publishing a new module creates a fresh execution environment. This is necessary for hot-swapping modules while transactions are in flight.</li>
<li class=""><strong>Concurrent execution.</strong> SpacetimeDB reserves the right to execute multiple reducers concurrently in separate execution environments (e.g., with MVCC).</li>
<li class=""><strong>Crash recovery.</strong> Instance memory is not persisted across restarts.</li>
<li class=""><strong>Non-transactional updates.</strong> If you modify global state and then roll back the transaction, the modified value may remain for subsequent transactions.</li>
<li class=""><strong>Replay safety.</strong> If a serializability anomaly is detected, SpacetimeDB may re-execute your reducer with the same arguments, causing modifications to global state to occur multiple times.</li>
</ol><p>Reducers are designed to be free of side effects. They should only modify tables. Always store state in tables to ensure correctness and durability.</p><pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#6272A4">// ❌ Undefined behavior: may or may not persist or correctly update across reducer calls</span></span>
