class="admonitionContent_STxx"><p>You need a module and a client connected to it. If you don&#x27;t have them yet, follow the <a class="" href="/docs/">quickstart</a> for your language first.</p><p>This guide uses views that take arguments, which were added in SpacetimeDB 2.13. <p>In this guide, you&#x27;ll build a feed of posts that loads 50 posts at a time as the user scrolls. Each client only receives the pages it has loaded, and those pages stay live: new posts show up as soon as they&#x27;re published. You&#x27;ll use a <a class="" href="/docs/functions/views">view</a> that takes a page number and a page size as arguments.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-it-works">How it works<a href="#how-it-works" class="hash-link" aria-label="Direct link to How it works" title="Direct link to How it works" translate="no">​</a></h2>
\<ul\>
<li class="">A private <code>post</code> table holds the posts, with an index on their <code>id</code>.</li>
<li class="">A <code>create_post</code> reducer adds a post.</li>
<li class="">A <code>feed_page</code> view takes a page number and a page size, and returns the posts of that page, newest first. With a page size of 50, page 0 holds the 50 newest posts, page 1 the 50 before them, and so on.</li>
<li class="">Clients subscribe to <code>feed_page</code> once for each page they load, and drop the subscriptions of pages they no longer need.</li>
</ul>
<p>Subscriptions keep a set of rows up to date, but they can&#x27;t sort rows or stop after a given number of them: they have no <code>ORDER BY</code> or <code>LIMIT</code>. A view runs your own code, so it can sort the posts and return a single page.</p>

It&#x27;s a regular index rather than a primary key, because a primary key can only look up one value at a time, not a range of them.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="define-the-view">Define the view<a href="#define-the-view" class="hash-link" aria-label="Direct link to Define the view" title="Direct link to Define the view" translate="no">​</a></h2>
<p>Add a public anonymous view named <code>feed_page</code>, with two arguments: the page number and the page size. It reads every post with a range query on the <code>id</code> index, starting at 0 and with no upper bound. Then it sorts the posts from newest to oldest, skips the posts of the pages before, and returns the next ones. It caps the page size at 100, so a client can&#x27;t ask for the whole feed at once.</p>
<p>Like a reducer, a view can take arguments. SpacetimeDB computes the view separately for each set of argument values, and because <code>feed_page</code> is anonymous, every client that loads the same page with the same page size shares one result. A view that takes arguments can only be subscribed to as a whole: clients can&#x27;t add a filter to it.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="load-pages-from-the-client">Load pages from the client<a href="#load-pages-from-the-client" class="hash-link" aria-label="Direct link to Load pages from the client" title="Direct link to Load pages from the client" translate="no">​</a></h2>
<p>On the client, subscribe to page 0 to show the newest posts. Keep the subscription handle of each loaded page:</p>
\<ul\>
<li class="">When the user scrolls to the end of the feed, subscribe to the next page. If the loaded pages hold fewer posts than they have room for, the last one isn&#x27;t full and there are no older posts to load.</li>
<li class="">When a page is far off screen, unsubscribe from it. Its posts leave the client cache.</li>
</ul>
<p>In TypeScript and C#, subscribe to a view that takes arguments with SQL, for example <code>SELECT * FROM feed_page(3, 50)</code>. In Rust, use the typed <code>feed_page(3, 50)</code> query. The posts of every loaded page arrive in the same <code>feed_page</code> table in the client cache, which doesn&#x27;t keep them in order, so sort them by <code>id</code> before you display them.</p>
<p>Pages count from the newest post, so a new post moves every post one place down: each loaded page gains a post at the top and passes one on to the next page. The loaded pages keep covering the same positions in the feed, for example the 100 newest posts when pages 0 and 1 are loaded.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="whats-next">What&#x27;s next?<a href="#whats-next" class="hash-link" aria-label="Direct link to What&#x27;s next?" title="Direct link to What&#x27;s next?" translate="no">​</a></h2>
<p>You now have a feed that loads 50 posts at a time, and keeps the loaded pages live:</p>
\<ul\>
<li class="">The <code>feed_page</code> view takes a page number and a page size, and returns that page of posts, newest first. Every client that loads the same page shares one result.</li>
<li class="">Clients subscribe to one page at a time, and unsubscribe from the pages they no longer show.</li>
</ul>
<p>To adapt it to your app:</p>
\<ul\>
<li class=""><strong>Several feeds.</strong> For a feed per channel, add an indexed <code>channel_id</code> column to <code>post</code> and give <code>feed_page</code> a third argument: <code>feed_page(channel_id, page, page_size)</code>. Read the posts with <code>filter</code> on <code>channel_id</code>, so each page only reads, and only runs again for, the posts of its own channel.</li>
<li class=""><strong>Jump to a page.</strong> Subscribe to any page directly, for example to show page 10 without loading pages 0 to 9.</li>
<li class=""><strong>Other sort orders.</strong> To sort by something else, such as likes, index that column and sort by it in the view.</li>
</ul>
<p>To learn more about the features used here, see <a class="" href="/docs/functions/views">Views</a>, <a class="" href="/docs/clients/subscriptions">Subscriptions</a> and <a class="" href="/docs/tables/indexes">Indexes</a>.</p>
