markdown">\<header\>\<h1\>Authorization</h1></header><h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="generating-identities-and-tokens">Generating identities and tokens<a href="#generating-identities-and-tokens" class="hash-link" aria-label="Direct link to Generating identities and tokens" title="Direct link to Generating identities and tokens" translate="no">​</a></h3>
<p>SpacetimeDB can derive an identity from the <code>sub</code> and <code>iss</code> claims of any <a href="https://openid.net/developers/how-connect-works/" target="_blank" rel="noopener noreferrer" class="">OpenID Connect</a> compliant <a href="https://jwt.io/" target="_blank" rel="noopener noreferrer" class="">JSON Web Token</a>.</p>
<p>Clients can request a new identity and token signed by the SpacetimeDB host via <a class="" href="/docs/http/identity#post-v1identity">the <code>POST /v1/identity</code> HTTP endpoint</a>. Such a token will not be portable to other SpacetimeDB clusters.</p>
<p>Alternately, a new identity and token will be generated during an anonymous connection via the WebSocket API, and passed to the client as an <code>IdentityToken</code> message.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="authorization-headers"><code>Authorization</code> headers<a href="#authorization-headers" class="hash-link" aria-label="Direct link to authorization-headers" title="Direct link to authorization-headers" translate="no">​</a></h3>
<p>Many SpacetimeDB HTTP endpoints either require or optionally accept a token in the <code>Authorization</code> header. SpacetimeDB authorization headers are of the form <code>Authorization: Bearer ${token}</code>, where <code>token</code> is an <a href="https://openid.net/developers/how-connect-works/" target="_blank" rel="noopener noreferrer" class="">OpenID Connect</a> compliant <a href="https://jwt.io/" target="_blank" rel="noopener noreferrer" class="">JSON Web Token</a>, such as the one returned from <a class="" href="/docs/http/identity#post-v1identity">the <code>POST /v1/identity</code> HTTP endpoint</a>.</p>
<p>All <code>/v1/database</code> endpoints support anonymous access. If no <code>Authorization</code> header is provided, SpacetimeDB will allocate a new anonymous identity for the request. Anonymous requests can access public information (database info, schemas, names) and can call reducers or run SQL queries, but will only have access to public tables and will be rejected when attempting privileged operations like deleting a database or viewing logs.</p>
