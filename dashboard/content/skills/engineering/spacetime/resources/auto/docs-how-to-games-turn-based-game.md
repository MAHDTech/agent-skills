<p>In this guide, you&#x27;ll build a game of tic-tac-toe where each player has 30 seconds to make a move, and loses the game if they run out of time. The server checks every move, so players can&#x27;t cheat. You&#x27;ll use a <a class="" href="/docs/functions/reducers">reducer</a> to check and apply moves, and a <a class="" href="/docs/tables/schedule-tables">schedule table</a> to end turns that take too long.</p>
<p>The same pattern works for any turn-based game, such as a card game or a strategy game: replace the board and the rules with your own.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-it-works">How it works<a href="#how-it-works" class="hash-link" aria-label="Direct link to How it works" title="Direct link to How it works" translate="no">​</a></h2>
\<ul\>
<li class="">A private <code>game</code> table holds each game: its players, its board, whose turn it is, and when that turn times out.</li>
<li class="">A <code>make_move</code> reducer checks that a move is legal, applies it, then gives the turn to the other player.</li>
<li class="">A private <code>turn_timer</code> schedule table holds one timer per game in progress. When the current turn&#x27;s deadline passes, it calls the <code>turn_timeout</code> reducer.</li>
<li class="">Each move replaces the game&#x27;s timer with a new one. If the timer fires, the player whose turn it is forfeits.</li>
<li class="">A <code>my_games</code> view returns the caller&#x27;s games. Clients subscribe to it, and show the board and a countdown.</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="define-the-tables">Define the tables<a href="#define-the-tables" class="hash-link" aria-label="Direct link to Define the tables" title="Direct link to Define the tables" translate="no">​</a></h2>
<p>Add two tables and a view:</p>
\<ul\>
<li class=""><code>game</code> has one row per game. It&#x27;s private: players read their games through the <code>my_games</code> view. It has an index on each player column. The view combines the two columns with <code>or</code>, and SpacetimeDB can&#x27;t use an index for an <code>or</code>, so it reads every game. That&#x27;s fine while the table is small. If you expect many games, split the view in two, one for each player column, as the <a class="" href="/docs/how-to/social/chat-rooms-and-dms#show-each-player-their-messages">chat guide does for DMs</a>: each view then reads only the caller&#x27;s games through its index.</li>
<li class=""><code>turn_timer</code> is the schedule table. It&#x27;s private too: clients read the deadline from their games instead. Its <code>game_id</code> column is unique, so a game never has more than one timer.</li>
<li class=""><code>my_games</code> is a public view that returns the caller&#x27;s games, as X or as O. Keeping tables private and exposing what clients need through views is the recommended practice: see <a class="" href="/docs/how-to/games/hide-information">Hide information from players</a>.</li>
</ul>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="make-a-move">Make a move<a href="#make-a-move" class="hash-link" aria-label="Direct link to Make a move" title="Direct link to Make a move" translate="no">​</a></h2>
<p>Add a <code>make_move</code> reducer. Clients can call it with any arguments, so it checks everything before it changes the board:</p>
\<ul\>
<li class="">The game exists and isn&#x27;t over.</li>
<li class="">It&#x27;s the caller&#x27;s turn. Players who aren&#x27;t in the game never have the turn, so this also rejects them.</li>
<li class="">The cell is on the board and empty.</li>
</ul>
<p>It then places the caller&#x27;s mark and looks for three in a row. If the caller won, or the board is full, the game is over and its timer is deleted. Otherwise, the turn goes to the other player, with a new deadline and a new timer.</p>

<p>A reducer runs as a single transaction, so a move and a timeout can never both happen, even when the move arrives at the last moment:</p>
\<ul\>
<li class="">If the move commits first, it replaces the timer. SpacetimeDB never calls <code>turn_timeout</code> for a timer that was deleted.</li>
<li class="">If the timeout commits first, the game is over, and the move is rejected.</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="end-turns-that-take-too-long">End turns that take too long<a href="#end-turns-that-take-too-long" class="hash-link" aria-label="Direct link to End turns that take too long" title="Direct link to End turns that take too long" translate="no">​</a></h2>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="whats-next">What&#x27;s next?<a href="#whats-next" class="hash-link" aria-label="Direct link to What&#x27;s next?" title="Direct link to What&#x27;s next?" translate="no">​</a></h2>
<p>You now have a turn-based game where the server enforces both the rules and the time limit:</p>
\<ul\>
<li class=""><code>make_move</code> rejects any move that isn&#x27;t legal, then gives the turn to the other player.</li>
<li class="">Each game has one timer that calls <code>turn_timeout</code> when a turn takes too long, and each move replaces it.</li>
<li class="">Because each reducer is a transaction, a move and a timeout can never both happen.</li>
</ul>
<p>To handle timeouts differently:</p>
\<ul\>
<li class=""><strong>Skip the turn instead of forfeiting.</strong> In <code>turn_timeout</code>, give the turn to the other player and call <code>set_turn_timer</code> with a new deadline, as <code>make_move</code> does. To end games where both players are gone, count each player&#x27;s missed turns and end the game after a few.</li>
<li class=""><strong>Use a chess clock.</strong> Give each player a time budget for the whole game, rather than a fixed time per turn. Store each player&#x27;s remaining time in <code>game</code>, subtract the time each move took, and set the timer to the current player&#x27;s remaining time.</li>
</ul>
<p>In tic-tac-toe, players see the whole board, so <code>my_games</code> returns whole games. For games where players must not see everything, such as card games, see <a class="" href="/docs/how-to/games/hide-information">Hide information from players</a>.</p>
