<p>In this guide, you&#x27;ll fill your game shop&#x27;s item catalog when you first publish your module, and update it when the catalog changes. You&#x27;ll insert the items from the <code>init</code> <a class="" href="/docs/functions/reducers/lifecycle">lifecycle reducer</a>, and store who published the database, so that only they can update the catalog later.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-it-works">How it works<a href="#how-it-works" class="hash-link" aria-label="Direct link to How it works" title="Direct link to How it works" translate="no">​</a></h2>
\<ul\>
<li class="">A public <code>shop_item</code> table holds the catalog. Each item has a fixed <code>sku</code>, such as <code>sword</code>, and a name and price that can change.</li>
<li class="">The catalog is a list in your module&#x27;s code. A <code>seed_items</code> function inserts each item, or updates it if it&#x27;s already there.</li>
<li class="">The <code>init</code> reducer calls <code>seed_items</code> when the database is created. It also stores the identity of the database owner, the user who published it, in a private <code>config</code> table.</li>
<li class="">Publishing new code to an existing database doesn&#x27;t run <code>init</code> again. To update the catalog there, the owner calls the <code>seed</code> reducer, which runs <code>seed_items</code> again.</li>
</ul>
<p>Running <code>seed_items</code> twice changes nothing, so the owner can call <code>seed</code> after every publish.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="whats-next">What&#x27;s next?<a href="#whats-next" class="hash-link" aria-label="Direct link to What&#x27;s next?" title="Direct link to What&#x27;s next?" translate="no">​</a></h2>
<p>You now fill your shop&#x27;s catalog when you first publish, and update it when it changes:</p>
\<ul\>
<li class="">The catalog is a list in your module&#x27;s code, and <code>seed_items</code> inserts or updates each item, so running it again changes nothing.</li>
<li class="">The <code>init</code> reducer seeds new databases, and stores the identity of the user who published them.</li>
<li class="">An owner-only <code>seed</code> reducer updates the catalog of databases that already exist.</li>
</ul>
<p>To adapt it to your app:</p>
\<ul\>
<li class=""><strong>Items you remove from the catalog.</strong> <code>seed_items</code> doesn&#x27;t delete them. If nothing refers to them, delete the rows that aren&#x27;t in the catalog in <code>seed_items</code>. If players can own them, add an <code>available</code> column instead, and set it to false.</li>
<li class=""><strong>Large catalogs.</strong> Keep the catalog in a JSON file, build it into your module, for example with <code>include_str!</code> in Rust, and parse it in <code>seed_items</code>.</li>
<li class=""><strong>The first admin.</strong> In <code>init</code>, give the owner the admin role from <a class="" href="/docs/how-to/app-patterns/admin-roles">Admin and moderator roles</a>. Then check that only admins can call <code>set_role</code>, so the owner can give roles to others.</li>
<li class=""><strong>Test data.</strong> To fill a development database with test players, add another owner-only reducer, and only call it on that database.</li>
</ul>
