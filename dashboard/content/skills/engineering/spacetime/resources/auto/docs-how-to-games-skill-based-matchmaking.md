class="admonitionContent_STxx"><p>You need a module and a client connected to it. If you don&#x27;t have them yet, follow the <a class="" href="/docs/">quickstart</a> for your language first. <p>In this guide, you&#x27;ll put players of similar skill in the same match, and update each player&#x27;s skill after every match. Skill is measured with <a href="https://openskill.me" target="_blank" rel="noopener noreferrer" class="">OpenSkill</a>, an open-source rating system that, like TrueSkill, rates players in teams as well as one-on-one. Matches have two teams, and a single constant switches between 1v1 and 2v2. You&#x27;ll use a <a class="" href="/docs/tables/schedule-tables">schedule table</a> to look for matches every second, allowing a wider skill gap the longer players wait.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-it-works">How it works<a href="#how-it-works" class="hash-link" aria-label="Direct link to How it works" title="Direct link to How it works" translate="no">​</a></h2>
\<ul\>
<li class="">A public <code>player_rating</code> table holds each player&#x27;s rating: <code>mu</code>, their estimated skill, and <code>sigma</code>, how uncertain that estimate is. New players start at a <code>mu</code> of 25 and a <code>sigma</code> of 8.33.</li>
<li class="">A <code>join_queue</code> reducer adds the caller to the queue with their current <code>mu</code>.</li>
<li class="">A <code>match_players</code> reducer runs every second. It sorts the waiting players by <code>mu</code>, and creates a match from any group of neighbours whose skill gap is small enough. The allowed gap grows with time spent waiting, so nobody waits forever.</li>
<li class="">Each match has two teams. Players are dealt to the teams so that both get a similar total skill.</li>
<li class="">A <code>finish_match</code> function, which your game logic calls when a match ends, updates the rating of every player in it.</li>
</ul>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="join-the-queue">Join the queue<a href="#join-the-queue" class="hash-link" aria-label="Direct link to Join the queue" title="Direct link to Join the queue" translate="no">​</a></h2>
<p>Insert the timer row from the <code>init</code> reducer, so <code>match_players</code> runs every second. <code>init</code> only runs when the database is created. Publishing new code to an existing database doesn&#x27;t run it again: to start matchmaking there, insert the timer row from another reducer, once.</p>
<p>Then change <code>join_queue</code>. It gives new players OpenSkill&#x27;s default rating, and adds the caller to the queue with their current <code>mu</code>. It no longer creates matches: <code>match_players</code> does.</p>
<p>Keep <code>leave_queue</code>, <code>client_disconnected</code> and the <code>my_match</code> view from the matchmaking queue guide as they are.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="match-players-of-similar-skill">Match players of similar skill<a href="#match-players-of-similar-skill" class="hash-link" aria-label="Direct link to Match players of similar skill" title="Direct link to Match players of similar skill" translate="no">​</a></h2>
<p><code>match_players</code> sorts the waiting players by <code>mu</code>, so players of similar skill are next to each other. It then slides along the sorted list, looking at each group of neighbours big enough to fill a match:</p>
\<ul\>
<li class="">If the gap between the group&#x27;s strongest and weakest player is small enough, it creates a match with them and moves past them.</li>
<li class="">Otherwise, it moves on by one player.</li>
</ul>
<p>The allowed gap starts at <code>STARTING_GAP</code> (<code>StartingGap</code> in C#) and grows with the time the group&#x27;s longest-waiting player has waited. A player whose skill is far from everyone else&#x27;s still gets a match, after waiting longer.</p>
<p>To create a match, it deals the players to the two teams in the order A, B, B, A, A, B, B, A, and so on. Because the players are sorted by skill, this gives both teams a similar total skill. In a 1v1 match, it simply puts one player on each team.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="update-ratings-when-a-match-ends">Update ratings when a match ends<a href="#update-ratings-when-a-match-ends" class="hash-link" aria-label="Direct link to Update ratings when a match ends" title="Direct link to Update ratings when a match ends" translate="no">​</a></h2>
<p>Add a <code>finish_match</code> function that takes a match and the team that won. It hands both teams&#x27; ratings to OpenSkill, winners first, saves the new ratings, then deletes the match so its players can join the queue again.</p>
<p>OpenSkill raises the winners&#x27; <code>mu</code> and lowers the losers&#x27;. The more surprising the result, the bigger the change: beating a much stronger team moves ratings more than beating a weaker one. Every match also lowers each player&#x27;s <code>sigma</code>, as OpenSkill grows more certain of their skill.</p>
<p><code>finish_match</code> is a plain function, not a reducer. Call it from your own game logic when a match ends, for example in the reducer that applies the winning move. If clients could call it, players could report wins they never earned.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="show-the-players-rating-and-rank">Show the player&#x27;s rating and rank<a href="#show-the-players-rating-and-rank" class="hash-link" aria-label="Direct link to Show the player&#x27;s rating and rank" title="Direct link to Show the player&#x27;s rating and rank" translate="no">​</a></h2>
<p>On the client, subscribe to the player&#x27;s own row in <code>player_rating</code>, along with <code>my_match</code> to learn about new matches, as in the matchmaking queue guide.</p>
<p><code>mu</code> alone is a poor rating to show players: a new player who wins their first match jumps straight to the top. Instead, show <code>mu - 3 * sigma</code>, which OpenSkill calls the ordinal. It&#x27;s a cautious estimate of the player&#x27;s skill: it starts near 0, and climbs as the player wins and OpenSkill grows more certain of their skill.</p>
<p>To show a rank such as Bronze or Gold, split that rating into tiers. Because the rating starts near 0, every new player starts in Bronze and climbs from there. Adjust the tiers to your game: few players get above 35.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="whats-next">What&#x27;s next?<a href="#whats-next" class="hash-link" aria-label="Direct link to What&#x27;s next?" title="Direct link to What&#x27;s next?" translate="no">​</a></h2>
<p>You now have matchmaking that puts players of similar skill together, and learns their skill from every match:</p>
\<ul\>
<li class=""><code>player_rating</code> stores each player&#x27;s OpenSkill rating, and <code>finish_match</code> updates it when a match ends, from your game logic only.</li>
<li class=""><code>match_players</code> runs every second, matches neighbours in skill, and widens the allowed gap the longer players wait.</li>
<li class=""><code>TEAM_SIZE</code> (<code>TeamSize</code> in C#) switches between 1v1 and team matches, and teams are dealt so their total skill is similar.</li>
<li class="">Clients show a cautious rating, <code>mu - 3 * sigma</code>, and a rank based on it.</li>
</ul>
<p>To support several game modes, such as 1v1 and 5v5, give each mode its own queue and its own ratings: a player&#x27;s skill in one mode says little about the other.</p>
\<ul\>
<li class="">Add a <code>mode</code> column to <code>queue_entry</code>, pass the mode to <code>join_queue</code>, and have <code>match_players</code> match each mode separately, with that mode&#x27;s team size.</li>
<li class="">Add a <code>mode</code> column to <code>player_rating</code>. A player now has one row per mode, so <code>identity</code> can&#x27;t be the primary key anymore: use an auto-incremented <code>id</code> instead, and a <a class="" href="/docs/tables/indexes#multi-column-indexes">multi-column index</a> on <code>identity</code> and <code>mode</code> to find a player&#x27;s rating in a mode.</li>
</ul>
<p>To learn more about the features used here, see <a class="" href="/docs/tables/schedule-tables">Schedule Tables</a>, <a class="" href="/docs/functions/reducers">Reducers</a> and <a class="" href="/docs/clients/subscriptions">Subscriptions</a>.</p>
