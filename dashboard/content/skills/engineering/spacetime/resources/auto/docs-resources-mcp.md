<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="starting-the-mcp-server">Starting the MCP Server<a href="#starting-the-mcp-server" class="hash-link" aria-label="Direct link to Starting the MCP Server" title="Direct link to Starting the MCP Server" translate="no">​</a></h2>
<p>Use the <code>spacetime mcp</code> command to bridge an MCP client over stdio to a SpacetimeDB host:</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> mcp</span><span style="color:#BD93F9"> --server</span><span style="color:#F1FA8C"> local</span></span>
<span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> mcp</span><span style="color:#F1FA8C"> my-database</span><span style="color:#BD93F9"> --server</span><span style="color:#F1FA8C"> local</span></span></code></pre>
<p>When you omit the database argument, the MCP server is host-wide.
When you pass a database name or identity, the MCP server is scoped to that database.
The database argument can also come from the <code>SPACETIMEDB_DB_NAME</code> environment variable.
When you run <code>spacetime mcp</code> from a project with a <code>spacetime.json</code> that names a single unambiguous <code>server</code>, the command uses that server unless you pass <code>--server</code> or <code>--no-config</code>. It does not infer a database from the config; omitting the database argument still starts a host-wide MCP server.</p>
<p>The command uses your saved SpacetimeDB identity unless you pass <code>--anonymous</code>.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="http-endpoints">HTTP Endpoints<a href="#http-endpoints" class="hash-link" aria-label="Direct link to HTTP Endpoints" title="Direct link to HTTP Endpoints" translate="no">​</a></h2>
<p>SpacetimeDB also exposes MCP over HTTP for clients that can send MCP JSON-RPC
requests directly:</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span>POST /v1/mcp</span></span>
<span class="line"><span>POST /v1/database/<name-or-identity>/mcp</span></span></code></pre>
<p><code>POST /v1/mcp</code> is host-wide, so each data tool call includes a <code>database</code>
argument. <code>POST /v1/database/<name-or-identity>/mcp</code> is scoped to one database,
so data tool calls omit the <code>database</code> argument.</p>
<p>Use the same bearer token you would use for other SpacetimeDB HTTP API calls, or
omit authorization to use an anonymous identity.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="host-wide-vs-database-scoped-tools">Host-wide vs Database-scoped Tools<a href="#host-wide-vs-database-scoped-tools" class="hash-link" aria-label="Direct link to Host-wide vs Database-scoped Tools" title="Direct link to Host-wide vs Database-scoped Tools" translate="no">​</a></h2>
<p>The tool shape depends on whether the MCP server is host-wide or database-scoped.
Read the MCP client&#x27;s tool list before constructing tool calls.</p>
<p>In host-wide mode, every data tool takes a required <code>database</code> argument.
The <code>database</code> value can be a database name or identity.
Host-wide mode also exposes <code>list_databases</code>.</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#F8F8F2">{ </span><span style="color:#8BE9FE">"</span><span style="color:#8BE9FD">database</span><span style="color:#8BE9FE">"</span><span style="color:#FF79C6">:</span><span style="color:#E9F284"> "</span><span style="color:#F1FA8C">my-database</span><span style="color:#E9F284">"</span><span style="color:#F8F8F2">, </span><span style="color:#8BE9FE">"</span><span style="color:#8BE9FD">sql</span><span style="color:#8BE9FE">"</span><span style="color:#FF79C6">:</span><span style="color:#E9F284"> "</span><span style="color:#F1FA8C">SELECT * FROM message</span><span style="color:#E9F284">"</span><span style="color:#F8F8F2"> }</span></span></code></pre>
<p>In database-scoped mode, the database is fixed by the <code>spacetime mcp \<database\></code> command.
Data tools do not take a <code>database</code> argument, and <code>list_databases</code> is not exposed.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="identity-and-permissions">Identity and Permissions<a href="#identity-and-permissions" class="hash-link" aria-label="Direct link to Identity and Permissions" title="Direct link to Identity and Permissions" translate="no">​</a></h2>
<p>MCP tools run with the identity used to start <code>spacetime mcp</code>, the same as other SpacetimeDB APIs.</p>
<p>Reducers are the normal write path.
Use <code>call</code> to change application state through module logic.
The reducer runs transactionally and either commits or rolls back.</p>
<p>The <code>sql</code> tool can read public tables.
SQL writes require ownership of the database.
Prefer reducers for writes so authorization and validation stay in the module.</p>
<p>Private tables are not client-readable through MCP SQL.
The <code>get_schema</code> tool can still show private table declarations, so a <code>no such table</code> error from <code>sql</code> can mean the table is private for the current identity rather than absent from the module.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="common-errors">Common Errors<a href="#common-errors" class="hash-link" aria-label="Direct link to Common Errors" title="Direct link to Common Errors" translate="no">​</a></h2>
<table><thead><tr><th>Error</th><th>Meaning</th></tr></thead>\<tbody\><tr><td><code>database argument must be a string</code></td><td>The server is host-wide and the tool call omitted <code>database</code>, or passed a non-string value.</td></tr><tr><td><code>unknown tool: list_databases</code></td><td>The server is database-scoped, so <code>list_databases</code> is not available.</td></tr><tr><td><code>`x` not found</code></td><td>No database named <code>x</code> exists on this server for the current identity, or the call used a name where an identity was required.</td></tr><tr><td><code>no such table: x</code></td><td>The table is private for the current identity, absent from the module, or the call targeted the wrong database.</td></tr></tbody></table>
