<p>SpacetimeDB modules can export three types of functions that clients can interact with:</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="reducers">Reducers<a href="#reducers" class="hash-link" aria-label="Direct link to Reducers" title="Direct link to Reducers" translate="no">​</a></h2>
<p><strong><a class="" href="/docs/functions/reducers">Reducers</a></strong> are functions that modify database state in response to client requests or system events. They are the primary way to mutate tables in SpacetimeDB. Reducers run inside database transactions, providing isolation, atomicity, and consistency guarantees. If a reducer fails, all changes are automatically rolled back.</p>
<p>Reducers are isolated and cannot interact with the outside world - they can only perform database operations. Use reducers for all state-changing operations in your module.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="procedures">Procedures<a href="#procedures" class="hash-link" aria-label="Direct link to Procedures" title="Direct link to Procedures" translate="no">​</a></h2>
<p><strong><a class="" href="/docs/functions/procedures">Procedures</a></strong> are functions similar to reducers, but with the ability to perform operations beyond the database. Unlike reducers, procedures can make HTTP requests to external services. However, procedures don&#x27;t automatically run in database transactions - they must manually open and commit transactions to read from or modify database state.</p>
<p>Procedures should only be used when you need their special capabilities, such as making HTTP requests. For standard database operations, prefer using reducers.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="views">Views<a href="#views" class="hash-link" aria-label="Direct link to Views" title="Direct link to Views" translate="no">​</a></h2>
<p><strong><a class="" href="/docs/functions/views">Views</a></strong> are read-only functions that compute and return results from your tables. Unlike reducers and procedures, views do not modify database state - they only query and return data. Views are useful for computing derived data, aggregations, or joining multiple tables server-side before sending results to clients.</p>
<p>Views run within a transaction to ensure isolation: the database state remains consistent for the entire duration of the view&#x27;s execution. This means a view will never see partial updates from concurrent reducers.</p>
