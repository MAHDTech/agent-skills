tocCollapsibleButton_Dk1U">On this page</button></div><div class="theme-doc-markdown markdown">\<header\>\<h1\>Authentication</h1></header>
<p>SpacetimeDB modules are exposed to the open internet and anyone can connect to
them. Therefore, authentication is a critical part of using SpacetimeDB securely.</p>
<p>SpacetimeDB uses OpenID Connect (OIDC) identity tokens for authentication, making
it compatible with most OIDC providers (e.g., Auth0, Firebase, Clerk, Google,
GitHub, Facebook, and many more). You can choose any OIDC provider that fits your
needs, or even implement your own.</p>
<p>If you&#x27;re new to OIDC, check out our <a href="https://spacetimedb.com/blog/who-are-you" target="_blank" rel="noopener noreferrer" class="">blog post about OIDC</a>
to learn more about how OIDC works and why it&#x27;s a great choice for authentication.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="server-issued-tokens-and-reconnects">Server-issued tokens and reconnects<a href="#server-issued-tokens-and-reconnects" class="hash-link" aria-label="Direct link to Server-issued tokens and reconnects" title="Direct link to Server-issued tokens and reconnects" translate="no">​</a></h2>
<p>If a client connects without supplying a token, SpacetimeDB creates a new
identity and returns a server-issued token for that identity. If you want later
connections to keep using that same identity, persist that returned token and
pass it back into the SDK on reconnect.</p>
<p>On platforms that can send an <code>Authorization</code> header during the WebSocket
handshake, the SDK can reuse that saved token directly. On platforms that cannot
set custom WebSocket headers, the SDK first exchanges the saved token for a
short-lived WebSocket token through
<a class="" href="/docs/http/identity#post-v1identitywebsocket-token"><code>POST /v1/identity/websocket-token</code></a>,
then sends only that short-lived token in the WebSocket URL.</p>
<p>This matters when you persist tokens on the client:</p>
\<ul\>
<li class="">Save the long-lived server-issued token that establishes the user&#x27;s identity.</li>
<li class="">Do not overwrite an already-saved long-lived token with a short-lived
WebSocket token received during reconnect.</li>
<li class="">Expect this distinction on browser-style transports where WebSocket headers
are unavailable, such as Unity WebGL builds.</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="spacetimeauth">SpacetimeAuth<a href="#spacetimeauth" class="hash-link" aria-label="Direct link to SpacetimeAuth" title="Direct link to SpacetimeAuth" translate="no">​</a></h2>
<p>To make it easier to get started with authentication, SpacetimeDB offers
<a class="" href="/docs/core-concepts/authentication/spacetimeauth/">SpacetimeAuth</a>, a fully
managed OIDC provider built specifically for SpacetimeDB applications. SpacetimeAuth
handles user management, authentication flows, and token issuance, so you don&#x27;t have
to worry about building and maintaining your own authentication service.</p>
<p>SpacetimeAuth is meant to be simple to use and easy to integrate with SpacetimeDB.
While being production-ready and able to support most common use cases, it is not
as feature-rich as some third-party OIDC providers. If you need advanced features
or customization, you may want to consider using a third-party OIDC provider instead.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="third-party-oidc-providers">Third-party OIDC providers<a href="#third-party-oidc-providers" class="hash-link" aria-label="Direct link to Third-party OIDC providers" title="Direct link to Third-party OIDC providers" translate="no">​</a></h2>
<p>You can also use any third-party OIDC provider with SpacetimeDB. Most OIDC
providers offer similar features, such as user management, authentication flows,
and token issuance. When choosing a third-party OIDC provider, consider factors
such as ease of integration, pricing, scalability, and security.</p>
\<ul\>
<li class=""><a href="https://auth0.com/" target="_blank" rel="noopener noreferrer" class="">Auth0</a> A managed identity and access
management service that provides, user management, and extensible login flows
for applications and APIs.</li>
<li class=""><a href="https://clerk.com/" target="_blank" rel="noopener noreferrer" class="">Clerk</a> A developer-focused
authentication and user management platform that provides OIDC-compliant
sign-in, session management, and prebuilt UI components for modern web applications.</li>
<li class=""><a href="https://www.keycloak.org/" target="_blank" rel="noopener noreferrer" class="">Keycloak</a> An open-source and
self-hosted OIDC provider with extensive features, customization options and integrations.</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="authenticate-your-services">Authenticate your services<a href="#authenticate-your-services" class="hash-link" aria-label="Direct link to Authenticate your services" title="Direct link to Authenticate your services" translate="no">​</a></h2>
<p>Sometimes, you may need to authenticate your servers, APIs or other services that
interact with your SpacetimeDB database. OIDC tokens can also be used for this
purpose, allowing secure communication between your services and SpacetimeDB.</p>
<p>To authenticate your services, you have a few options depending on your OIDC provider:</p>
\<ul\>
<li class=""><strong>Client credentials flow</strong>: Many OIDC providers support the client credentials
flow, which allows your service to obtain an access token using its own
credentials (client ID and client secret). This is a common approach for
service-to-service authentication.</li>
<li class=""><strong>Service accounts</strong>: Some OIDC providers offer service accounts, which are
special user accounts designed for non-human users (e.g., servers, APIs). You
can create a service account and use its credentials to obtain an access token.</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="authorization-in-your-module">Authorization in your module<a href="#authorization-in-your-module" class="hash-link" aria-label="Direct link to Authorization in your module" title="Direct link to Authorization in your module" translate="no">​</a></h2>
<p>Obtaining an OIDC token is just the first step in securing your SpacetimeDB
module, known as <strong>authentication</strong>. You also need to implement <strong>authorization</strong>
to control what authenticated users can do within your module.</p>
<p>When a client connects to your SpacetimeDB module, the SpacetimeDB server
validates the client&#x27;s OIDC token and extracts the identity claims. These claims
are then made available to your module&#x27;s reducers, views and procedures via the context.</p>
