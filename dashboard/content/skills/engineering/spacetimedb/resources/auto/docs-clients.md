tocCollapsibleButton_Dk1U">On this page</button></div><div class="theme-doc-markdown markdown">\<header\>\<h1\>Clients</h1></header><p>The SpacetimeDB Client SDKs provide a comprehensive interface for building applications that connect to SpacetimeDB <a class="" href="/docs/databases">databases</a>. Client applications can query data, invoke server-side functions, and receive real-time updates as the database state changes.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="available-sdks">Available SDKs<a href="#available-sdks" class="hash-link" aria-label="Direct link to Available SDKs" title="Direct link to Available SDKs" translate="no">​</a></h2>
<p>SpacetimeDB provides client SDKs for multiple languages:</p>
\<ul\>
<li class=""><a class="" href="/docs/clients/rust">Rust</a> - <a class="" href="/docs/quickstarts/rust">(Quickstart)</a></li>
<li class=""><a class="" href="/docs/clients/c-sharp">C#</a> - <a class="" href="/docs/quickstarts/c-sharp">(Quickstart)</a></li>
<li class=""><a class="" href="/docs/clients/typescript">TypeScript</a> - <a class="" href="/docs/quickstarts/typescript">(Quickstart)</a></li>
<li class=""><a class="" href="/docs/clients/unreal">Unreal</a> - <a class="" href="/docs/tutorials/unreal">(Tutorial)</a></li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="getting-started">Getting Started<a href="#getting-started" class="hash-link" aria-label="Direct link to Getting Started" title="Direct link to Getting Started" translate="no">​</a></h2>
<p>To build a client application with SpacetimeDB:</p>
\<ol\>
<li class=""><strong><a class="" href="/docs/clients/codegen">Generate client bindings</a></strong> - Use <code>spacetime generate</code> to create type-safe bindings for your <a class="" href="/docs/databases">database</a></li>
<li class=""><strong><a class="" href="/docs/clients/connection">Connect to your database</a></strong> - Establish a WebSocket connection to SpacetimeDB</li>
<li class=""><strong><a class="" href="/docs/clients/api">Use the SDK API</a></strong> - Subscribe to data, invoke functions, and register callbacks</li>
</ol>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="core-capabilities">Core Capabilities<a href="#core-capabilities" class="hash-link" aria-label="Direct link to Core Capabilities" title="Direct link to Core Capabilities" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="connection-management">Connection Management<a href="#connection-management" class="hash-link" aria-label="Direct link to Connection Management" title="Direct link to Connection Management" translate="no">​</a></h3>
<p>The SDKs handle establishing and maintaining WebSocket connections to SpacetimeDB servers. Connections support authentication via tokens (for example, from <a class="" href="/docs/core-concepts/authentication/spacetimeauth/">SpacetimeAuth</a>) and provide lifecycle callbacks for connect, disconnect, and error events.</p>
<p>See <a class="" href="/docs/clients/connection">Connecting to SpacetimeDB</a> for details.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="client-side-data-cache">Client-Side Data Cache<a href="#client-side-data-cache" class="hash-link" aria-label="Direct link to Client-Side Data Cache" title="Direct link to Client-Side Data Cache" translate="no">​</a></h3>
<p>Each client maintains a local cache of database rows through <a class="" href="/docs/clients/subscriptions">subscriptions</a>. Clients define which data they need using typed query builders (or raw SQL when needed), and SpacetimeDB automatically synchronizes changes to the subscribed data. The local cache can be queried without network round-trips, providing fast access to frequently-read data.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="real-time-updates">Real-Time Updates<a href="#real-time-updates" class="hash-link" aria-label="Direct link to Real-Time Updates" title="Direct link to Real-Time Updates" translate="no">​</a></h3>
<p>Clients receive automatic updates when subscribed data changes. The SDKs provide callbacks for observing:</p>
\<ul\>
<li class=""><strong>Subscription updates</strong> - When subscription queries are applied or fail</li>
<li class=""><strong>Row changes</strong> - When rows are inserted, updated, or deleted in the local cache</li>
<li class=""><strong>Reducer invocations</strong> - When <a class="" href="/docs/functions/reducers">reducers</a> run on the server</li>
<li class=""><strong>Procedure results</strong> - When <a class="" href="/docs/functions/procedures">procedures</a> are called the results are returned via a callback</li>
</ul>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="invoking-server-functions">Invoking Server Functions<a href="#invoking-server-functions" class="hash-link" aria-label="Direct link to Invoking Server Functions" title="Direct link to Invoking Server Functions" translate="no">​</a></h3>
<p>Clients can invoke server-side functions to modify data or perform operations:</p>
\<ul\>
<li class=""><strong><a class="" href="/docs/functions/reducers">Reducers</a></strong> - Transactional functions that modify database state</li>
<li class=""><strong><a class="" href="/docs/functions/procedures">Procedures</a></strong> - Functions that can perform external operations like HTTP requests</li>
</ul>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="type-safety">Type Safety<a href="#type-safety" class="hash-link" aria-label="Direct link to Type Safety" title="Direct link to Type Safety" translate="no">​</a></h3>
<p>The <a class="" href="/docs/clients/codegen">generated client bindings</a> provide compile-time type safety between your client and server code. Table schemas, function signatures, and return types are all reflected in the generated code, catching errors before runtime.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="choosing-a-language">Choosing a Language<a href="#choosing-a-language" class="hash-link" aria-label="Direct link to Choosing a Language" title="Direct link to Choosing a Language" translate="no">​</a></h2>
<p>When selecting a language for your client application, consider these factors:</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="team-expertise">Team Expertise<a href="#team-expertise" class="hash-link" aria-label="Direct link to Team Expertise" title="Direct link to Team Expertise" translate="no">​</a></h3>
<p>Choose a language your development team is comfortable with to maximize productivity and reduce development time.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="application-type">Application Type<a href="#application-type" class="hash-link" aria-label="Direct link to Application Type" title="Direct link to Application Type" translate="no">​</a></h3>
\<ul\>
<li class=""><strong>Web applications</strong> - TypeScript integrates seamlessly with browser and Node.js environments</li>
<li class=""><strong>Desktop applications</strong> - Rust or C# depending on your platform and requirements</li>
<li class=""><strong>Performance-critical applications</strong> - Rust offers the best performance and memory efficiency</li>
<li class=""><strong>Unity games</strong> - C# is required for Unity development</li>
<li class=""><strong>Unreal games</strong> - C++ and Blueprint are both supported for Unreal clients</li>
</ul>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="platform-and-ecosystem">Platform and Ecosystem<a href="#platform-and-ecosystem" class="hash-link" aria-label="Direct link to Platform and Ecosystem" title="Direct link to Platform and Ecosystem" translate="no">​</a></h3>
<p>Each language has its own ecosystem of libraries and tools. If your application depends on specific libraries or frameworks, that may influence your choice.</p>
<p>The functionality of the SDKs remains consistent across languages, so transitioning between them primarily involves syntax changes rather than architectural changes. You can even use multiple languages in the same project - for example, C# for a Unity game client and TypeScript for a web administration panel.</p>
