<p>Today we&#x27;re thrilled to announce <strong>Envoy AI Gateway 1.0</strong> — the first <strong>stable, generally available</strong>
release of the open source AI gateway built on <strong>CNCF&#x27;s <a href="https://gateway.envoyproxy.io/" target="_blank" rel="noopener noreferrer" class="">Envoy Gateway</a></strong>.</p>
<p>When we <a href="https://aigateway.envoyproxy.io/blog/01-release-announcement" target="_blank" rel="noopener noreferrer" class="">shipped v0.1 in February 2025</a>,
we closed that post with three words: <strong>"Onward to 1.0!"</strong> Sixteen months and many releases later,
backed by a community of maintainers and adopters across the industry, we&#x27;re here. 1.0 means you can
build on Envoy AI Gateway with confidence: a control-plane API we&#x27;re committing to keep stable, running
on the same battle-tested Envoy foundation that already powers production traffic at the world&#x27;s largest
companies.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="-what-10-means-stability-you-can-build-on">🔒 What 1.0 Means: Stability You Can Build On<a href="#-what-10-means-stability-you-can-build-on" class="hash-link" aria-label="Direct link to 🔒 What 1.0 Means: Stability You Can Build On" title="Direct link to 🔒 What 1.0 Means: Stability You Can Build On" translate="no">​</a></h2>
<p>The headline of 1.0 isn&#x27;t a single new feature — it&#x27;s a <strong>promise</strong>. Our
<a href="https://github.com/envoyproxy/ai-gateway/blob/main/RELEASES.md" target="_blank" rel="noopener noreferrer" class="">release policy</a> has always said that
we&#x27;d cut the major v1.0.0 release once we had a <em>first stable control-plane API</em>. That moment is here.</p>
<p>For stable APIs, the commitment is simple and strong:</p>
<blockquote>
<p><strong>We will never break the APIs unless there is a critical security issue</strong>, and we will always provide
a migration path in the release notes if we ever must.</p>
</blockquote>
<p>Concretely, that means:</p>
<table><thead><tr><th>Guarantee</th><th>What it means for you</th></tr></thead>\<tbody\><tr><td><strong>Stable CRDs</strong></td><td>The resources you author — <code>AIGatewayRoute</code>, <code>AIServiceBackend</code>, <code>BackendSecurityPolicy</code>, <code>GatewayConfig</code>, <code>MCPRoute</code>, all served at <code>v1beta1</code> — won&#x27;t break under you.</td></tr><tr><td><strong>Predictable upgrades</strong></td><td>Upgrading the controller won&#x27;t break a valid, migrated configuration.</td></tr><tr><td><strong>Documented migrations</strong></td><td>Any future change that requires action will ship with a clear, documented upgrade path.</td></tr></tbody></table>
<p>This is the foundation enterprises have been asking for — the ability to standardize on a single,
provider-agnostic AI gateway without betting on a moving target.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="️-the-road-from-01-to-10">🛣️ The Road from 0.1 to 1.0<a href="#️-the-road-from-01-to-10" class="hash-link" aria-label="Direct link to 🛣️ The Road from 0.1 to 1.0" title="Direct link to 🛣️ The Road from 0.1 to 1.0" translate="no">​</a></h2>
<p>v0.1 launched with a unified API in front of <strong>two</strong> providers and the essentials: upstream
authorization and token-based rate limiting. 1.0 is a different animal. Here&#x27;s how far the project has
come:</p>
<table><thead><tr><th>Capability</th><th>v0.1 (Feb 2025)</th><th>1.0</th></tr></thead>\<tbody\><tr><td><strong>AI providers</strong></td><td>2 (OpenAI, AWS Bedrock)</td><td><strong>16</strong>, with cross-provider request/response translation</td></tr><tr><td><strong>API surface</strong></td><td>Chat completions</td><td>Chat, completions, embeddings, image generation, audio (transcription / translation / speech), and the OpenAI Responses API</td></tr><tr><td><strong>MCP (Model Context Protocol)</strong></td><td>—</td><td>A full <strong>MCP gateway</strong>: server multiplexing, tool routing & filtering, and fine-grained authorization</td></tr><tr><td><strong>Multimodal</strong></td><td>—</td><td>Image, audio, and video inputs across supported providers</td></tr><tr><td><strong>Observability</strong></td><td>Basic metrics</td><td>OpenTelemetry tracing, OpenInference, GenAI token metrics, separate reasoning-token accounting</td></tr><tr><td><strong>Multi-tenancy & routing</strong></td><td>Token rate limiting</td><td>Hostname-based routing, model virtualization, and quota-aware rate limiting</td></tr><tr><td><strong>Control-plane API</strong></td><td>v1alpha1 (experimental)</td><td><strong>v1beta1 (stable)</strong></td></tr></tbody></table>
<p>Sixteen providers, integrated through a single OpenAI-compatible interface, including OpenAI, Azure
OpenAI, Google Gemini, Google Vertex AI, AWS Bedrock, Anthropic, Mistral, Cohere, Groq, Together AI,
DeepInfra, DeepSeek, Hunyuan, SambaNova, Grok, and the Tetrate Agent Router Service.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="-whats-in-10">✨ What&#x27;s in 1.0<a href="#-whats-in-10" class="hash-link" aria-label="Direct link to ✨ What&#x27;s in 1.0" title="Direct link to ✨ What&#x27;s in 1.0" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="one-api-every-provider">One API, every provider<a href="#one-api-every-provider" class="hash-link" aria-label="Direct link to One API, every provider" title="Direct link to One API, every provider" translate="no">​</a></h3>
<p>Point your application at a single OpenAI-compatible endpoint and let the gateway handle
provider-specific translation, authentication, and routing. Switch or mix providers without touching
application code — and use <strong>model virtualization</strong> to keep your app code stable while routing changes
underneath:</p>

<p>This is the key to A/B testing, gradual migrations, multi-provider strategies, and safeguarding against
vendor lock-in.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="provider-authentication-handled-for-you">Provider authentication, handled for you<a href="#provider-authentication-handled-for-you" class="hash-link" aria-label="Direct link to Provider authentication, handled for you" title="Direct link to Provider authentication, handled for you" translate="no">​</a></h3>
<p><code>BackendSecurityPolicy</code> keeps provider credentials out of your application and centralizes upstream auth —
API keys, AWS, Azure, and GCP cloud-native identity (including Workload Identity), all managed at the
gateway.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="an-mcp-gateway-for-the-agent-era">An MCP gateway for the agent era<a href="#an-mcp-gateway-for-the-agent-era" class="hash-link" aria-label="Direct link to An MCP gateway for the agent era" title="Direct link to An MCP gateway for the agent era" translate="no">​</a></h3>
<p>Aggregate multiple <strong>Model Context Protocol</strong> servers behind one endpoint, route and filter the tools
clients can see, and enforce <strong>fine-grained, CEL-based authorization</strong> — so <code>tools/list</code> only ever
returns what a caller is actually allowed to use.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="enterprise-observability-built-in">Enterprise observability, built in<a href="#enterprise-observability-built-in" class="hash-link" aria-label="Direct link to Enterprise observability, built in" title="Direct link to Enterprise observability, built in" translate="no">​</a></h3>
<p>Token-aware metrics, OpenTelemetry tracing with OpenInference compatibility (for evaluation tools like
Arize Phoenix), and separate accounting for reasoning tokens give you the cost control and visibility
that AI workloads demand.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="standards-all-the-way-down">Standards all the way down<a href="#standards-all-the-way-down" class="hash-link" aria-label="Direct link to Standards all the way down" title="Direct link to Standards all the way down" translate="no">​</a></h3>
<p>Built on the Kubernetes <strong>Gateway API</strong> and the
<a href="https://gateway-api-inference-extension.sigs.k8s.io/" target="_blank" rel="noopener noreferrer" class="">Gateway API Inference Extension</a>, Envoy AI Gateway
is an additive layer on Envoy Gateway — it expands what Envoy can do for GenAI traffic without changing
how you already deploy and operate it.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="-built-by-a-community-on-cncf-envoy">🌍 Built by a Community, on CNCF Envoy<a href="#-built-by-a-community-on-cncf-envoy" class="hash-link" aria-label="Direct link to 🌍 Built by a Community, on CNCF Envoy" title="Direct link to 🌍 Built by a Community, on CNCF Envoy" translate="no">​</a></h2>

<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="-whats-next-beyond-10">🔭 What&#x27;s Next, Beyond 1.0<a href="#-whats-next-beyond-10" class="hash-link" aria-label="Direct link to 🔭 What&#x27;s Next, Beyond 1.0" title="Direct link to 🔭 What&#x27;s Next, Beyond 1.0" translate="no">​</a></h2>
<p>A stable API is a starting line, not a finish line. On the roadmap:</p>
\<ul\>
<li class=""><strong>A dedicated <code>MCPBackend</code> CRD</strong>, decoupling MCP backend configuration from <code>MCPRoute</code>.</li>
<li class=""><strong>Deeper MCP authorization</strong> across tools, resources, and prompts.</li>
<li class=""><strong>Fuller quota-aware routing</strong> that automatically steers around rate-limited upstreams.</li>
<li class=""><strong>More provider translation paths</strong> and <strong>expanded multimodal</strong> support.</li>
</ul>
<p>The roadmap is community-driven — and we&#x27;d love your help shaping it.</p>
