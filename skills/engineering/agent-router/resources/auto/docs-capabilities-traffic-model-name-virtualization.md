Virtualization</h1></header><p>Agent Router provides an advanced model name virtualization capability that allows you to manage and route requests to different AI models seamlessly.
This guide covers the key feature and configuration for model virtualization.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="motivation">Motivation<a href="#motivation" class="hash-link" aria-label="Direct link to Motivation" title="Direct link to Motivation" translate="no">​</a></h2>
<p>It is not uncommon for multiple AI providers to offer a similar or identical model, such as Llama-3-70b, etc.
However, each provider tends to have its own unique naming convention for the same model.
For example, <code>Claude 4 Sonnet</code> is hosted both on GCP and AWS Bedrock, but they have different model names:</p>
\<ul\>
<li class="">GCP: <code>claude-sonnet-4@20250514</code>, etc.</li>
<li class="">AWS Bedrock: <code>anthropic.claude-sonnet-4-20250514-v1:0</code></li>
</ul>
<p>Even within the same provider, model names may vary based on deployment configurations or versions.
For example, an OpenAI Platform request to <code>gpt-5-nano</code> might result in a response from <code>gpt-5-nano-2025-08-07</code>.
Azure OpenAI uses deployment names in the URL path rather than model names in the request body, so you won&#x27;t know the model in use until you get the response.</p>
<p>From downstream GenAI applications&#x27; perspective, it is beneficial to have a unified model name that abstracts away these differences. We do this while still availing the authoritative model name that served a response.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="provider-specific-virtualization">Provider-specific Virtualization<a href="#provider-specific-virtualization" class="hash-link" aria-label="Direct link to Provider-specific Virtualization" title="Direct link to Provider-specific Virtualization" translate="no">​</a></h2>
<p>AI providers handle model naming and execution differently to balance flexibility, determinism, and optimization. This section categorizes these behaviors into virtualization types, enabling Agent Router to abstract differences for unified downstream access while retaining executed model details where possible.</p>
\<ul\>
<li class=""><strong>Automatic Routing & Resolution</strong>: Providers select and optimize models at runtime behind generic identifiers, returning the actual executed version for reproducibility and debugging.</li>
<li class=""><strong>Static Model Execution</strong>: Uses direct mapping to immutable identifiers or fixed versions for deterministic execution, ensuring requested models run exactly as specified, ideal for consistent embeddings.</li>
<li class=""><strong>Deterministic Snapshot Mapping</strong>: Resolves models via endpoint/URL with dated snapshots (no response model field), providing consistent cross-platform behavior through timestamped versions.</li>
<li class=""><strong>URI-Based Resolution</strong>: Ignores request body model field, using URI path for deployment-based routing while returning the actual versioned model name in responses.</li>
<li class=""><strong>Third-Party Delegation</strong>: Delegates embeddings to specialized third-party services with separate APIs, integrating ecosystem expertise while focusing on core capabilities.</li>
</ul>

<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="azure-openai-uri-based-behavior">Azure OpenAI URI-Based Behavior<a href="#azure-openai-uri-based-behavior" class="hash-link" aria-label="Direct link to Azure OpenAI URI-Based Behavior" title="Direct link to Azure OpenAI URI-Based Behavior" translate="no">​</a></h3>
<p>Azure OpenAI has a unique approach where <a href="https://learn.microsoft.com/en-us/azure/ai-foundry/openai/how-to/chatgpt" target="_blank" rel="noopener noreferrer" class="">the model field in the request JSON is completely ignored</a>. The deployment name in the URI path determines which model is actually used, and the response returns the actual versioned model name:</p>
\<ul\>
<li class=""><strong>URI Format</strong>: <code>https://{resource}.openai.azure.com/openai/deployments/{deployment-name}/chat/completions</code></li>
<li class=""><strong>Request Body</strong>: <code>{"model": "anything"}</code> ← This value is ignored</li>
<li class=""><strong>Response</strong>: <code>{"model": "gpt-5-nano-2025-08-07"}</code> ← Returns the actual versioned model name</li>
</ul>
<p>This means <a href="https://learn.microsoft.com/en-us/azure/ai-foundry/openai/faq" target="_blank" rel="noopener noreferrer" class="">Azure OpenAI doesn&#x27;t read the model field from the request JSON at all</a> - it uses the deployment name from the URI path exclusively, but returns the real underlying versioned model identifier in the response.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="aws-bedrock-static-execution">AWS Bedrock Static Execution<a href="#aws-bedrock-static-execution" class="hash-link" aria-label="Direct link to AWS Bedrock Static Execution" title="Direct link to AWS Bedrock Static Execution" translate="no">​</a></h3>
<p>AWS Bedrock uses static model execution with immutable versioned identifiers. The Converse API does not return a model field in responses. Each model ID like <code>anthropic.claude-sonnet-4-20250514-v1:0</code> represents a specific, frozen model version with no automatic updates or routing.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="gcp-anthropic-embeddings-delegation">GCP Anthropic Embeddings Delegation<a href="#gcp-anthropic-embeddings-delegation" class="hash-link" aria-label="Direct link to GCP Anthropic Embeddings Delegation" title="Direct link to GCP Anthropic Embeddings Delegation" translate="no">​</a></h3>
<p>GCP Anthropic delegates embeddings to <a href="https://docs.anthropic.com/en/docs/build-with-claude/embeddings" target="_blank" rel="noopener noreferrer" class="">Voyage AI&#x27;s specialized embedding models</a> rather than providing Claude-native embeddings. Available models include:</p>
\<ul\>
<li class=""><code>voyage-3.5</code> - Balanced performance embedding model</li>
<li class=""><code>voyage-3-large</code> - Best quality general-purpose embeddings</li>
<li class=""><code>voyage-code-3</code> - Optimized for code retrieval</li>
<li class=""><code>voyage-law-2</code> - Legal domain-specific embeddings</li>
</ul>
<p>This delegation approach allows Anthropic to focus on language model capabilities while leveraging domain expertise for embeddings.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="openai-virtualization">OpenAI Virtualization<a href="#openai-virtualization" class="hash-link" aria-label="Direct link to OpenAI Virtualization" title="Direct link to OpenAI Virtualization" translate="no">​</a></h3>
<p>OpenAI performs automatic model routing where <a href="https://learn.microsoft.com/en-us/azure/ai-foundry/openai/how-to/chatgpt" target="_blank" rel="noopener noreferrer" class="">generic identifiers like <code>gpt-5-nano</code> may route to different model versions</a> like <code>gpt-5-nano-2025-08-07</code> based on availability and optimization.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="gcp-provider-behavior">GCP Provider Behavior<a href="#gcp-provider-behavior" class="hash-link" aria-label="Direct link to GCP Provider Behavior" title="Direct link to GCP Provider Behavior" translate="no">​</a></h3>
<p>Both GCP Anthropic and GCP Vertex AI use endpoint-based model resolution where <a href="https://cloud.google.com/vertex-ai/generative-ai/docs/partner-models/claude" target="_blank" rel="noopener noreferrer" class="">the model is specified in the URI path rather than returned in the response body</a>. This provides deterministic behavior with timestamped snapshots.</p>
