<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="overview">Overview<a href="#overview" class="hash-link" aria-label="Direct link to Overview" title="Direct link to Overview" translate="no">​</a></h2>
<p>Agent Router&#x27;s router joins and records distributed traces when supplied
with an <a href="https://opentelemetry.io/" target="_blank" rel="noopener noreferrer" class="">OpenTelemetry</a> collector endpoint.</p>
<p>Requests to the OpenAI Chat Completions, Completions (legacy), and Embeddings
endpoints are recorded as Spans which include typical timing and request
details. In addition, there are GenAI attributes representing the LLM or
Embeddings call including full request and response details, defined by
<a href="https://github.com/Arize-ai/openinference/tree/main/spec" target="_blank" rel="noopener noreferrer" class="">OpenInference semantic conventions</a>.</p>
<p>OpenInference attributes default to include full request and response data for
both chat completions and embeddings. This can be toggled with configuration,
but when enabled allows systems like <a href="https://docs.arize.com/phoenix" target="_blank" rel="noopener noreferrer" class="">Arize Phoenix</a> to perform
evaluations of production requests captured in OpenTelemetry spans.</p>
<p>For chat completions, this includes traditional LLM metrics such as correctness
and hallucination detection. For embeddings, it enables agentic RAG evaluations
focused on retrieval and semantic analysis.</p>

<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="semantic-conventions">Semantic Conventions<a href="#semantic-conventions" class="hash-link" aria-label="Direct link to Semantic Conventions" title="Direct link to Semantic Conventions" translate="no">​</a></h2>
<p>Spans are recorded using <a href="https://github.com/Arize-ai/openinference/tree/main/spec" target="_blank" rel="noopener noreferrer" class="">OpenInference semantic conventions</a> by
default. You can instead emit the
<a href="https://github.com/open-telemetry/semantic-conventions-genai" target="_blank" rel="noopener noreferrer" class="">OpenTelemetry GenAI semantic conventions</a>, which use <code>gen_ai.*</code>
attributes and are consumed by OpenTelemetry-native backends:</p>
<div class="language-yaml codeBlockContainer_Ckt0 theme-code-block" style="--prism-color:#393A34;--prism-background-color:#f6f8fa"><div class="codeBlockContent_QJqH"><pre tabindex="0" class="prism-code language-yaml codeBlock_bY9V thin-scrollbar" style="color:#393A34;background-color:#f6f8fa"><code class="codeBlockLines_e6Vv"><div class="token-line" style="color:#393A34"><span class="token key atrule" style="color:#00a4db">extProc</span><span class="token punctuation" style="color:#393A34">:</span><span class="token plain"></span><br></div><div class="token-line" style="color:#393A34"><span class="token plain">  </span><span class="token key atrule" style="color:#00a4db">extraEnvVars</span><span class="token punctuation" style="color:#393A34">:</span><span class="token plain"></span><br></div><div class="token-line" style="color:#393A34"><span class="token plain">    </span><span class="token punctuation" style="color:#393A34">-</span><span class="token plain"> </span><span class="token key atrule" style="color:#00a4db">name</span><span class="token punctuation" style="color:#393A34">:</span><span class="token plain"> AI_GATEWAY_TRACING_SEMCONV</span><br></div><div class="token-line" style="color:#393A34"><span class="token plain">      </span><span class="token key atrule" style="color:#00a4db">value</span><span class="token punctuation" style="color:#393A34">:</span><span class="token plain"> </span><span class="token string" style="color:#e3116c">"gen_ai"</span><br></div></code></pre></div></div>
<table><thead><tr><th>Value</th><th>Behavior</th></tr></thead>\<tbody\><tr><td>unset or <code>openinference</code></td><td>OpenInference attributes (default)</td></tr><tr><td><code>gen_ai</code></td><td>OpenTelemetry GenAI attributes</td></tr></tbody></table>
<p>Any other value fails startup rather than silently falling back, so a typo is
reported immediately instead of producing traces nobody is watching.</p>
<p>Only one convention is emitted at a time. Choosing <code>gen_ai</code> changes the shape of
your spans, so update dashboards and alerts before switching:</p>
<table><thead><tr><th></th><th>OpenInference</th><th>OpenTelemetry GenAI</th></tr></thead>\<tbody\><tr><td>Span name</td><td><code>ChatCompletion</code></td><td><code>chat {model}</code></td></tr><tr><td>Span kind</td><td><code>INTERNAL</code></td><td><code>CLIENT</code></td></tr><tr><td>Model</td><td><code>llm.model_name</code></td><td><code>gen_ai.request.model</code>, <code>gen_ai.response.model</code></td></tr><tr><td>Provider</td><td><code>llm.system</code></td><td><code>gen_ai.provider.name</code></td></tr><tr><td>Tokens</td><td><code>llm.token_count.prompt</code></td><td><code>gen_ai.usage.input_tokens</code></td></tr><tr><td>Messages</td><td><code>llm.input_messages.N.*</code></td><td><code>gen_ai.input.messages</code> (single JSON value)</td></tr><tr><td>Errors</td><td><code>exception</code> event</td><td><code>error.type</code> attribute</td></tr></tbody></table>
<p>Note that the GenAI conventions are still marked Development upstream, so
attribute names may change in future releases.</p>
<p>Since span names include the model, they are higher cardinality than
OpenInference&#x27;s fixed names. This matters for backends that index on span name.</p>

OpenInference convention. They have no effect when <code>gen_ai</code> is selected.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="mcp-spans">MCP spans<a href="#mcp-spans" class="hash-link" aria-label="Direct link to MCP spans" title="Direct link to MCP spans" translate="no">​</a></h3>
<p><code>AI_GATEWAY_TRACING_SEMCONV</code> selects the vocabulary for MCP spans as well as for

the <a href="https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/mcp.md" target="_blank" rel="noopener noreferrer" class="">OpenTelemetry MCP semantic conventions</a>.</p>

<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="session-tracking">Session Tracking<a href="#session-tracking" class="hash-link" aria-label="Direct link to Session Tracking" title="Direct link to Session Tracking" translate="no">​</a></h2>
<p>Sessions help track and organize related traces across multi-turn conversations
with your AI app. Maintaining context between interactions is key for
observability.</p>
<p>With sessions, you can:</p>
\<ul\>
<li class="">Track a conversation&#x27;s full history in one thread.</li>
<li class="">View inputs/outputs for a given agent.</li>
<li class="">Monitor token usage and latency per conversation.</li>
</ul>
<p>By tagging spans with a consistent session ID, you get a connected view of
performance across a user&#x27;s journey.</p>
<p>The challenge is that requests to the gateway may not send traces, making
grouping difficult. Many GenAI frameworks allow you to set custom HTTP headers
when sending traffic to an LLM. Propagating sessions this way is simpler than
instrumenting applications with tracing code and can still achieve grouping.</p>
<p>There&#x27;s no standard name for session ID headers, but there is a common attribute
in OpenTelemetry, <a href="https://opentelemetry.io/docs/specs/semconv/registry/attributes/session/" target="_blank" rel="noopener noreferrer" class="">session.id</a>, which has special handling in some
OpenTelemetry platforms such as <a href="https://arize.com/docs/phoenix/tracing/llm-traces/sessions" target="_blank" rel="noopener noreferrer" class="">Phoenix</a>.</p>
<p>To bridge this gap, Agent Router lets you map HTTP request headers to
OpenTelemetry attributes. You can define a base mapping shared by metrics,
spans, and access logs, plus optional per-signal mappings for metrics, spans,
and access logs.</p>
\<ul\>
<li class=""><code>controller.requestHeaderAttributes</code></li>
<li class=""><code>controller.spanRequestHeaderAttributes</code></li>
<li class=""><code>controller.metricsRequestHeaderAttributes</code></li>
<li class=""><code>controller.logRequestHeaderAttributes</code></li>
</ul>
<p><code>controller.spanRequestHeaderAttributes</code> and <code>controller.logRequestHeaderAttributes</code> default to <code>agent-session-id:session.id</code> when unset (set them to an empty string to disable the default). Metrics never default to <code>session.id</code>.</p>
<p>Both of these use the same value format: a comma-separated list of
<code><http-header>:<otel-attribute></code> pairs. For example, if your session ID header
is <code>agent-session-id</code>, you can map it to the standard OpenTelemetry attribute
<code>session.id</code> like this: <code>agent-session-id:session.id</code>.</p>
<p>Some metrics systems will be able to do fine-grained aggregation, but not all.
Here&#x27;s an example of keeping the default session mapping for spans/logs while
only adding a low-cardinality attribute to metrics:</p>
<div class="language-shell codeBlockContainer_Ckt0 theme-code-block" style="--prism-color:#393A34;--prism-background-color:#f6f8fa"><div class="codeBlockContent_QJqH"><pre tabindex="0" class="prism-code language-shell codeBlock_bY9V thin-scrollbar" style="color:#393A34;background-color:#f6f8fa"><code class="codeBlockLines_e6Vv"><div class="token-line" style="color:#393A34"><span class="token plain">helm upgrade aieg oci://docker.io/envoyproxy/ai-gateway-helm \</span><br></div><div class="token-line" style="color:#393A34"><span class="token plain">  --version v1.2.0 \</span><br></div><div class="token-line" style="color:#393A34"><span class="token plain">  --namespace envoy-ai-gateway-system \</span><br></div><div class="token-line" style="color:#393A34"><span class="token plain">  --reuse-values \</span><br></div><div class="token-line" style="color:#393A34"><span class="token plain">  --set "controller.metricsRequestHeaderAttributes=x-tenant-id:tenant.id"</span><br></div></code></pre></div></div>

<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="per-gateway-configuration">Per-Gateway Configuration<a href="#per-gateway-configuration" class="hash-link" aria-label="Direct link to Per-Gateway Configuration" title="Direct link to Per-Gateway Configuration" translate="no">​</a></h2>

use the <code>GatewayConfig</code> CRD instead of global Helm values. This allows you to:</p>

<li class="">Set per-gateway service names for better trace organization</li>
<li class="">Override global tracing settings for specific Gateways</li>
</ul>
