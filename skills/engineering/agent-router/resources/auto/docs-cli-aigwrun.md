<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="overview">Overview<a href="#overview" class="hash-link" aria-label="Direct link to Overview" title="Direct link to Overview" translate="no">​</a></h2>
<p>This command runs the Agent Router locally as a standalone proxy with a given configuration file without any dependencies such as docker or Kubernetes.
Since the project is primarily focused on the Kubernetes environment, this command is useful for testing the configuration locally before deploying it to a Kubernetes cluster.
Not only does it help in testing the configuration, but it is also useful in a local development environment of the provider-agnostic AI applications.</p>

<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="quick-start">Quick Start<a href="#quick-start" class="hash-link" aria-label="Direct link to Quick Start" title="Direct link to Quick Start" translate="no">​</a></h2>
<p>The simplest way to get started is to have <code>aigw</code> generate a configuration for
you using environment variables. <code>aigw</code> supports auto-configuration using the same

<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="mcp-servers-configuration-format">MCP Servers Configuration Format<a href="#mcp-servers-configuration-format" class="hash-link" aria-label="Direct link to MCP Servers Configuration Format" title="Direct link to MCP Servers Configuration Format" translate="no">​</a></h3>
<p>Each server configuration in the <code>mcpServers</code> object supports the following properties:</p>
<p><strong><code>type</code></strong> (string, required)</p>
<p>The transport protocol for the MCP server. Supported values: <code>"http"</code>, <code>"streamable-http"</code>, <code>"streamable_http"</code>, or <code>"streamableHttp"</code>.</p>
<p><strong><code>url</code></strong> (string, required)</p>
<p>The full endpoint URL for the MCP server, including protocol, hostname, and path.</p>
<p><strong><code>headers</code></strong> (object, optional)</p>
<p>HTTP headers to send with requests to the MCP server. Authorization headers with Bearer tokens are automatically extracted and injected as API keys.</p>
<p>Example:</p>
<div class="language-json codeBlockContainer_Ckt0 theme-code-block" style="--prism-color:#393A34;--prism-background-color:#f6f8fa"><div class="codeBlockContent_QJqH"><pre tabindex="0" class="prism-code language-json codeBlock_bY9V thin-scrollbar" style="color:#393A34;background-color:#f6f8fa"><code class="codeBlockLines_e6Vv"><div class="token-line" style="color:#393A34"><span class="token property" style="color:#36acaa">"headers"</span><span class="token operator" style="color:#393A34">:</span><span class="token plain"> </span><span class="token punctuation" style="color:#393A34">{</span><span class="token plain"></span><br></div><div class="token-line" style="color:#393A34"><span class="token plain">  </span><span class="token property" style="color:#36acaa">"Authorization"</span><span class="token operator" style="color:#393A34">:</span><span class="token plain"> </span><span class="token string" style="color:#e3116c">"Bearer ${GITHUB_TOKEN}"</span><span class="token punctuation" style="color:#393A34">,</span><span class="token plain"></span><br></div><div class="token-line" style="color:#393A34"><span class="token plain">  </span><span class="token property" style="color:#36acaa">"X-Custom-Header"</span><span class="token operator" style="color:#393A34">:</span><span class="token plain"> </span><span class="token string" style="color:#e3116c">"value"</span><span class="token plain"></span><br></div><div class="token-line" style="color:#393A34"><span class="token plain"></span><span class="token punctuation" style="color:#393A34">}</span><br></div></code></pre></div></div>
<p>Header values support environment variable substitution using <code>${VAR}</code> syntax. For example, <code>${GITHUB_TOKEN}</code> will be replaced at runtime with the value of the <code>GITHUB_TOKEN</code> environment variable.</p>
<p><strong><code>includeTools</code></strong> (array of strings, optional)</p>
<p>List of specific tool names to expose from this server. If not specified, all tools from the server are exposed.</p>
<p>This follows the same convention as <a href="https://google-gemini.github.io/gemini-cli/docs/tools/mcp-server.html#optional" target="_blank" rel="noopener noreferrer" class="">Gemini CLI&#x27;s tool filtering</a>.</p>
<p>Example:</p>
<div class="language-json codeBlockContainer_Ckt0 theme-code-block" style="--prism-color:#393A34;--prism-background-color:#f6f8fa"><div class="codeBlockContent_QJqH"><pre tabindex="0" class="prism-code language-json codeBlock_bY9V thin-scrollbar" style="color:#393A34;background-color:#f6f8fa"><code class="codeBlockLines_e6Vv"><div class="token-line" style="color:#393A34"><span class="token property" style="color:#36acaa">"includeTools"</span><span class="token operator" style="color:#393A34">:</span><span class="token plain"> </span><span class="token punctuation" style="color:#393A34">[</span><span class="token string" style="color:#e3116c">"issue_read"</span><span class="token punctuation" style="color:#393A34">,</span><span class="token plain"> </span><span class="token string" style="color:#e3116c">"list_issues"</span><span class="token punctuation" style="color:#393A34">,</span><span class="token plain"> </span><span class="token string" style="color:#e3116c">"search_issues"</span><span class="token punctuation" style="color:#393A34">]</span><br></div></code></pre></div></div>

<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="advanced-mcp-configuration">Advanced MCP Configuration<a href="#advanced-mcp-configuration" class="hash-link" aria-label="Direct link to Advanced MCP Configuration" title="Direct link to Advanced MCP Configuration" translate="no">​</a></h3>
<p>For production deployments with advanced features like OAuth authentication, fine-grained access control, and Kubernetes integration, use the <a class="" href="/docs/capabilities/mcp/"><code>MCPRoute</code> API</a>. The same configuration can be used in both <code>aigw run</code> standalone mode and Kubernetes environments.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="admin-endpoints">Admin Endpoints<a href="#admin-endpoints" class="hash-link" aria-label="Direct link to Admin Endpoints" title="Direct link to Admin Endpoints" translate="no">​</a></h3>
<p>While running, <code>aigw</code> serves admin endpoints on port <code>1064</code> by default:</p>
\<ul\>
<li class=""><code>/metrics</code>: Prometheus metrics endpoint for <a class="" href="/docs/capabilities/observability/metrics">LLM/AI metrics</a></li>
<li class=""><code>/health</code>: Health check endpoint that verifies the external processor is healthy</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="opentelemetry">OpenTelemetry<a href="#opentelemetry" class="hash-link" aria-label="Direct link to OpenTelemetry" title="Direct link to OpenTelemetry" translate="no">​</a></h2>
<p>Agent Router&#x27;s router joins and records distributed traces when supplied
with an <a href="https://opentelemetry.io/" target="_blank" rel="noopener noreferrer" class="">OpenTelemetry</a> collector endpoint.</p>
<p>Requests to the OpenAI Chat Completions and Embeddings endpoints are recorded
as Spans which include typical timing and request details. In addition, there
are GenAI attributes representing the LLM or Embeddings call including full
request and response details, defined by <a href="https://github.com/Arize-ai/openinference/tree/main/spec" target="_blank" rel="noopener noreferrer" class="">OpenInference semantic conventions</a>.</p>
<p>OpenInference attributes default to include full request and response data for
both chat completions and embeddings. This can be toggled with configuration,
but when enabled allows systems like <a href="https://docs.arize.com/phoenix" target="_blank" rel="noopener noreferrer" class="">Arize Phoenix</a> to perform
evaluations of production requests captured in OpenTelemetry spans.</p>
<p>For chat completions, this includes traditional LLM metrics such as correctness
and hallucination detection. For embeddings, it enables agentic RAG evaluations
focused on retrieval and semantic analysis.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="opentelemetry-configuration">OpenTelemetry configuration<a href="#opentelemetry-configuration" class="hash-link" aria-label="Direct link to OpenTelemetry configuration" title="Direct link to OpenTelemetry configuration" translate="no">​</a></h3>
<p><code>aigw run</code> supports OpenTelemetry tracing via environment variables:</p>
\<ul\>
<li class="">
<p><strong><a href="https://opentelemetry.io/docs/specs/otel/configuration/sdk-environment-variables/" target="_blank" rel="noopener noreferrer" class="">OTEL SDK</a></strong>: OTLP exporter configuration that controls span
and metrics export such as:</p>
\<ul\>
<li class=""><code>OTEL_EXPORTER_OTLP_ENDPOINT</code>: Collector endpoint (e.g., <code>http://phoenix:6006</code>)</li>
<li class=""><code>OTEL_EXPORTER_OTLP_TRACES_ENDPOINT</code>: Override traces endpoint separately</li>
<li class=""><code>OTEL_EXPORTER_OTLP_METRICS_ENDPOINT</code>: Override metrics endpoint separately</li>
<li class=""><code>OTEL_TRACES_EXPORTER</code>: Traces exporter type (e.g., <code>console</code>, <code>otlp</code>, <code>none</code>)</li>
<li class=""><code>OTEL_METRICS_EXPORTER</code>: Metrics exporter type (e.g., <code>console</code>, <code>otlp</code>, <code>none</code>)</li>
<li class=""><code>OTEL_BSP_SCHEDULE_DELAY</code>: Batch span processor delay (default: 5000ms)</li>
<li class=""><code>OTEL_METRIC_EXPORT_INTERVAL</code>: Metrics export interval (default: 60000ms)</li>
</ul>
</li>
<li class="">
<p><strong>Semantic Convention</strong>: Select which span attributes are recorded. See
<a class="" href="/docs/capabilities/observability/tracing#semantic-conventions">Tracing</a> for the attribute differences.</p>
\<ul\>
<li class=""><code>AI_GATEWAY_TRACING_SEMCONV</code>: <code>openinference</code> (default) or <code>gen_ai</code> for the
OpenTelemetry GenAI conventions. An unrecognized value fails startup.</li>
<li class=""><code>OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT</code>: Capture message content
when <code>gen_ai</code> is selected (default: <code>false</code>). The GenAI conventions treat
content as opt-in, unlike OpenInference.</li>
<li class="">This also selects the vocabulary for MCP spans: the default keeps the
gateway-specific <code>mcp.*</code> attributes, <code>gen_ai</code> opts into the OpenTelemetry MCP
conventions.</li>
</ul>
</li>
<li class="">
<p><strong><a href="https://github.com/Arize-ai/openinference/blob/main/spec/configuration.md" target="_blank" rel="noopener noreferrer" class="">OpenInference</a></strong>: Control sensitive data redaction,
such as below. These apply only when <code>AI_GATEWAY_TRACING_SEMCONV</code> is
<code>openinference</code>. There is <a href="https://github.com/Arize-ai/openinference/blob/main/spec/embedding_spans.md" target="_blank" rel="noopener noreferrer" class="">similar config</a> for embeddings:</p>
\<ul\>
<li class=""><code>OPENINFERENCE_HIDE_INPUTS</code>: Hide input messages/prompts (default: <code>false</code>)</li>
<li class=""><code>OPENINFERENCE_HIDE_OUTPUTS</code>: Hide output messages/completions (default: <code>false</code>)</li>
<li class=""><code>OPENINFERENCE_HIDE_EMBEDDINGS_TEXT</code>: Hide embeddings input (default: <code>false</code>)</li>
<li class=""><code>OPENINFERENCE_HIDE_EMBEDDINGS_VECTORS</code>: Hide embeddings output (default: <code>false</code>)</li>
</ul>
</li>
<li class="">
<p><strong>Header Mapping</strong>: Map HTTP request headers to span attributes, metric labels, and access log attributes. See <a class="" href="/docs/capabilities/observability/tracing#session-tracking">Session Tracking</a> for more details.</p>
\<ul\>
<li class=""><code>OTEL_AIGW_REQUEST_HEADER_ATTRIBUTES</code>: Base mapping applied to metrics, spans, and access logs. Example: <code>x-tenant-id:tenant.id</code></li>
<li class=""><code>OTEL_AIGW_SPAN_REQUEST_HEADER_ATTRIBUTES</code>: Span-only mapping (merged with base). Default: <code>agent-session-id:session.id</code> when unset (set to empty to disable). Example: <code>x-forwarded-proto:url.scheme</code></li>
<li class=""><code>OTEL_AIGW_METRICS_REQUEST_HEADER_ATTRIBUTES</code>: Metrics-only mapping (merged with base). Example: <code>x-tenant-id:tenant.id</code> (metrics never default to <code>session.id</code>)</li>
<li class=""><code>OTEL_AIGW_LOG_REQUEST_HEADER_ATTRIBUTES</code>: Access-log-only mapping (merged with base). Default: <code>agent-session-id:session.id</code> when unset (set to empty to disable). Example: <code>x-forwarded-proto:url.scheme</code></li>
</ul>
</li>
</ul>
<p>See <a href="https://github.com/theagentrouter/agent-router/blob/main/cmd/aigw/docker-compose-otel.yaml" target="_blank" rel="noopener noreferrer" class="">docker-compose-otel.yaml</a> for a complete example configuration.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="configuration">Configuration<a href="#configuration" class="hash-link" aria-label="Direct link to Configuration" title="Direct link to Configuration" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="file-locations">File Locations<a href="#file-locations" class="hash-link" aria-label="Direct link to File Locations" title="Direct link to File Locations" translate="no">​</a></h3>
<p><code>aigw run</code> uses the <a href="https://specifications.freedesktop.org/basedir-spec/basedir-spec-latest.html" target="_blank" rel="noopener noreferrer" class="">XDG Base Directory Specification</a> to organize files:</p>
<table><thead><tr><th>Environment Variable</th><th>Default Path</th><th>Purpose</th></tr></thead>\<tbody\><tr><td><code>AIGW_CONFIG_HOME</code></td><td><code>~/.config/aigw</code></td><td>User configuration files</td></tr><tr><td><code>AIGW_DATA_HOME</code></td><td><code>~/.local/share/aigw</code></td><td>Downloaded Envoy binaries</td></tr><tr><td><code>AIGW_STATE_HOME</code></td><td><code>~/.local/state/aigw</code></td><td>Persistent logs and configs</td></tr><tr><td><code>AIGW_RUNTIME_DIR</code></td><td><code>/tmp/aigw-${UID}</code></td><td>Ephemeral runtime files</td></tr></tbody></table>
<p>See <a class="" href="/docs/cli/aigwinstall#configuration">Installation - Configuration</a> for more details about XDG directories.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="file-mappings">File Mappings<a href="#file-mappings" class="hash-link" aria-label="Direct link to File Mappings" title="Direct link to File Mappings" translate="no">​</a></h3>
<p>Each invocation creates a unique run identifier (<code>runID</code>) in format <code>YYYYMMDD_HHMMSS_UUU</code> to isolate concurrent runs:</p>
<table><thead><tr><th>File Type</th><th>Purpose</th><th>Path</th><th>Type</th></tr></thead>\<tbody\><tr><td>Default Config</td><td>Configuration file location</td><td><code>${AIGW_CONFIG_HOME}/config.yaml</code></td><td>CONFIG</td></tr><tr><td>Envoy Version Preference</td><td>Selected Envoy version (via func-e)</td><td><code>${AIGW_CONFIG_HOME}/envoy-version</code></td><td>CONFIG</td></tr><tr><td>Envoy Binaries</td><td>Downloaded executables (via func-e)</td><td><code>${AIGW_DATA_HOME}/envoy-versions/{version}/bin/envoy</code></td><td>DATA</td></tr><tr><td>AIGW Logs</td><td>Gateway logs and stderr output</td><td><code>${AIGW_STATE_HOME}/runs/{runID}/aigw.log</code></td><td>STATE</td></tr><tr><td>Envoy Gateway Config</td><td>Generated EG configuration</td><td><code>${AIGW_STATE_HOME}/runs/{runID}/envoy-gateway-config.yaml</code></td><td>STATE</td></tr><tr><td>Envoy Gateway Resources</td><td>Generated EG resources (Gateway, Routes)</td><td><code>${AIGW_STATE_HOME}/runs/{runID}/envoy-ai-gateway-resources/...</code></td><td>STATE</td></tr><tr><td>External Processor Config</td><td>Generated extproc configuration</td><td><code>${AIGW_STATE_HOME}/runs/{runID}/extproc-config.yaml</code></td><td>STATE</td></tr><tr><td>Envoy Run Logs (func-e)</td><td>Envoy stdout/stderr (via func-e)</td><td><code>${AIGW_STATE_HOME}/envoy-runs/{runID}/stdout.log,stderr.log</code></td><td>STATE</td></tr><tr><td>UDS Socket</td><td>Unix domain socket for extproc</td><td><code>${AIGW_RUNTIME_DIR}/{runID}/uds.sock</code></td><td>RUNTIME</td></tr><tr><td>Admin Address (func-e)</td><td>Envoy admin endpoint (via func-e)</td><td><code>${AIGW_RUNTIME_DIR}/{runID}/admin-address.txt</code></td><td>RUNTIME</td></tr></tbody></table>
<p><strong>File Categories:</strong></p>
\<ul\>
<li class=""><strong>CONFIG</strong>: User-specific configuration (persistent, shared across runs)</li>
<li class=""><strong>DATA</strong>: Downloaded binaries (persistent, shared across runs)</li>
<li class=""><strong>STATE</strong>: Per-run logs and configs (persistent for debugging)</li>
<li class=""><strong>RUNTIME</strong>: Ephemeral files like sockets (cleaned on reboot)</li>
</ul>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="runid"><code>runID</code><a href="#runid" class="hash-link" aria-label="Direct link to runid" title="Direct link to runid" translate="no">​</a></h3>
<p>By default, <code>aigw run</code> generates a timestamp-based <code>runID</code> for each invocation. You can customize this for predictable paths:</p>
<div class="language-shell codeBlockContainer_Ckt0 theme-code-block" style="--prism-color:#393A34;--prism-background-color:#f6f8fa"><div class="codeBlockContent_QJqH"><pre tabindex="0" class="prism-code language-shell codeBlock_bY9V thin-scrollbar" style="color:#393A34;background-color:#f6f8fa"><code class="codeBlockLines_e6Vv"><div class="token-line" style="color:#393A34"><span class="token plain"># Use run ID "0" for Docker/Kubernetes deployments</span><br></div><div class="token-line" style="color:#393A34"><span class="token plain">aigw run --run-id=0</span><br></div><div class="token-line" style="color:#393A34"><span class="token plain" style="display:inline-block"></span><br></div><div class="token-line" style="color:#393A34"><span class="token plain"># Or via environment variable</span><br></div><div class="token-line" style="color:#393A34"><span class="token plain">AIGW_RUN_ID=production aigw run</span><br></div></code></pre></div></div>
<p>Custom run IDs:</p>
\<ul\>
<li class="">Enable predictable file paths in containers</li>
<li class="">Allow correlation across multiple runs with the same ID</li>
<li class="">Must not contain path separators (<code>/</code> or <code>\</code>)</li>
</ul>
