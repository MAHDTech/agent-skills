<p><code>QuotaPolicy</code> enables token-based quota management for AI inference services in Agent Router.
When all related backend&#x27;s quota are exceeded, requests are rejected with a <code>429 Too Many Requests</code> status code.</p>
<div class="theme-admonition theme-admonition-note admonition_xJq3 alert alert--secondary"><div class="admonitionHeading_Gvgb"><span class="admonitionIcon_Rf37"><svg viewBox="0 0 14 16"><path fill-rule="evenodd" d="M6.3 5.69a.942.942 0 0 1-.28-.7c0-.28.09-.52.28-.7.19-.18.42-.28.7-.28.28 0 .52.09.7.28.18.19.28.42.28.7 0 .28-.09.52-.28.7a1 1 0 0 1-.7.3c-.28 0-.52-.11-.7-.3zM8 7.99c-.02-.25-.11-.48-.31-.69-.2-.19-.42-.3-.69-.31H6c-.27.02-.48.13-.69.31-.2.2-.3.44-.31.69h1v3c.02.27.11.5.31.69.2.2.42.31.69.31h1c.27 0 .48-.11.69-.31.2-.19.3-.42.31-.69H8V7.98v.01zM7 2.3c-3.14 0-5.7 2.54-5.7 5.68 0 3.14 2.56 5.7 5.7 5.7s5.7-2.55 5.7-5.7c0-3.15-2.56-5.69-5.7-5.69v.01zM7 .98c3.86 0 7 3.14 7 7s-3.14 7-7 7-7-3.12-7-7 3.14-7 7-7z"></path></svg></span>QuotaPolicy vs. usage-based rate limiting</div><div class="admonitionContent_BuS1"><p><code>QuotaPolicy</code> manages the platform&#x27;s upstream consumption budget: how many tokens the gateway may
spend against a provider backend and model across all routes and consumers. <a class="" href="/docs/capabilities/traffic/usage-based-ratelimiting">Usage-based rate
limiting</a> manages consumer usage: how much a client may consume on a
route. Both can count tokens and return <code>429 Too Many Requests</code>, but they answer different questions:
whether the platform has exhausted its budget for a provider/model, or whether a client has exceeded
its allowance. See <a href="#choosing-a-policy" class="">Choosing a policy</a> for details.</p></div></div>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="overview">Overview<a href="#overview" class="hash-link" aria-label="Direct link to Overview" title="Direct link to Overview" translate="no">​</a></h2>
<p>Key features of QuotaPolicy:</p>
\<ul\>
<li class=""><strong>Per-model token quotas</strong> — assign token budgets to individual models served by an <code>AIServiceBackend</code>.</li>
<li class=""><strong>CEL cost expressions</strong> — weight input, output, cached, and reasoning tokens differently when
computing how much a request burns down a quota.</li>
<li class=""><strong>Client-selector bucket rules</strong> — carve out per-tenant or per-header quotas using request attributes.</li>
<li class=""><strong>Shadow mode</strong> — evaluate quota rules without enforcing them, for safe rollout.</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="choosing-a-policy">Choosing a Policy<a href="#choosing-a-policy" class="hash-link" aria-label="Direct link to Choosing a Policy" title="Direct link to Choosing a Policy" translate="no">​</a></h2>
<p>Both policies use Envoy&#x27;s rate limit protocol and Redis-backed counters, but <code>QuotaPolicy</code> is enforced
by a dedicated AI Gateway rate limit service. Usage-based rate limiting uses Envoy Gateway&#x27;s global
rate limit service. Choose between them based on the budget&#x27;s intent and scope:</p>
<table><thead><tr><th></th><th><code>QuotaPolicy</code></th><th>Usage-based rate limiting</th></tr></thead>\<tbody\><tr><td>Configuration</td><td>One AI Gateway policy containing the token cost and quota buckets</td><td><code>llmRequestCosts</code> on an <code>AIGatewayRoute</code>, plus an Envoy Gateway <code>BackendTrafficPolicy</code></td></tr><tr><td>Scope</td><td>Backend- and model-scoped - the budget follows an <code>AIServiceBackend</code> across every route that sends traffic to it</td><td>Route/Gateway-scoped - budgets are keyed by client descriptors on a route</td></tr><tr><td>Token accounting</td><td>One default or custom CEL cost per model</td><td>Multiple metadata keys can track and limit input, output, total, or custom token costs separately</td></tr><tr><td>Client budgets</td><td>Default and header-selected buckets, with optional shadow mode</td><td>Envoy Gateway client selectors and rate limit rules</td></tr><tr><td>Enforcement</td><td>In <code>Shared</code> mode, a request is denied only when all applicable quota buckets are exhausted; the quota is evaluated for the selected backend</td><td>A request is denied when any matched rate limit is exceeded; limits are evaluated from the route&#x27;s client descriptors</td></tr><tr><td>Time windows</td><td>Exactly one second, minute, hour, or day</td><td>One second, minute, hour, day, month, or year</td></tr></tbody></table>
<p>Use <code>QuotaPolicy</code> when the platform needs to protect its provider budget for a backend and model.
For example, a platform team can give every tenant a separate daily budget for an expensive model,
set a shared backend budget alongside those tenant budgets, and evaluate a new tenant rule in shadow
mode. The policy stays with the <code>AIServiceBackend</code> even when multiple routes send traffic to it.</p>
<p>Use usage-based rate limiting when you need to define each client&#x27;s allowance on a route. It is also
the natural choice when you need lower-level Envoy Gateway controls, route-specific token cost
metadata, separate limits for input and output tokens, or a monthly or yearly window.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="how-it-works">How It Works<a href="#how-it-works" class="hash-link" aria-label="Direct link to How It Works" title="Direct link to How It Works" translate="no">​</a></h2>
\<ol\>
<li class="">A <code>QuotaPolicy</code> is attached to one or more <code>AIServiceBackend</code> resources via <code>targetRefs</code>.</li>
<li class="">For each completed request, the token cost is computed using the configured cost expression
(defaults to <code>total_tokens</code>).</li>
<li class="">The cost is charged against the matching quota bucket (the per-model default bucket, or a matching
bucket rule).</li>
<li class="">When all related quota buckets for that model are exceeded, subsequent matching requests receive <code>429 Too Many Requests</code>.</li>
</ol>
<div class="theme-admonition theme-admonition-tip admonition_xJq3 alert alert--success"><div class="admonitionHeading_Gvgb"><span class="admonitionIcon_Rf37"><svg viewBox="0 0 12 16"><path fill-rule="evenodd" d="M6.5 0C3.48 0 1 2.19 1 5c0 .92.55 2.25 1 3 1.34 2.25 1.78 2.78 2 4v1h5v-1c.22-1.22.66-1.75 2-4 .45-.75 1-2.08 1-3 0-2.81-2.48-5-5.5-5zm3.64 7.48c-.25.44-.47.8-.67 1.11-.86 1.41-1.25 2.06-1.45 3.23-.02.05-.02.11-.02.17H5c0-.06 0-.13-.02-.17-.2-1.17-.59-1.83-1.45-3.23-.2-.31-.42-.67-.67-1.11C2.44 6.78 2 5.65 2 5c0-2.2 2.02-4 4.5-4 1.22 0 2.36.42 3.22 1.19C10.55 2.94 11 3.94 11 5c0 .66-.44 1.78-.86 2.48zM4 14h5c-.23 1.14-1.3 2-2.5 2s-2.27-.86-2.5-2z"></path></svg></span>Prerequisites</div><div class="admonitionContent_BuS1"><p>Quota enforcement requires two components that are not deployed by the AI Gateway Helm chart today:</p>\<ol\>
<li class=""><strong>Redis</strong> stores quota counters. See the
<a href="https://github.com/theagentrouter/agent-router/blob/main/examples/token_ratelimit/redis.yaml" target="_blank" rel="noopener noreferrer" class="">redis.yaml example</a>
for a simple deployment.</li>
<li class=""><strong>A dedicated rate limit service</strong> evaluates the <code>ai-gateway-quota</code> domain. It must use the AI
Gateway controller&#x27;s xDS server for configuration, with node ID <code>envoy-ai-gateway-ratelimit</code>, and
listen at the controller&#x27;s <code>quotaRateLimitServiceAddr</code>. The
<a href="https://github.com/theagentrouter/agent-router/blob/main/tests/e2e/testdata/backend_quota_ratelimit.yaml" target="_blank" rel="noopener noreferrer" class="">quota E2E manifest</a>
provides a deployment example.</li>
</ol><p>Envoy Gateway&#x27;s rate-limit addon is a separate service used by usage-based rate limiting. It is not
required for a QuotaPolicy-only deployment, although both services can use the same Redis instance.</p><p>By default, <code>controller.quotaRateLimitFailureModeDeny</code> is <code>false</code>. If the dedicated service is absent
or unreachable, quota checks fail open and requests continue without enforcement. Set it to <code>true</code>
if unavailable quota enforcement should reject requests instead.</p></div></div>

<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id="bucket-mode">Bucket Mode<a href="#bucket-mode" class="hash-link" aria-label="Direct link to Bucket Mode" title="Direct link to Bucket Mode" translate="no">​</a></h3>
<p>The <code>mode</code> field on a per-model <code>quota</code> controls how the <code>defaultBucket</code> and matching <code>bucketRules</code>

<p>Shadow mode is configured per bucket rule. It cannot be set on the <code>defaultBucket</code>.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="duration-format">Duration Format<a href="#duration-format" class="hash-link" aria-label="Direct link to Duration Format" title="Direct link to Duration Format" translate="no">​</a></h2>
<p>The <code>duration</code> field selects the sliding-window size. It must be exactly one of the following values:</p>
<table><thead><tr><th>Value</th><th>Window</th></tr></thead>\<tbody\><tr><td><code>"1s"</code></td><td>One second</td></tr><tr><td><code>"1m"</code></td><td>One minute</td></tr><tr><td><code>"1h"</code></td><td>One hour</td></tr><tr><td><code>"1d"</code></td><td>One day</td></tr></tbody></table>
<p>The window is fixed-size — arbitrary multiples such as <code>"30s"</code> or <code>"15m"</code> are <strong>not</strong> valid and will
be rejected by the CRD schema. Choose the <code>limit</code> to express your budget within one of these windows.</p>
<p>The one-day maximum is a current <code>QuotaPolicy</code> API restriction, not an inherent limitation of token
accounting. Token-based rate limiting configured through an Envoy Gateway <code>BackendTrafficPolicy</code>
also supports <code>Month</code> and <code>Year</code> units. Use <a class="" href="/docs/capabilities/traffic/usage-based-ratelimiting">usage-based rate limiting</a>
when a token budget needs either of those longer windows.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="service-wide-quota">Service-Wide Quota<a href="#service-wide-quota" class="hash-link" aria-label="Direct link to Service-Wide Quota" title="Direct link to Service-Wide Quota" translate="no">​</a></h2>
<div class="theme-admonition theme-admonition-warning admonition_xJq3 alert alert--warning"><div class="admonitionHeading_Gvgb"><span class="admonitionIcon_Rf37"><svg viewBox="0 0 16 16"><path fill-rule="evenodd" d="M8.893 1.5c-.183-.31-.52-.5-.887-.5s-.703.19-.886.5L.138 13.499a.98.98 0 0 0 0 1.001c.193.31.53.501.886.501h13.964c.367 0 .704-.19.877-.5a1.03 1.03 0 0 0 .01-1.002L8.893 1.5zm.133 11.497H6.987v-2.003h2.039v2.003zm0-3.004H6.987V5.987h2.039v4.006z"></path></svg></span>Not yet available</div><div class="admonitionContent_BuS1"><p>The API exposes a backend-wide <code>serviceQuota</code> field — intended to apply a single budget across all
models on a backend — but it is <strong>not yet enforced</strong> (it is currently a known TODO in the API).
Configuring it has no effect on traffic, so use <a href="#per-model-quotas" class="">Per-Model Quotas</a> to enforce
token quotas today. This section will document <code>serviceQuota</code> once enforcement lands.</p></div></div>
