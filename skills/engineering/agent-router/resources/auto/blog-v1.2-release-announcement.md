<p><strong>Agent Router 1.2 is out.</strong> It is the first release since Envoy AI Gateway became Agent Router,
and nothing you deploy is renamed: same CRDs, same Helm charts, same <code>aigw</code> CLI.</p>
<p>The short version: 1.2 makes the gateway safe to share. Safe to put your MCP tools in front of real
users. Safe to run one gateway for many teams. And easier to trust when something goes wrong in
production.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="put-mcp-tools-in-front-of-real-users">Put MCP tools in front of real users<a href="#put-mcp-tools-in-front-of-real-users" class="hash-link" aria-label="Direct link to Put MCP tools in front of real users" title="Direct link to Put MCP tools in front of real users" translate="no">​</a></h2>
<p>When an agent calls a tool through the gateway, the gateway decides who the caller is and what they
can touch. 1.2 tightens every step of that decision:</p>
\<ul\>
<li class=""><strong>Only verified identity counts.</strong> Authorization rules read JWT claims only from tokens Envoy has
verified, and the token&#x27;s issuer must match the one you configured.</li>
<li class=""><strong>Broken rules deny.</strong> A CEL policy that errors at runtime now blocks the call instead of being
skipped.</li>
<li class=""><strong>Sessions belong to one user.</strong> An MCP session is bound to the user who started it, so someone
else can&#x27;t reuse its session ID.</li>
<li class=""><strong>No shared default key.</strong> The Helm chart generates a random session encryption seed instead of
shipping a well-known one.</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="mcp-that-fits-the-clients-you-already-have">MCP that fits the clients you already have<a href="#mcp-that-fits-the-clients-you-already-have" class="hash-link" aria-label="Direct link to MCP that fits the clients you already have" title="Direct link to MCP that fits the clients you already have" translate="no">​</a></h2>
\<ul\>
<li class=""><strong>Clean tool names.</strong> Clients that hardcode tool names, such as MCP Apps, can see <code>search_issues</code>
instead of <code>github__search_issues</code> (<code>prefixMode: Never</code>).</li>
<li class=""><strong>Bring your own token.</strong> Users can forward a personal token, such as a GitHub PAT, and fall back
to a shared service key when they don&#x27;t (<code>injectionPolicy: IfNotPresent</code>).</li>
<li class=""><strong>Keep your Gateway-wide policies.</strong> Gateway-level rate limits and ext-auth can now stay in force
alongside MCP OAuth instead of being replaced (<code>mergeType</code>).</li>
<li class=""><strong>More identity providers.</strong> Point the gateway at the exact OAuth metadata URL when your provider
doesn&#x27;t serve it at the standard path.</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="one-gateway-many-teams">One gateway, many teams<a href="#one-gateway-many-teams" class="hash-link" aria-label="Direct link to One gateway, many teams" title="Direct link to One gateway, many teams" translate="no">​</a></h2>
<p>When several teams share a gateway, one team&#x27;s config should never reach another team&#x27;s
credentials. In 1.2, a BackendSecurityPolicy can use a Secret in another namespace only when that
namespace allows it with a ReferenceGrant, for every credential type. A grant that names an object
now covers only that object, and revoking a grant takes effect right away.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="fewer-surprises-in-production">Fewer surprises in production<a href="#fewer-surprises-in-production" class="hash-link" aria-label="Direct link to Fewer surprises in production" title="Direct link to Fewer surprises in production" translate="no">​</a></h2>
\<ul\>
<li class=""><strong>Rotated credentials apply immediately.</strong> This fixes a 1.1.0 regression where upstream calls
could fail with a stale key until the next reconcile.</li>
<li class=""><strong>Compare providers side by side.</strong> GenAI metrics now carry the backend, so you can compare
latency, time to first token, and token usage for the same model across providers.</li>
<li class=""><strong>Per-tenant token limits charge the right tenant</strong>, and streaming usage is recorded even when the
client disconnects right after the last chunk.</li>
<li class=""><strong>Clear errors.</strong> Calling an endpoint a provider doesn&#x27;t support returns 422, not 500.</li>
<li class=""><strong>Smoother rollouts.</strong> The controller reports Ready only after its caches sync, and the webhook
certificate survives <code>helm upgrade</code> and Argo CD syncs.</li>
</ul>
<p>On the provider side, 1.2 adds Amazon Bedrock&#x27;s OpenAI-compatible endpoint (no translation hop) and
TypeSafe System One. It also filters <code>anthropic-beta</code> flags per backend, so one unsupported flag no
longer fails the whole request, and counts OpenAI prompt-cache writes in your cost metrics.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="before-you-upgrade">Before you upgrade<a href="#before-you-upgrade" class="hash-link" aria-label="Direct link to Before you upgrade" title="Direct link to Before you upgrade" translate="no">​</a></h2>
<p>Some of these fixes change behavior. Upgrade from 1.1.x (not directly from 1.0.x), and check these
first:</p>
\<ol\>
<li class=""><strong>Upgrade Envoy Gateway to v1.9.2 and the Gateway API CRDs to v1.6.</strong></li>
<li class=""><strong>Expect MCP clients to reconnect.</strong> The new random seed ends active sessions. A temporary
fallback seed keeps them alive.</li>
<li class=""><strong>Match <code>oauth.issuer</code> to your identity provider&#x27;s <code>iss</code> exactly</strong>, trailing slash included.</li>
<li class=""><strong>Add <code>securityPolicy.oauth</code></strong> to any MCPRoute whose CEL reads <code>auth.jwt</code>, and make CEL
null-safe.</li>
<li class=""><strong>Add ReferenceGrants</strong> for credential Secrets in other namespaces.</li>
<li class=""><strong>Review per-tenant token limits.</strong> They are now enforced correctly, so tenants may start seeing
429s.</li>
</ol>
<p>The <a class="" href="/release-notes/v1.2">v1.2 release notes</a> have the full list and step-by-step upgrade guidance.</p>
