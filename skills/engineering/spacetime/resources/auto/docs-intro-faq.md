<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="what-is-spacetimedb">What is SpacetimeDB?<a href="#what-is-spacetimedb" class="hash-link" aria-label="Direct link to What is SpacetimeDB?" title="Direct link to What is SpacetimeDB?" translate="no">​</a></h3>
<p>SpacetimeDB is a database that is also a server. You upload your application logic (called a "module") directly into the database, and clients connect to it without any server in between. It is a relational database with tables, queries, and transactions, but your business logic runs inside it as stored procedures on steroids.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-is-spacetimedb-different-from-a-traditional-backend">How is SpacetimeDB different from a traditional backend?<a href="#how-is-spacetimedb-different-from-a-traditional-backend" class="hash-link" aria-label="Direct link to How is SpacetimeDB different from a traditional backend?" title="Direct link to How is SpacetimeDB different from a traditional backend?" translate="no">​</a></h3>
<p>In a traditional stack, you deploy a web server (Node, Django, Rails, etc.) that sits between your clients and your database. You write API endpoints, manage connection pooling, handle caching, and deploy infrastructure.</p>
<p>With SpacetimeDB, you skip all of that. Your module is the backend. Clients connect directly to the database, call reducers (like RPC endpoints), and subscribe to real-time data updates. No separate server, no REST API, no GraphQL layer.</p>

<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="is-spacetimedb-only-for-games">Is SpacetimeDB only for games?<a href="#is-spacetimedb-only-for-games" class="hash-link" aria-label="Direct link to Is SpacetimeDB only for games?" title="Direct link to Is SpacetimeDB only for games?" translate="no">​</a></h3>
<p>No. SpacetimeDB is designed for any real-time application: games, chat apps, collaboration tools, dashboards, IoT, or anything that benefits from low-latency state synchronization. Games are a demanding use case that proves SpacetimeDB&#x27;s performance. Our own MMORPG <a href="https://bitcraftonline.com" target="_blank" rel="noopener noreferrer" class="">BitCraft Online</a> runs entirely on SpacetimeDB. The same architecture works for any application.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="is-spacetimedb-open-source">Is SpacetimeDB open source?<a href="#is-spacetimedb-open-source" class="hash-link" aria-label="Direct link to Is SpacetimeDB open source?" title="Direct link to Is SpacetimeDB open source?" translate="no">​</a></h3>
<p>SpacetimeDB is source-available under the <a href="https://github.com/clockworklabs/SpacetimeDB/blob/master/LICENSE.txt" target="_blank" rel="noopener noreferrer" class="">Business Source License 1.1 (BSL)</a>. It converts to the AGPL v3.0 (with a linking exception) after a few years. The linking exception means you are <strong>not</strong> required to open-source your own code if you use SpacetimeDB. You only need to contribute back changes to SpacetimeDB itself.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-does-spacetimedb-compare-to">How does SpacetimeDB compare to...<a href="#how-does-spacetimedb-compare-to" class="hash-link" aria-label="Direct link to How does SpacetimeDB compare to..." title="Direct link to How does SpacetimeDB compare to..." translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-is-spacetimedb-different-from-mirror--netcode--photon--other-networking-libraries">How is SpacetimeDB different from Mirror / Netcode / Photon / other networking libraries?<a href="#how-is-spacetimedb-different-from-mirror--netcode--photon--other-networking-libraries" class="hash-link" aria-label="Direct link to How is SpacetimeDB different from Mirror / Netcode / Photon / other networking libraries?" title="Direct link to How is SpacetimeDB different from Mirror / Netcode / Photon / other networking libraries?" translate="no">​</a></h3>
<p>Networking libraries like Mirror, Netcode for GameObjects, and Photon handle the transport layer: sending messages between clients and a server you build and deploy yourself. You are still responsible for writing server logic, managing state, handling persistence, and deploying infrastructure.</p>
<p>SpacetimeDB replaces the entire server. Your game state lives in tables, your game logic lives in reducers, and SpacetimeDB automatically synchronizes state to clients in real-time. You do not write networking code, serialization code, or deploy servers.</p>

<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-is-spacetimedb-different-from-firebase--supabase">How is SpacetimeDB different from Firebase / Supabase?<a href="#how-is-spacetimedb-different-from-firebase--supabase" class="hash-link" aria-label="Direct link to How is SpacetimeDB different from Firebase / Supabase?" title="Direct link to How is SpacetimeDB different from Firebase / Supabase?" translate="no">​</a></h3>
<p>Firebase and Supabase are Backend-as-a-Service platforms. They give you a database with an API layer on top, but your application logic still runs elsewhere (cloud functions, edge functions, or your own server). Complex business logic is awkward to express as database triggers or serverless functions.</p>
<p>SpacetimeDB lets you write your entire application as a module in a real programming language (Rust, C#, TypeScript, or C++) that runs inside the database. You get full transactional guarantees, direct table access, and real-time subscriptions without the cold starts, execution limits, or awkward abstractions of serverless functions.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-is-spacetimedb-different-from-a-regular-database-postgresql-mysql">How is SpacetimeDB different from a regular database (PostgreSQL, MySQL)?<a href="#how-is-spacetimedb-different-from-a-regular-database-postgresql-mysql" class="hash-link" aria-label="Direct link to How is SpacetimeDB different from a regular database (PostgreSQL, MySQL)?" title="Direct link to How is SpacetimeDB different from a regular database (PostgreSQL, MySQL)?" translate="no">​</a></h3>
<p>A traditional database stores data and lets you query it. Your application logic runs in a separate server that connects to the database over the network.</p>
<p>SpacetimeDB holds all data in memory for sub-microsecond access, runs your application logic inside the database as WebAssembly modules, and pushes real-time updates to connected clients automatically. It is purpose-built for real-time applications, not batch processing or analytics. For certain benchmarks, SpacetimeDB can be between 100 and 1000 times faster than a traditional database.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="core-concepts">Core Concepts<a href="#core-concepts" class="hash-link" aria-label="Direct link to Core Concepts" title="Direct link to Core Concepts" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="what-is-a-module">What is a "module"?<a href="#what-is-a-module" class="hash-link" aria-label="Direct link to What is a "module"?" title="Direct link to What is a "module"?" translate="no">​</a></h3>
<p>A module is your application&#x27;s server-side code compiled to WebAssembly (or bundled as JavaScript for TypeScript modules). It defines your tables, reducers, views, and procedures. You upload it to SpacetimeDB with <code>spacetime publish</code>, and it runs inside the database. Think of it as your entire backend in a single deployable unit.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="what-are-tables">What are tables?<a href="#what-are-tables" class="hash-link" aria-label="Direct link to What are tables?" title="Direct link to What are tables?" translate="no">​</a></h3>
<p>Tables are the core data storage in SpacetimeDB. You define them in your module using your language&#x27;s type system. Tables support primary keys, unique constraints, and indexes. Clients can subscribe to tables and receive real-time updates when rows change.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="what-are-reducers">What are reducers?<a href="#what-are-reducers" class="hash-link" aria-label="Direct link to What are reducers?" title="Direct link to What are reducers?" translate="no">​</a></h3>
<p>Reducers are functions that modify your database state. They run inside a database transaction: either all changes commit or none do. Clients call reducers through auto-generated, type-safe bindings. Think of them as transactional RPC endpoints.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="what-are-views">What are views?<a href="#what-are-views" class="hash-link" aria-label="Direct link to What are views?" title="Direct link to What are views?" translate="no">​</a></h3>
<p>Views are read-only functions that compute derived data from your tables. They are like SQL views but written in your module&#x27;s language. Clients can subscribe to views just like tables, and they update automatically when the underlying data changes. See <a class="" href="/docs/functions/views">Views</a> for details.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="what-are-procedures">What are procedures?<a href="#what-are-procedures" class="hash-link" aria-label="Direct link to What are procedures?" title="Direct link to What are procedures?" translate="no">​</a></h3>
<p>Procedures are similar to reducers but with additional capabilities. They can make HTTP requests to external services and manually manage transactions. Clients can also call procedures over HTTP. Use reducers for most cases; use procedures when you need to interact with the outside world. In the future, procedures will be configurable as HTTP endpoints. See <a class="" href="/docs/functions/procedures">Procedures</a> for details.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="architecture">Architecture<a href="#architecture" class="hash-link" aria-label="Direct link to Architecture" title="Direct link to Architecture" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-does-data-persistence-work">How does data persistence work?<a href="#how-does-data-persistence-work" class="hash-link" aria-label="Direct link to How does data persistence work?" title="Direct link to How does data persistence work?" translate="no">​</a></h3>
<p>SpacetimeDB holds all data in memory for fast access, but persists everything to a commit log (similar to a write-ahead log). On restart, the database replays the commit log to recover its exact state. You get the speed of in-memory computing with the durability of a traditional database.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-does-real-time-sync-work">How does real-time sync work?<a href="#how-does-real-time-sync-work" class="hash-link" aria-label="Direct link to How does real-time sync work?" title="Direct link to How does real-time sync work?" translate="no">​</a></h3>
<p>Clients subscribe to typed query builder expressions that specify what data they care about. (Raw SQL subscriptions are also available for advanced use cases.) SpacetimeDB evaluates these subscriptions and pushes incremental updates whenever the underlying data changes. On the client side, the SDK maintains a local cache that mirrors the server state. You query this cache directly with no round trips.</p>

<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="are-reducers-like-rest-endpoints">Are reducers like REST endpoints?<a href="#are-reducers-like-rest-endpoints" class="hash-link" aria-label="Direct link to Are reducers like REST endpoints?" title="Direct link to Are reducers like REST endpoints?" translate="no">​</a></h3>
<p>Reducers are more like transactional RPC calls. A client calls a reducer by name with arguments, the reducer runs inside a database transaction, and either all changes commit or none do. Unlike REST, there is no HTTP overhead, no JSON serialization, and no need to design URL routes. Clients call reducers through auto-generated, type-safe bindings.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="what-happens-if-a-reducer-fails">What happens if a reducer fails?<a href="#what-happens-if-a-reducer-fails" class="hash-link" aria-label="Direct link to What happens if a reducer fails?" title="Direct link to What happens if a reducer fails?" translate="no">​</a></h3>
<p>The entire transaction rolls back. No partial updates, no corrupted state. The database remains exactly as it was before the reducer was called. You can throw errors or return <code>Err</code> freely. SpacetimeDB handles the cleanup.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="what-languages-can-i-write-modules-in">What languages can I write modules in?<a href="#what-languages-can-i-write-modules-in" class="hash-link" aria-label="Direct link to What languages can I write modules in?" title="Direct link to What languages can I write modules in?" translate="no">​</a></h3>
<p>Server-side modules can be written in:</p>
\<ul\>
<li class=""><strong>Rust</strong></li>
<li class=""><strong>C#</strong></li>
<li class=""><strong>TypeScript</strong> (new in 2.0)</li>
<li class=""><strong>C++</strong> (new in 2.0)</li>
</ul>
<p>Client SDKs are available for:</p>
\<ul\>
<li class=""><strong>Rust</strong></li>
<li class=""><strong>C#</strong> (including Unity)</li>
<li class=""><strong>TypeScript</strong> (including React, Vue, Svelte, Angular, and more)</li>
<li class=""><strong>C++</strong> (Unreal Engine)</li>
</ul>
<p>SpacetimeDB 2.0 also includes a <strong>type-safe query builder</strong> for client-side subscriptions, so you do not have to write raw SQL strings if you prefer not to.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="authentication--authorization">Authentication & Authorization<a href="#authentication--authorization" class="hash-link" aria-label="Direct link to Authentication & Authorization" title="Direct link to Authentication & Authorization" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-do-i-implement-auth-in-my-app">How do I implement auth in my app?<a href="#how-do-i-implement-auth-in-my-app" class="hash-link" aria-label="Direct link to How do I implement auth in my app?" title="Direct link to How do I implement auth in my app?" translate="no">​</a></h3>
<p>SpacetimeDB uses <a href="https://openid.net/developers/how-connect-works/" target="_blank" rel="noopener noreferrer" class="">OpenID Connect (OIDC)</a> for authentication. Every reducer call includes the caller&#x27;s <code>Identity</code>, which you can use for authorization logic in your module. You have several options for identity providers:</p>
\<ul\>
<li class=""><strong><a class="" href="/docs/core-concepts/authentication/spacetimeauth/">SpacetimeAuth</a></strong>: A fully managed OIDC provider built specifically for SpacetimeDB. The easiest way to get started.</li>
<li class=""><strong>Third-party providers</strong>: Any OIDC-compliant provider works, including <a href="https://auth0.com/" target="_blank" rel="noopener noreferrer" class="">Auth0</a>, <a href="https://clerk.com/" target="_blank" rel="noopener noreferrer" class="">Clerk</a>, <a href="https://www.keycloak.org/" target="_blank" rel="noopener noreferrer" class="">Keycloak</a>, Google, GitHub, and others.</li>
</ul>
<p>See <a class="" href="/docs/core-concepts/authentication">Authentication</a> for full details.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="can-i-use-identity-as-a-1-to-1-mapping-with-users">Can I use <code>Identity</code> as a 1-to-1 mapping with users?<a href="#can-i-use-identity-as-a-1-to-1-mapping-with-users" class="hash-link" aria-label="Direct link to can-i-use-identity-as-a-1-to-1-mapping-with-users" title="Direct link to can-i-use-identity-as-a-1-to-1-mapping-with-users" translate="no">​</a></h3>
<p>Yes, and this is the recommended approach. Each authenticated user receives a stable <code>Identity</code> that persists across sessions. You can store user profiles keyed by <code>Identity</code> and use it as your primary user identifier. If you use an OIDC provider (such as SpacetimeAuth, Auth0, or Clerk), the <code>Identity</code> is derived from the provider&#x27;s tokens, so the same user always gets the same <code>Identity</code>.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="can-i-store-passwords-in-a-private-table-and-have-users-log-in-by-calling-a-reducer">Can I store passwords in a private table and have users log in by calling a reducer?<a href="#can-i-store-passwords-in-a-private-table-and-have-users-log-in-by-calling-a-reducer" class="hash-link" aria-label="Direct link to Can I store passwords in a private table and have users log in by calling a reducer?" title="Direct link to Can I store passwords in a private table and have users log in by calling a reducer?" translate="no">​</a></h3>
<p>This is not recommended. While SpacetimeDB 2.0 no longer exposes reducer arguments to subscribers (the old reducer callback system has been replaced by <a class="" href="/docs/tables/event-tables">Event Tables</a>), storing and verifying passwords in your module means implementing your own authentication logic, which is error-prone and unnecessary. Use OIDC-based authentication instead, where the identity provider handles credential verification and issues tokens that SpacetimeDB validates.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="schema--migrations">Schema & Migrations<a href="#schema--migrations" class="hash-link" aria-label="Direct link to Schema & Migrations" title="Direct link to Schema & Migrations" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-do-i-handle-schema-migrations">How do I handle schema migrations?<a href="#how-do-i-handle-schema-migrations" class="hash-link" aria-label="Direct link to How do I handle schema migrations?" title="Direct link to How do I handle schema migrations?" translate="no">​</a></h3>
<p>When you publish an updated module, SpacetimeDB compares the new schema with the existing one and performs automatic migrations for compatible changes (adding tables, adding columns with defaults, etc.). For breaking changes, you may need to publish with <code>--delete-data</code> during development. See <a class="" href="/docs/databases/automatic-migrations">Automatic Migrations</a> for details on what changes are supported.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-do-i-add-a-column-to-an-existing-table">How do I add a column to an existing table?<a href="#how-do-i-add-a-column-to-an-existing-table" class="hash-link" aria-label="Direct link to How do I add a column to an existing table?" title="Direct link to How do I add a column to an existing table?" translate="no">​</a></h3>
<p>SpacetimeDB supports adding new columns to the end of a table, provided the new columns have <a class="" href="/docs/tables/default-values">default values</a>. This is handled automatically when you republish your module. For more complex changes (reordering columns, changing types), use the <a class="" href="/docs/databases/incremental-migrations">incremental migration pattern</a>: create a new table with the desired schema and lazily migrate rows from the old table as they are accessed.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-do-i-remove-a-column-from-an-existing-table">How do I remove a column from an existing table?<a href="#how-do-i-remove-a-column-from-an-existing-table" class="hash-link" aria-label="Direct link to How do I remove a column from an existing table?" title="Direct link to How do I remove a column from an existing table?" translate="no">​</a></h3>
<p>Removing columns is not supported through automatic migration. Use <a class="" href="/docs/databases/incremental-migrations">incremental migrations</a> instead: create a new table without the column and migrate data incrementally.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-do-i-add-a-new-table">How do I add a new table?<a href="#how-do-i-add-a-new-table" class="hash-link" aria-label="Direct link to How do I add a new table?" title="Direct link to How do I add a new table?" translate="no">​</a></h3>
<p>You can simply add the table definition to your module and republish. SpacetimeDB creates new tables automatically during publish.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-do-i-add-or-remove-indexes">How do I add or remove indexes?<a href="#how-do-i-add-or-remove-indexes" class="hash-link" aria-label="Direct link to How do I add or remove indexes?" title="Direct link to How do I add or remove indexes?" translate="no">​</a></h3>
<p>You can add or remove indexes by updating the table definition and republishing. Note that removing an index may break client subscription queries that depend on it.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="deployment--operations">Deployment & Operations<a href="#deployment--operations" class="hash-link" aria-label="Direct link to Deployment & Operations" title="Direct link to Deployment & Operations" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-do-i-deploy-to-production">How do I deploy to production?<a href="#how-do-i-deploy-to-production" class="hash-link" aria-label="Direct link to How do I deploy to production?" title="Direct link to How do I deploy to production?" translate="no">​</a></h3>
<p>You can deploy to <a href="https://spacetimedb.com/pricing" target="_blank" rel="noopener noreferrer" class="">SpacetimeDB Maincloud</a>, our fully managed serverless platform:</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> publish</span><span style="color:#F1FA8C"> my-app</span><span style="color:#BD93F9"> --server</span><span style="color:#F1FA8C"> maincloud</span></span></code></pre>
<p>Maincloud handles infrastructure, scaling, replication, and backups. It scales to zero when idle, so you only pay for what you use. There is a free tier with 2,500 TeV of energy credit per month, a Pro tier at $25/month with 100,000 TeV, and Team and Enterprise tiers for larger workloads. See the <a href="https://spacetimedb.com/pricing" target="_blank" rel="noopener noreferrer" class="">pricing page</a> for full details.</p>
<p>You can also self-host SpacetimeDB and publish to your own server.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="can-i-update-my-module-without-downtime">Can I update my module without downtime?<a href="#can-i-update-my-module-without-downtime" class="hash-link" aria-label="Direct link to Can I update my module without downtime?" title="Direct link to Can I update my module without downtime?" translate="no">​</a></h3>
<p>Yes. When you <code>spacetime publish</code> an update, SpacetimeDB hot-swaps the module code. Connected clients are not disconnected. They seamlessly continue with the new logic. This is possible because all state lives in tables, not in the server process.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-do-i-clear-my-database">How do I clear my database?<a href="#how-do-i-clear-my-database" class="hash-link" aria-label="Direct link to How do I clear my database?" title="Direct link to How do I clear my database?" translate="no">​</a></h3>
<p>Use the <code>-c</code> (or <code>--delete-data</code>) flag when publishing:</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> publish</span><span style="color:#F1FA8C"> my-app</span><span style="color:#BD93F9"> -c</span></span></code></pre>
<p>This deletes all data and re-runs the <code>init</code> reducer.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="is-there-a-size-limit-for-databases">Is there a size limit for databases?<a href="#is-there-a-size-limit-for-databases" class="hash-link" aria-label="Direct link to Is there a size limit for databases?" title="Direct link to Is there a size limit for databases?" translate="no">​</a></h3>
<p>SpacetimeDB holds all data in memory, so the practical limit is the available RAM on the host. On Maincloud, resource limits depend on your plan. For self-hosted deployments, you control the hardware.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-do-i-build-a-room-based-or-match-based-game">How do I build a room-based or match-based game?<a href="#how-do-i-build-a-room-based-or-match-based-game" class="hash-link" aria-label="Direct link to How do I build a room-based or match-based game?" title="Direct link to How do I build a room-based or match-based game?" translate="no">​</a></h3>
<p>SpacetimeDB databases are lightweight and fast to create. The recommended pattern is to use an external orchestration service that creates and destroys SpacetimeDB databases for each room or match. Each database runs an independent instance of your module with its own state.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="troubleshooting">Troubleshooting<a href="#troubleshooting" class="hash-link" aria-label="Direct link to Troubleshooting" title="Direct link to Troubleshooting" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="im-getting-a-401403-when-publishing-what-is-wrong">I&#x27;m getting a 401/403 when publishing. What is wrong?<a href="#im-getting-a-401403-when-publishing-what-is-wrong" class="hash-link" aria-label="Direct link to I&#x27;m getting a 401/403 when publishing. What is wrong?" title="Direct link to I&#x27;m getting a 401/403 when publishing. What is wrong?" translate="no">​</a></h3>
<p>Database names are global on Maincloud. If someone else already published a database with that name, you will get an authorization error. Try a more unique name.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="my-spacetime-generate-command-gives-a-confusing-error">My <code>spacetime generate</code> command gives a confusing error<a href="#my-spacetime-generate-command-gives-a-confusing-error" class="hash-link" aria-label="Direct link to my-spacetime-generate-command-gives-a-confusing-error" title="Direct link to my-spacetime-generate-command-gives-a-confusing-error" translate="no">​</a></h3>
<p>If your module&#x27;s <code>init</code> reducer panics (for example, due to a unique constraint violation on re-publish), <code>spacetime generate</code> may show an unhelpful error like "EOF while parsing a value at line 1 column 0". Fix the runtime error in your module first, then generate again.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-do-i-reset-my-database-during-development">How do I reset my database during development?<a href="#how-do-i-reset-my-database-during-development" class="hash-link" aria-label="Direct link to How do I reset my database during development?" title="Direct link to How do I reset my database during development?" translate="no">​</a></h3>
<p>Use <code>spacetime publish my-app --delete-data</code> to clear all data and republish. Or use <code>spacetime dev</code>, which handles this automatically with the <code>--delete-data=on-conflict</code> flag.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="i-got-a-weird-error-when-compiling-my-module">I got a weird error when compiling my module!<a href="#i-got-a-weird-error-when-compiling-my-module" class="hash-link" aria-label="Direct link to I got a weird error when compiling my module!" title="Direct link to I got a weird error when compiling my module!" translate="no">​</a></h3>
<p>Make sure you are using the same version of the SpacetimeDB module library (e.g., <code>spacetimedb</code> Rust crate, <code>spacetimedb</code> npm package, or <code>SpacetimeDB.ClientSDK</code> NuGet package) as the version of the SpacetimeDB host you are publishing to. Version mismatches between the module library and the host are a common source of confusing compilation or publish errors.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="i-got-a-weird-error-when-compiling-my-client">I got a weird error when compiling my client!<a href="#i-got-a-weird-error-when-compiling-my-client" class="hash-link" aria-label="Direct link to I got a weird error when compiling my client!" title="Direct link to I got a weird error when compiling my client!" translate="no">​</a></h3>
<p>Make sure the version of the client SDK you are using matches the version of <code>spacetime generate</code> that produced your bindings. If you recently updated SpacetimeDB, re-run <code>spacetime generate</code> to regenerate your bindings, and update your client SDK to the matching version.</p></div><footer class="theme-doc-footer
