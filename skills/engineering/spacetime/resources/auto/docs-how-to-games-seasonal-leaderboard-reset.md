<p>In this guide, you&#x27;ll split a top 100 leaderboard into seasons that last 4 weeks each. When a season ends, its 3 best players go into a hall of fame, and the leaderboard starts over. You&#x27;ll use a <a class="" href="/docs/tables/schedule-tables">schedule table</a> to end each season on time, and give each score the season it was set in, so that ending a season doesn&#x27;t delete anything.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-it-works">How it works<a href="#how-it-works" class="hash-link" aria-label="Direct link to How it works" title="Direct link to How it works" translate="no">​</a></h2>
\<ul\>
<li class="">A private <code>player_score</code> table stores each player&#x27;s best score, and the season it was set in.</li>
<li class="">A private <code>season</code> table holds the current season&#x27;s number and when it ends.</li>
<li class="">When the season ends, a schedule table calls the <code>end_season</code> reducer. It records the season&#x27;s 3 best players in a <code>season_winner</code> table, then starts the next season.</li>
<li class="">The <code>top_100</code> view only reads the current season&#x27;s scores, so the leaderboard starts empty each season.</li>
<li class="">Clients subscribe to three anonymous views: <code>top_100</code>, <code>current_season</code> and <code>hall_of_fame</code>.</li>
</ul>
<p>Ending a season never deletes a score. Deleting every score at the end of a season would touch every player&#x27;s row in a single transaction, which takes longer the more players you have. Moving to the next season only changes one row, however many players you have. A player&#x27;s score from an earlier season is replaced the next time they submit a score.</p>

<li class=""><code>season</code> has a single row, with <code>id</code> 0, that holds the current season&#x27;s number and when it ends.</li>
<li class=""><code>season_timer</code> is the schedule table that ends the season.</li>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="end-a-season">End a season<a href="#end-a-season" class="hash-link" aria-label="Direct link to End a season" title="Direct link to End a season" translate="no">​</a></h2>
<p>Add the <code>end_season</code> reducer, which SpacetimeDB calls when the season&#x27;s timer fires. It does two things:</p>
\<ol\>
<li class=""><strong>It records the season&#x27;s best players.</strong> It reads the season&#x27;s scores through the <code>season</code> index, sorts them from highest to lowest, and copies the first 3 into <code>season_winner</code>. Always sort the rows yourself rather than relying on the order of the index: the rows written by the current transaction can come out of the index before all the others.</li>
<li class=""><strong>It starts the next season.</strong> It increments the season number, and schedules the next end one season after the previous end, rather than one season after now. A timer can fire a few milliseconds late, and counting from now would make each season start a little later than the last.</li>
</ol>
<p><code>end_season</code> reads all of the season&#x27;s scores, but only once per season. Clients can&#x27;t call it: scheduled reducers are private, so only the scheduler, the database owner and team collaborators can run them.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="define-the-views">Define the views<a href="#define-the-views" class="hash-link" aria-label="Direct link to Define the views" title="Direct link to Define the views" translate="no">​</a></h2>
<p>Add three public anonymous views. They return the same rows to every player, so SpacetimeDB computes each one once and shares it with every subscribed client.</p>
\<ul\>
<li class=""><code>top_100</code> reads the current season&#x27;s scores through the <code>season</code> index, sorts them from highest to lowest, and returns the first 100. Like <code>end_season</code>, it sorts the rows itself rather than relying on the order of the index.</li>
<li class=""><code>current_season</code> returns the <code>season</code> row, so clients can show when the season ends.</li>
<li class=""><code>hall_of_fame</code> returns every row of <code>season_winner</code>.</li>
</ul>
<p><code>current_season</code> and <code>hall_of_fame</code> return their whole table, so they return a query instead of rows: SpacetimeDB keeps them up to date the same way as a subscription query. Returning a whole table through a view keeps the table private, so you can still change what clients see later, for example to only show the last few seasons.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="whats-next">What&#x27;s next?<a href="#whats-next" class="hash-link" aria-label="Direct link to What&#x27;s next?" title="Direct link to What&#x27;s next?" translate="no">​</a></h2>
<p>You now have a leaderboard that starts over every 4 weeks, and remembers each season&#x27;s best players:</p>
\<ul\>
<li class="">Each score records the season it was set in, and the views only read the current season&#x27;s scores.</li>
<li class="">A one-shot timer ends each season, records its 3 best players, and schedules the end of the next season.</li>
<li class="">Ending a season never deletes a score, so it takes the same time however many players you have.</li>
</ul>
<p>To adapt it to your game:</p>
\<ul\>
<li class=""><strong>Give out rewards.</strong> <code>end_season</code> already knows the season&#x27;s best players: grant their rewards in the same reducer, for example by inserting rows into a table of badges.</li>
<li class=""><strong>End seasons on calendar dates.</strong> To end each season on the first day of the month, compute the next end date in <code>end_season</code> instead of adding a fixed length. In a TypeScript module, the <a href="https://spacetimedb.com/submodules/cron" target="_blank" rel="noopener noreferrer" class="">Cron submodule</a>, a package you add to your module, can run <code>end_season</code> on a calendar schedule instead, in the time zone you choose.</li>
<li class=""><strong>Clean up old scores.</strong> Rows from players who stopped playing stay in <code>player_score</code>. If that matters, delete the rows of old seasons from another scheduled reducer, a few at a time.</li>
<li class=""><strong>Reset ratings too.</strong> If you use <a class="" href="/docs/how-to/games/skill-based-matchmaking">skill-based matchmaking</a>, you can also reset players&#x27; ratings in <code>end_season</code>, so that everyone starts the new season on equal terms.</li>
</ul>
