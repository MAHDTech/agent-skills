<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="credentials">Credentials<a href="#credentials" class="hash-link" aria-label="Direct link to Credentials" title="Direct link to Credentials" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="cli-login-not-accepted-by-server">CLI login not accepted by server<a href="#cli-login-not-accepted-by-server" class="hash-link" aria-label="Direct link to CLI login not accepted by server" title="Direct link to CLI login not accepted by server" translate="no">​</a></h3>
<p>If your CLI operations fail with the error <code>Invalid Token: InvalidSignature</code>, it&#x27;s likely because you logged in with <code>--server-issued-login</code> from a different SpacetimeDB server. It&#x27;s also possible your server&#x27;s signing keys have changed, most likely due to the server having been reset.</p>
<p>Log out to remove the invalid token, then log in again. Logging in with GitHub or Google will prevent this happening again, as those identities are portable and valid with any SpacetimeDB server, including Maincloud.</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> logout</span></span>
<span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> login</span></span></code></pre>
<div class="theme-admonition theme-admonition-danger admonition_Ph9R alert alert--danger"><div class="admonitionHeading_kG9t"><span class="admonitionIcon_VA_f"><svg viewBox="0 0 12 16"><path fill-rule="evenodd" d="M5.05.31c.81 2.17.41 3.38-.52 4.31C3.55 5.67 1.98 6.45.9 7.98c-1.45 2.05-1.7 6.53 3.53 7.7-2.2-1.16-2.67-4.52-.3-6.61-.61 2.03.53 3.33 1.94 2.86 1.39-.47 2.3.53 2.27 1.67-.02.78-.31 1.44-1.13 1.81 3.42-.59 4.78-3.42 4.78-5.56 0-2.84-2.53-3.22-1.25-5.61-1.52.13-2.03 1.13-1.89 2.75.09 1.08-1.02 1.8-1.86 1.33-.67-.41-.66-1.19-.06-1.78C8.18 5.31 8.68 2.45 5.05.32L5.03.3l.02.01z"></path></svg></span>danger</div><div class="admonitionContent_STxx"><p><code>spacetime logout</code> will discard your previous server-issued token, resulting in you no longer being able to manage any databases you previously published owned by that identity. If you still need access to the server-issued token, view it with <code>spacetime login show --token</code> and save it. You can then log back in with that token using <code>spacetime login --token</code>.</p></div></div>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="lost-access-to-a-local-database-after-spacetime-login">Lost access to a local database after <code>spacetime login</code><a href="#lost-access-to-a-local-database-after-spacetime-login" class="hash-link" aria-label="Direct link to lost-access-to-a-local-database-after-spacetime-login" title="Direct link to lost-access-to-a-local-database-after-spacetime-login" translate="no">​</a></h3>
<p>If commands like <code>spacetime publish</code>, <code>spacetime call</code> or <code>spacetime delete</code> stop working for a local database after you ran <code>spacetime login</code>, the database is probably owned by a server-issued identity that the login replaced.</p>
<p>This happens when you publish to a local server before logging in. If the CLI has no token and doesn&#x27;t log you in with spacetimedb.com (for example because you passed <code>-y</code>), it logs in directly to the local server instead and prints:</p>
<div class="language-text codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><div class="codeBlockContent_VOyQ"><pre tabindex="0" class="prism-code language-text codeBlock_evfK thin-scrollbar" style="color:#bfc7d5;background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="token-line" style="color:#bfc7d5"><span class="token plain">We have logged in directly to your target server.</span><br></span><span class="token-line" style="color:#bfc7d5"><span class="token plain">WARNING: This login will NOT work for any other servers.</span><br></span></code></pre></div></div>
<p>The database you publish is then owned by that server-issued identity. The CLI keeps only one login. A later <code>spacetime login</code> discards the server-issued token as soon as it starts, without asking and before you finish logging in, and the new identity isn&#x27;t the database&#x27;s owner.</p>
<p>To avoid this, run <code>spacetime login</code> before you publish anything. A GitHub or Google login works with any SpacetimeDB server, including your local one and Maincloud, so one login can own your local and Maincloud databases.</p>
<p>If you have already published with a server-issued identity and want to switch to your spacetimedb.com login:</p>
\<ol\>
<li class="">Save the server-issued token: <code>spacetime login show --token</code>.</li>
<li class="">Run <code>spacetime login</code>.</li>
<li class="">To manage the old database, log back in with the saved token (<code>spacetime login --token \<token\></code>), or delete the database while logged in with it and publish it again with your spacetimedb.com login. Deleting a database deletes its data.</li>
</ol>
<p>If the server-issued token is already gone, it can&#x27;t be recovered. Publish the module again under a new database name.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="client-connection-rejected">Client connection rejected<a href="#client-connection-rejected" class="hash-link" aria-label="Direct link to Client connection rejected" title="Direct link to Client connection rejected" translate="no">​</a></h3>
<p>If SpacetimeDB rejects connections from your application&#x27;s client, it&#x27;s most likely because you&#x27;re supplying a token that was issued by a different SpacetimeDB server, or has expired. Clear the invalid token:</p>
<table><thead><tr><th>Client SDK</th><th>How to clear</th></tr></thead>\<tbody\><tr><td>Rust (native)</td><td>Delete the credentials file for your application from within <code>~/.spacetimedb_client_credentials</code>. Check where you construct the <code>spacetimedb_sdk::credentials::File</code> to find which file to delete.</td></tr><tr><td>C# (native)</td><td>Delete the <code>auth_token=</code> line from your app&#x27;s saved settings, by default located in <code>~/.spacetime_csharp_sdk/settings.ini</code>. Check your call to <code>AuthToken.Init</code> to find the directory and/or file name.</td></tr><tr><td>TypeScript, Rust or C# (browser)</td><td>Clear cookies.</td></tr><tr><td>Unity</td><td>Clear PlayerPrefs by selecting <strong>Edit -> Clear All PlayerPrefs</strong></td></tr><tr><td>Unreal</td><td>Delete the file <code>Saved/Config/WindowsEditor/GameUserSettings.ini</code> in your Unreal project.</td></tr></tbody></table>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="in-modules">In Modules<a href="#in-modules" class="hash-link" aria-label="Direct link to In Modules" title="Direct link to In Modules" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="identity-seen-by-reducers-never-changes">Identity seen by reducers never changes<a href="#identity-seen-by-reducers-never-changes" class="hash-link" aria-label="Direct link to Identity seen by reducers never changes" title="Direct link to Identity seen by reducers never changes" translate="no">​</a></h3>
<p>In module code, <code>ctx.identity()</code> (or <code>Ctx.Identity()</code>) reads the identity of the database, not of the connected client. Call <code>ctx.sender()</code>/<code>Ctx.Sender()</code> instead to read the identity of the client which requested the current function call.</p>
<p>As of SpacetimeDB 2.3.0, the <code>identity</code> method is a  deprecated alias for <code>ctx.database_identity()</code>/<code>ctx.databaseIdentity()</code>/<code>Ctx.DatabaseIdentity()</code>.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="code-changes-not-taking-effect">Code changes not taking effect<a href="#code-changes-not-taking-effect" class="hash-link" aria-label="Direct link to Code changes not taking effect" title="Direct link to Code changes not taking effect" translate="no">​</a></h3>
<p>If you&#x27;ve made changes to your module code that aren&#x27;t taking effect, you likely need to publish the new version of the code to the database. Use the <code>spacetime publish</code> CLI command, or run <code>spacetime dev</code>, which will watch your project and automatically call <code>spacetime publish</code> whenever you make changes.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="in-clients">In Clients<a href="#in-clients" class="hash-link" aria-label="Direct link to In Clients" title="Direct link to In Clients" translate="no">​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="connection-completely-unresponsive">Connection completely unresponsive<a href="#connection-completely-unresponsive" class="hash-link" aria-label="Direct link to Connection completely unresponsive" title="Direct link to Connection completely unresponsive" translate="no">​</a></h3>
<p>If your <code>DbConnection</code> is completely unresponsive, with function calls never receiving responses and subscriptions never being applied, you may have one of several issues:</p>
<h4 class="anchor anchorTargetStickyNavbar_Y_NL" id="connection-rejected">Connection rejected<a href="#connection-rejected" class="hash-link" aria-label="Direct link to Connection rejected" title="Direct link to Connection rejected" translate="no">​</a></h4>
<p>Your client may have failed to connect to the remote server, or may have been disconnected soon after starting. Make sure you register <code>on_connect_error</code>/<code>onConnectError</code>/<code>OnConnectError</code> and <code>on_disconnect</code>/<code>onDisconnect</code>/<code>OnDisconnect</code> callbacks when building your <code>DbConnection</code>, and check if they&#x27;re being invoked with errors.</p>
<h4 class="anchor anchorTargetStickyNavbar_Y_NL" id="connection-not-advancing">Connection not advancing<a href="#connection-not-advancing" class="hash-link" aria-label="Direct link to Connection not advancing" title="Direct link to Connection not advancing" translate="no">​</a></h4>
<p>You may need to advance your connection by calling one of the following methods:</p>
<table><thead><tr><th>Client SDK</th><th>Method</th><th>Description</th></tr></thead>\<tbody\><tr><td>Rust (native only)</td><td><code>conn.run_threaded()</code></td><td>Spawn a thread to continuously advance the connection.</td></tr><tr><td>Rust (browser only)</td><td><code>conn.run_background_task()</code></td><td>Spawn a task to continuously advance the connection.</td></tr><tr><td>Rust</td><td><code>conn.run_async()</code></td><td>A <code>Future</code> which you can <code>await</code> or poll to advance the connection.</td></tr><tr><td>Rust</td><td><code>conn.frame_tick()</code></td><td>In single-threaded games, call this every frame to advance the connection.</td></tr><tr><td>C#</td><td><code>Conn.FrameTick()</code></td><td>In native C# clients, call this from your game or application update loop. If you use a separate loop, keep <code>Conn.Db</code> access on that same thread or synchronize access.</td></tr><tr><td>Unity</td><td><code>SpacetimeDBNetworkManager</code> or <code>Conn.FrameTick()</code></td><td>The Unity package can advance connections automatically when a single <code>SpacetimeDBNetworkManager</code> component is present in the scene. If you manage the loop yourself, call <code>FrameTick()</code> every frame.</td></tr><tr><td>Unreal</td><td><code>Conn->FrameTick()</code> or <code>Conn->SetAutoTicking(true)</code></td><td>Call <code>FrameTick()</code> every frame, or enable auto-ticking once after building the connection.</td></tr><tr><td>TypeScript</td><td>N/a</td><td>The TypeScript client SDK advances connections automatically.</td></tr></tbody></table>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="rows-never-appear">Rows never appear<a href="#rows-never-appear" class="hash-link" aria-label="Direct link to Rows never appear" title="Direct link to Rows never appear" translate="no">​</a></h3>
<p>If rows from a table or view never appear and row callbacks are never invoked, you may need to add a subscription, or a subscription may have failed.</p>
<h4 class="anchor anchorTargetStickyNavbar_Y_NL" id="add-a-subscription">Add a subscription<a href="#add-a-subscription" class="hash-link" aria-label="Direct link to Add a subscription" title="Direct link to Add a subscription" translate="no">​</a></h4>
<p>In order for rows to be visible to a client, you must subscribe to a table or view. See <a class="" href="/docs/clients/subscriptions">Subscriptions</a>.</p>
<h4 class="anchor anchorTargetStickyNavbar_Y_NL" id="check-for-subscription-errors">Check for subscription errors<a href="#check-for-subscription-errors" class="hash-link" aria-label="Direct link to Check for subscription errors" title="Direct link to Check for subscription errors" translate="no">​</a></h4>
<p>If you&#x27;ve subscribed to a subscription but never see any rows, your subscription may have failed. Ensure you&#x27;re registering an <code>on_error</code>/<code>onError</code>/<code>OnError</code> callback with the subscription builder, and check if it is invoked.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="insert-update-or-delete-callback-not-invoked-when-row-changes">Insert, update or delete callback not invoked when row changes<a href="#insert-update-or-delete-callback-not-invoked-when-row-changes" class="hash-link" aria-label="Direct link to Insert, update or delete callback not invoked when row changes" title="Direct link to Insert, update or delete callback not invoked when row changes" translate="no">​</a></h3>
<p>For a table or view with a primary key, a row change may be routed to either the on-insert, on-update or on-delete callback. Each change will only cause one of these callbacks to be invoked, so make sure you&#x27;ve registered all three of them.</p>
<div class="theme-admonition theme-admonition-note admonition_Ph9R alert alert--secondary"><div class="admonitionHeading_kG9t"><span class="admonitionIcon_VA_f"><svg viewBox="0 0 14 16"><path fill-rule="evenodd" d="M6.3 5.69a.942.942 0 0 1-.28-.7c0-.28.09-.52.28-.7.19-.18.42-.28.7-.28.28 0 .52.09.7.28.18.19.28.42.28.7 0 .28-.09.52-.28.7a1 1 0 0 1-.7.3c-.28 0-.52-.11-.7-.3zM8 7.99c-.02-.25-.11-.48-.31-.69-.2-.19-.42-.3-.69-.31H6c-.27.02-.48.13-.69.31-.2.2-.3.44-.31.69h1v3c.02.27.11.5.31.69.2.2.42.31.69.31h1c.27 0 .48-.11.69-.31.2-.19.3-.42.31-.69H8V7.98v.01zM7 2.3c-3.14 0-5.7 2.54-5.7 5.68 0 3.14 2.56 5.7 5.7 5.7s5.7-2.55 5.7-5.7c0-3.15-2.56-5.69-5.7-5.69v.01zM7 .98c3.86 0 7 3.14 7 7s-3.14 7-7 7-7-3.12-7-7 3.14-7 7-7z"></path></svg></span>note</div><div class="admonitionContent_STxx"><p>Insert, update and delete callbacks on the client don&#x27;t always correspond 1-to-1 with calls to those methods in the module code.</p><p>The client may see an update event when you call delete followed by insert within the same reducer or transaction.</p><p>The client may see an insert or a delete event when you call update but either the old or new version of the row doesn&#x27;t match the client&#x27;s subscriptions.</p></div></div>
<p>For tables without primary keys, only the on-insert and on-delete callbacks will ever be invoked.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="row-seen-by-update-callback-is-out-of-date">Row seen by update callback is out of date<a href="#row-seen-by-update-callback-is-out-of-date" class="hash-link" aria-label="Direct link to Row seen by update callback is out of date" title="Direct link to Row seen by update callback is out of date" translate="no">​</a></h3>
<p>If it appears that an on-update callback is observing an old version of a row, you may have mixed up the parameters to that callback. Update callbacks take three parameter: an <code>EventContext</code> for interacting with the connection, the old version of the row, and the new version of the row. Make sure the function you register to the callback has 3 arguments:<code>(ctx, old, new)</code>.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="serialization-errors">Serialization errors<a href="#serialization-errors" class="hash-link" aria-label="Direct link to Serialization errors" title="Direct link to Serialization errors" translate="no">​</a></h3>
<p>If you see errors related to serialization, including unexpected EOFs, incorrect lengths or unrecognized tags, it&#x27;s likely your generated <code>module_bindings</code> are out of date. Re-run <code>spacetime generate</code> to update them, or use <code>spacetime dev</code>, which will watch your module code and automatically call <code>spacetime generate</code> whenever you make changes.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="reducers-procedures-views-not-visible-to-client">Reducers, procedures, views not visible to client<a href="#reducers-procedures-views-not-visible-to-client" class="hash-link" aria-label="Direct link to Reducers, procedures, views not visible to client" title="Direct link to Reducers, procedures, views not visible to client" translate="no">​</a></h3>
<p>Scheduled reducers or procedures won&#x27;t show up in client codegen. That&#x27;s expected; clients can&#x27;t directly invoke them.</p>
<p>If functions that aren&#x27;t scheduled aren&#x27;t showing up, or views aren&#x27;t visible, it&#x27;s likely your generated <code>module_bindings</code> are out of date. Re-run <code>spacetime generate</code> to update them, or use <code>spacetime dev</code>, which will watch your module code and automatically call <code>spacetime generate</code> whenever you make changes.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="tables-not-visible-to-client">Tables not visible to client<a href="#tables-not-visible-to-client" class="hash-link" aria-label="Direct link to Tables not visible to client" title="Direct link to Tables not visible to client" translate="no">​</a></h3>
<p>If a table isn&#x27;t visible in client codegen, and you&#x27;ve already run <code>spacetime generate</code> or are using <code>spacetime dev</code>, the table may be private. Only tables marked public will be visible to clients and are available for subscriptions. See <a class="" href="/docs/tables#defining-tables">Defining Tables</a> for how to mark a table public.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="compilation-or-type-errors-in-generated-module_bindings">Compilation or type errors in generated <code>module_bindings</code><a href="#compilation-or-type-errors-in-generated-module_bindings" class="hash-link" aria-label="Direct link to compilation-or-type-errors-in-generated-module_bindings" title="Direct link to compilation-or-type-errors-in-generated-module_bindings" translate="no">​</a></h3>
<p>If you see errors when compiling or type checking your autogenerated <code>module_bindings</code>, it&#x27;s likely that your SpacetimeDB CLI version doesn&#x27;t match the client SDK you&#x27;re using in your client project.</p>
<p>Ensure that your CLI is up to date by running <code>spacetime version upgrade</code>, then check your version with <code>spacetime --version</code>.</p>
