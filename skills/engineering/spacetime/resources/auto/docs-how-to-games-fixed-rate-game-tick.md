<p>In this guide, you&#x27;ll run your game&#x27;s server logic at a fixed rate: a reducer that SpacetimeDB calls 20 times per second, which moves every entity in the world. You&#x27;ll use a <a class="" href="/docs/tables/schedule-tables">schedule table</a> to call the reducer and the <code>init</code> <a class="" href="/docs/functions/reducers/lifecycle">lifecycle reducer</a> to start it.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-it-works">How it works<a href="#how-it-works" class="hash-link" aria-label="Direct link to How it works" title="Direct link to How it works" translate="no">​</a></h2>
\<ul\>
<li class="">A <code>tick_timer</code> schedule table holds one row that tells SpacetimeDB to call the <code>tick</code> reducer every 50 milliseconds.</li>
<li class="">The <code>init</code> reducer inserts that row when the database is created.</li>
<li class="">The <code>tick</code> reducer measures how much time has passed since the last tick, then moves each entity by its velocity.</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="define-the-tables">Define the tables<a href="#define-the-tables" class="hash-link" aria-label="Direct link to Define the tables" title="Direct link to Define the tables" translate="no">​</a></h2>
<p>Add three tables:</p>
\<ul\>
<li class=""><code>tick_timer</code> is the schedule table. Its <code>scheduled_at</code> column says when to call <code>tick</code>.</li>
<li class=""><code>tick_state</code> is a private table with a single row that stores when the last tick ran.</li>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="write-the-tick-reducer">Write the tick reducer<a href="#write-the-tick-reducer" class="hash-link" aria-label="Direct link to Write the tick reducer" title="Direct link to Write the tick reducer" translate="no">​</a></h2>
<p>The <code>tick</code> reducer does two things:</p>
\<ol\>
<li class=""><strong>It measures the time since the last tick</strong>, rather than assuming exactly 50 milliseconds. This is standard practice for game loops: the time between two ticks varies slightly, and moving by the measured time keeps every entity at a steady speed.</li>
<li class=""><strong>It moves each entity</strong> by its velocity multiplied by that time. This is where your game logic goes.</li>
</ol>
<p>Clients can&#x27;t call <code>tick</code> themselves: scheduled reducers are private, so only the scheduler, the database owner and team collaborators can run them.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="keep-the-tick-fast">Keep the tick fast<a href="#keep-the-tick-fast" class="hash-link" aria-label="Direct link to Keep the tick fast" title="Direct link to Keep the tick fast" translate="no">​</a></h2>
\<ul\>
<li class=""><strong>Finish well within the interval.</strong> A tick that takes longer than 50 milliseconds delays everything else in the database, and the ticks it overlaps are skipped. Keep expensive work, like pathfinding or AI decisions, out of the tick, or spread it across several ticks.</li>
<li class=""><strong>Only write what changed.</strong> Every update to a public table is sent to the clients subscribed to it, so a tick that rewrites every row sends every row to every client 20 times per second. Skipping entities that aren&#x27;t moving, as the reducer above does, avoids that. To also limit which entities each client receives, see <a class="" href="/docs/how-to/games/sync-nearby-entities">Only sync what&#x27;s near the player</a>.</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="whats-next">What&#x27;s next?<a href="#whats-next" class="hash-link" aria-label="Direct link to What&#x27;s next?" title="Direct link to What&#x27;s next?" translate="no">​</a></h2>
<p>You now have server logic that runs 20 times per second:</p>
\<ul\>
<li class="">A schedule table calls the <code>tick</code> reducer at a fixed interval, starting from <code>init</code>.</li>
<li class="">The reducer moves entities by the measured time since the last tick, so they move at a steady speed.</li>
<li class="">Deleting the timer row stops the tick.</li>
</ul>
<p>To learn more about the features used here, see <a class="" href="/docs/tables/schedule-tables">Schedule Tables</a> and <a class="" href="/docs/functions/reducers/lifecycle">Lifecycle Reducers</a>.</p>
