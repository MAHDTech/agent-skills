class="admonitionContent_STxx"><p>You need a module and a client connected to it, <a href="https://nodejs.org/" target="_blank" rel="noopener noreferrer" class="">Node.js</a> to run the sidecar, and an API key from the provider of the AI model you want to use. <p>In this guide, you&#x27;ll let players ask an AI model for a reply, and have a sidecar answer them. A sidecar is a separate program that runs next to your database: it connects to it like any client, picks up the requests players make, calls the model, and writes the replies back.</p>
<p>Compared with <a class="" href="/docs/how-to/app-patterns/call-ai-model">calling the model from your module</a>, a sidecar can use your provider&#x27;s official SDK, stream replies, wait as long as a reply takes, and keep your API key out of the database. The module only stores requests and replies, so the same pattern works for any slow or external work, not just AI.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-it-works">How it works<a href="#how-it-works" class="hash-link" aria-label="Direct link to How it works" title="Direct link to How it works" translate="no">​</a></h2>
\<ul\>
<li class="">An <code>ai_request</code> table holds every request: who asked, the prompt, and the reply or error once it&#x27;s done.</li>
<li class="">Players call a <code>request_ai_reply</code> reducer to add a request, and read their own requests through a <code>my_ai_requests</code> view.</li>
<li class="">The sidecar subscribes to a <code>pending_ai_requests</code> view, calls the model for each request, then calls a <code>complete_ai_request</code> reducer with the reply.</li>
<li class="">An <code>ai_worker</code> table lists the identities allowed to read the queue and complete requests, so only your sidecar can answer.</li>
</ul>

<p>Create <code>src/sidecar.ts</code>. The sidecar connects to your database, saves its token so it keeps the same identity when it restarts, and subscribes to <code>pending_ai_requests</code>. For each pending request, it calls the model and then <code>complete_ai_request</code>. If the model call fails, it completes the request with an error instead, so the player isn&#x27;t left waiting.</p>

<p>The first time it runs, the sidecar prints its identity, for example <code>Sidecar connected as c200…</code>. Add that identity to <code>ai_worker</code> with SQL, prefixed with <code>0x</code>. Only the database owner and collaborators can write to a table this way:</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> sql</span><span style="color:#F1FA8C"> my-game</span><span style="color:#E9F284"> "</span><span style="color:#F1FA8C">INSERT INTO ai_worker (identity) VALUES (0x{identity})</span><span style="color:#E9F284">"</span></span></code></pre>
<p>where <em>identity</em> is the hexadecimal identity the sidecar printed. The sidecar receives the pending requests as soon as the row is added, and keeps the same identity on later runs because it reuses the token it saved in <code>sidecar-token.txt</code>. Keep that file private: anyone with the token can act as your sidecar.</p>
<p>Run a single sidecar per database. Two sidecars would both answer the same requests.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="whats-next">What&#x27;s next?<a href="#whats-next" class="hash-link" aria-label="Direct link to What&#x27;s next?" title="Direct link to What&#x27;s next?" translate="no">​</a></h2>
<p>You now have a sidecar that answers players&#x27; AI requests:</p>
\<ul\>
<li class="">Players add requests with <code>request_ai_reply</code> and read their replies through the <code>my_ai_requests</code> view.</li>
<li class="">The sidecar reads the queue through the <code>pending_ai_requests</code> view, calls the model with your provider&#x27;s SDK, and stores replies with <code>complete_ai_request</code>.</li>
<li class="">The <code>ai_worker</code> table makes sure only your sidecar can read the queue and answer requests, and your API key stays with the sidecar.</li>
</ul>
