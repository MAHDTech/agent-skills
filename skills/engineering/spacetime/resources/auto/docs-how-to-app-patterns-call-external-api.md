class="admonitionContent_STxx"><p>You need a module and a client connected to it. If you don&#x27;t have them yet, follow the <a class="" href="/docs/">quickstart</a> for your language first. This guide uses <a href="https://open-meteo.com" target="_blank" rel="noopener noreferrer" class="">Open-Meteo</a>, a weather API you can call without an API key. <p>In this guide, you&#x27;ll show live weather in your game world, from a weather API. Your module fetches the weather on a schedule and stores it in a public table, so every client gets it through a subscription, and you make one request per refresh, however many players are connected. You&#x27;ll make the request from a <a class="" href="/docs/functions/procedures">procedure</a>, call it with a <a class="" href="/docs/tables/schedule-tables">schedule table</a>, and start it from the <code>init</code> <a class="" href="/docs/functions/reducers/lifecycle">lifecycle reducer</a>.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-it-works">How it works<a href="#how-it-works" class="hash-link" aria-label="Direct link to How it works" title="Direct link to How it works" translate="no">​</a></h2>
\<ul\>
<li class="">A public <code>weather</code> table has a single row with the latest weather: the temperature, a weather code, and when it was fetched.</li>
<li class="">A private <code>weather_refresh</code> schedule table calls the <code>refresh_weather</code> procedure every 15 minutes. The <code>init</code> reducer inserts its rows when the database is created.</li>
<li class=""><code>refresh_weather</code> fetches the current weather from the API, then stores it in <code>weather</code>.</li>
<li class="">If the request fails, <code>weather</code> keeps the last weather, and the next refresh tries again.</li>
<li class="">Clients subscribe to <code>weather</code>, and update what they show when it changes.</li>
</ul>
<p>The request is made from a procedure, not a reducer. Reducers can&#x27;t make HTTP requests, because they run inside a transaction. A procedure makes the request outside of any transaction, then stores the result in a short one.</p>

\<ul\>

<li class=""><code>weather_refresh</code> is the schedule table. Its <code>scheduled_at</code> column says when to call <code>refresh_weather</code>.</li>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="start-the-refresh">Start the refresh<a href="#start-the-refresh" class="hash-link" aria-label="Direct link to Start the refresh" title="Direct link to Start the refresh" translate="no">​</a></h2>
<p>Insert two rows into <code>weather_refresh</code> from the <code>init</code> reducer:</p>
\<ul\>
<li class="">One that calls <code>refresh_weather</code> right away, so clients get the weather as soon as you publish. SpacetimeDB deletes it once it has run.</li>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="fetch-and-store-the-weather">Fetch and store the weather<a href="#fetch-and-store-the-weather" class="hash-link" aria-label="Direct link to Fetch and store the weather" title="Direct link to Fetch and store the weather" translate="no">​</a></h2>
<p>Add a <code>fetch_weather</code> function that requests the current weather, and returns the temperature and the weather code. It&#x27;s the only code specific to Open-Meteo. It gives up on the request after 10 seconds, and fails if the status isn&#x27;t 200, or if the reply doesn&#x27;t have the values it expects.</p>
<p>Then add the <code>refresh_weather</code> procedure. SpacetimeDB calls it with each row of <code>weather_refresh</code> when the row&#x27;s time comes. It calls <code>fetch_weather</code>, then stores the result in <code>weather</code>, in a short transaction. If <code>fetch_weather</code> fails, it logs the error and returns, so <code>weather</code> keeps the last weather.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="whats-next">What&#x27;s next?<a href="#whats-next" class="hash-link" aria-label="Direct link to What&#x27;s next?" title="Direct link to What&#x27;s next?" translate="no">​</a></h2>
<p>You now bring live data from an external API into your game:</p>
\<ul\>
<li class="">A schedule table calls a procedure every 15 minutes, starting from <code>init</code>.</li>
<li class="">The procedure fetches the data outside of any transaction, and stores it in a public table that clients subscribe to.</li>
<li class="">When the API fails, the table keeps the last data, and the next refresh tries again.</li>
</ul>
<p>To adapt it to your app:</p>
\<ul\>
<li class=""><strong>APIs that need a key.</strong> Store the key in an environment variable, as in <a class="" href="/docs/how-to/app-patterns/call-ai-model#store-the-api-key">Call an AI model from your module</a>, and send it in a header.</li>
<li class=""><strong>Several locations.</strong> Give <code>weather</code> one row per location, with its latitude and longitude. Open-Meteo accepts several comma-separated coordinates in one request, and returns a list, so one request still refreshes them all.</li>
<li class=""><strong>Rate limits.</strong> Check the API&#x27;s limits, and refresh no more often than its data changes. Each refresh is one request, however many players are connected.</li>
<li class=""><strong>Refresh on demand.</strong> A reducer can&#x27;t make the request, but it can insert a row into <code>weather_refresh</code> that runs right away. Limit how often players can do it, as the <a class="" href="/docs/how-to/social/unique-usernames">usernames guide</a> does for name requests. In a TypeScript module, the <a href="https://spacetimedb.com/submodules/rate-limit" target="_blank" rel="noopener noreferrer" class="">Rate Limit submodule</a>, a package you add to your module, can do it for you.</li>
<li class=""><strong>APIs that send you data.</strong> Some APIs call your server when something changes, instead of waiting for you to ask. To receive those calls, add an <a class="" href="/docs/functions/http-handlers">HTTP handler</a> to your module.</li>
</ul>
<p>To learn more about the features used here, see <a class="" href="/docs/functions/procedures">Procedures</a>, <a class="" href="/docs/tables/schedule-tables">Schedule Tables</a> and <a class="" href="/docs/functions/reducers/lifecycle">Lifecycle Reducers</a>.</p>
