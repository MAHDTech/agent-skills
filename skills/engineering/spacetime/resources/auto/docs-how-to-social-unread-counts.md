class="admonitionContent_STxx"><p>This guide builds on <a class="" href="/docs/how-to/social/chat-rooms-and-dms">Chat rooms and private DMs</a>: it uses its tables, its <code>find_membership</code> function, its views and its client. If you haven&#x27;t built chat rooms yet, follow that guide first.</p></div></div>
<p>In this guide, you&#x27;ll show how many messages each room has that the player hasn&#x27;t read, such as "general (3)", and let them know when a new message arrives in another room. The database remembers what each player has read, so reading a room on one device clears its count on the others.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-it-works">How it works<a href="#how-it-works" class="hash-link" aria-label="Direct link to How it works" title="Direct link to How it works" translate="no">​</a></h2>
\<ul\>
<li class="">A private <code>read_marker</code> table holds the <code>id</code> of the last message each player read in each room.</li>
<li class="">A <code>mark_read</code> reducer moves the caller&#x27;s marker forward, and never back.</li>
<li class="">A <code>my_read_markers</code> view returns the caller&#x27;s markers.</li>
<li class="">Clients count each room&#x27;s unread messages from <code>my_messages</code>, which they already have: the messages that other players sent after the marker.</li>
<li class="">When the player opens a room, or a message arrives in the room they have open, the client marks the room as read.</li>
<li class="">When a message arrives in another room, the client shows a notice, such as "New message from Alice in general".</li>
</ul>
<p>Each message&#x27;s <code>id</code> is larger than the ids of the messages sent before it, so one number per room is enough: the unread messages are the ones with a larger <code>id</code>. Because the marker never moves back, a late or repeated request can&#x27;t make messages unread again.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="define-the-table-and-the-view">Define the table and the view<a href="#define-the-table-and-the-view" class="hash-link" aria-label="Direct link to Define the table and the view" title="Direct link to Define the table and the view" translate="no">​</a></h2>
<p>Add the <code>read_marker</code> table. It&#x27;s private, so players can&#x27;t read what others have read. It has an index on <code>member</code>, so the reducer and the view can find a player&#x27;s markers quickly.</p>
<p>Then add the <code>my_read_markers</code> view, which returns the caller&#x27;s markers.</p>

<p>On the client, add <code>my_read_markers</code> to the subscription of the chat rooms client: <code>tables.myReadMarkers</code> in TypeScript, <code>q => q.From.MyReadMarkers()</code> in C#, and <code>|q| q.from.my_read_markers()</code> in Rust. Then add the functions below:</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="notify-about-new-messages">Notify about new messages<a href="#notify-about-new-messages" class="hash-link" aria-label="Direct link to Notify about new messages" title="Direct link to Notify about new messages" translate="no">​</a></h2>
<p>When a message arrives in the room on screen, mark the room as read, so the player&#x27;s other devices clear it too. Wait for the marker to change before showing the counts again, or the room briefly shows 1 unread message. When a message arrives in another room, show a notice, then the counts.</p>
<p>Only notify about messages that other players just sent. Inserts into <code>my_messages</code> also happen when the client subscribes, and when the player joins a room and gets its earlier messages. The event of each insert tells them apart:</p>
\<ul\>
<li class=""><code>SubscribeApplied</code>: the client just subscribed, and is getting the rows that already exist.</li>
<li class=""><code>Reducer</code>: a reducer this client called made the change, such as <code>join_room</code> or <code>send_message</code>.</li>
<li class=""><code>Transaction</code>: another client&#x27;s reducer made the change. That&#x27;s the one to notify about.</li>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="whats-next">What&#x27;s next?<a href="#whats-next" class="hash-link" aria-label="Direct link to What&#x27;s next?" title="Direct link to What&#x27;s next?" translate="no">​</a></h2>
<p>You now show unread counts that stay in sync across the player&#x27;s devices, and notify them about new messages:</p>
\<ul\>
<li class="">A private table holds the <code>id</code> of the last message each player read in each room, and a view gives each player their own.</li>
<li class="">A reducer only moves a marker forward, and only to a message of the room.</li>
<li class="">Clients count the unread messages themselves, from the messages they already have.</li>
<li class="">Clients tell new messages from other players apart from the ones they get when they subscribe or join a room, with the event of each insert.</li>
</ul>
<p>To adapt it to your app:</p>
\<ul\>
<li class=""><strong>DMs.</strong> Add a marker for each conversation, with the other player&#x27;s identity instead of a room, and count the DMs you received after it.</li>
<li class=""><strong>Big rooms.</strong> The client counts unread messages from the messages it has, so it needs every message of every room the player is in. If you only send clients the latest messages, for example with <a class="" href="/docs/how-to/app-patterns/pagination">pagination</a>, keep an unread count in each player&#x27;s marker instead: <code>send_message</code> adds one to the count of every other member of the room, and <code>mark_read</code> sets it back to zero.</li>
<li class=""><strong>Mentions.</strong> To notify players only when someone mentions them, check the text of each message for their name before showing the notice.</li>
<li class=""><strong>Players who aren&#x27;t online.</strong> Clients only see new messages while they&#x27;re connected. To reach players who aren&#x27;t, send them an email from your module, as in <a class="" href="/docs/how-to/app-patterns/send-email">Send an email from your module</a>.</li>
</ul>
