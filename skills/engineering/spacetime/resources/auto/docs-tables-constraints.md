<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="primary-key-rules">Primary Key Rules<a href="#primary-key-rules" class="hash-link" aria-label="Direct link to Primary Key Rules" title="Direct link to Primary Key Rules" translate="no">​</a></h3>
\<ul\>
<li class=""><strong>One per table</strong>: A table can have at most one primary key column.</li>
<li class=""><strong>Immutable identity</strong>: The primary key defines the row&#x27;s identity. Changing a primary key value is treated as deleting the old row and inserting a new one.</li>
<li class=""><strong>Unique by definition</strong>: Primary keys are automatically unique. No two rows can have the same primary key value.</li>
</ul>
<p>Because of the unique constraint, SpacetimeDB implements primary keys using a <strong>unique index</strong>. This index is created automatically.</p>

<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="tables-without-primary-keys">Tables Without Primary Keys<a href="#tables-without-primary-keys" class="hash-link" aria-label="Direct link to Tables Without Primary Keys" title="Direct link to Tables Without Primary Keys" translate="no">​</a></h3>
<p>Tables don&#x27;t require a primary key. Without one, the entire row acts as the primary key:</p>
\<ul\>
<li class="">Rows are identified by their complete content</li>
<li class="">Updates require matching all fields</li>
<li class="">Duplicate rows are not possible. Inserting an identical row has no effect</li>
</ul>
<p>SpacetimeDB always maintains set semantics regardless of whether you define a primary key. The difference is what defines uniqueness: a primary key column, or the entire row.</p>
<p>Primary keys add indexing overhead. If your table is only accessed by iterating over all rows (no lookups by key), omitting the primary key can improve performance.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="common-primary-key-patterns">Common Primary Key Patterns<a href="#common-primary-key-patterns" class="hash-link" aria-label="Direct link to Common Primary Key Patterns" title="Direct link to Common Primary Key Patterns" translate="no">​</a></h3>
<p><strong>Auto-incrementing IDs</strong>: Combine <code>primaryKey()</code> with <code>autoInc()</code> for automatically assigned unique identifiers:</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#F8F8F2">#[spacetimedb</span><span style="color:#FF79C6">::</span><span style="color:#F8F8F2">table(accessor </span><span style="color:#FF79C6">=</span><span style="color:#F8F8F2"> post, public)]</span></span>

<span class="line"><span style="color:#F8F8F2">    #[primary_key]</span></span>
<span class="line"><span style="color:#F8F8F2">    #[auto_inc]</span></span>
<span class="line"><span style="color:#F8F8F2">    id</span><span style="color:#FF79C6">:</span><span style="color:#8BE9FD;font-style:italic"> u64</span><span style="color:#F8F8F2">,</span></span>

<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#F8F8F2">#[spacetimedb</span><span style="color:#FF79C6">::</span><span style="color:#F8F8F2">table(accessor </span><span style="color:#FF79C6">=</span><span style="color:#F8F8F2"> user_profile, public)]</span></span>

<span class="line"><span style="color:#F8F8F2">    bio</span><span style="color:#FF79C6">:</span><span style="color:#8BE9FD;font-style:italic"> String</span><span style="color:#F8F8F2">,</span></span>

<p>This pattern ensures each identity can only have one profile and makes lookups by identity efficient.</p>
