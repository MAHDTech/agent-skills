<p>In this guide, you&#x27;ll build a matchmaking queue: players ask to find a match, wait in a queue, and are put into a 4-player match as soon as enough players are waiting. You&#x27;ll use <a class="" href="/docs/functions/reducers">reducers</a> to join and leave the queue, the <code>client_disconnected</code> <a class="" href="/docs/functions/reducers/lifecycle">lifecycle reducer</a> to clean up after players who leave, and a per-player <a class="" href="/docs/functions/views">view</a> to tell each player about their match.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="how-it-works">How it works<a href="#how-it-works" class="hash-link" aria-label="Direct link to How it works" title="Direct link to How it works" translate="no">​</a></h2>
\<ul\>
<li class="">A private <code>queue_entry</code> table holds the players who are waiting.</li>
<li class="">A <code>join_queue</code> reducer adds the caller to the queue, then creates a match if enough players are waiting.</li>
<li class="">A <code>leave_queue</code> reducer and the <code>client_disconnected</code> reducer remove players from the queue.</li>
<li class="">Private <code>game_match</code> and <code>match_player</code> tables record each match and its players.</li>
<li class="">A public <code>my_match</code> view returns the players in the caller&#x27;s match, and nothing else.</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="define-the-tables">Define the tables<a href="#define-the-tables" class="hash-link" aria-label="Direct link to Define the tables" title="Direct link to Define the tables" translate="no">​</a></h2>
<p>Add three tables. All of them are private: players only learn about their own match, through the view.</p>
\<ul\>
<li class=""><code>queue_entry</code> has one row per waiting player, with the time they joined.</li>
<li class=""><code>game_match</code> has one row per match.</li>
<li class=""><code>match_player</code> has one row per player in a match. Its primary key is the player&#x27;s identity, so a player can only be in one match at a time. It has an index on <code>match_id</code>, to find every player in a match.</li>
</ul>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="join-the-queue-and-create-matches">Join the queue and create matches<a href="#join-the-queue-and-create-matches" class="hash-link" aria-label="Direct link to Join the queue and create matches" title="Direct link to Join the queue and create matches" translate="no">​</a></h2>
<p>Add a <code>join_queue</code> reducer. It refuses players who are already waiting or already in a match, adds the caller to the queue, then checks whether enough players are waiting to start a match.</p>
<p>If they are, the reducer creates a match with the players who have waited longest and removes them from the queue. A reducer runs as a single transaction, so two players joining at the same moment can never be put into two matches, or into a match with a player who just left.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="whats-next">What&#x27;s next?<a href="#whats-next" class="hash-link" aria-label="Direct link to What&#x27;s next?" title="Direct link to What&#x27;s next?" translate="no">​</a></h2>
<p>You now have a queue that groups waiting players into 4-player matches:</p>
\<ul\>
<li class=""><code>join_queue</code> adds players to the queue and creates a match as soon as enough of them are waiting, all in one transaction.</li>
<li class=""><code>leave_queue</code> and <code>client_disconnected</code> keep players who left out of new matches.</li>
<li class="">The per-player <code>my_match</code> view tells each player about their own match, and only theirs.</li>
</ul>
<p>To learn more about the features used here, see <a class="" href="/docs/functions/reducers">Reducers</a>, <a class="" href="/docs/functions/reducers/lifecycle">Lifecycle Reducers</a> and <a class="" href="/docs/functions/views">Views</a>.</p>
