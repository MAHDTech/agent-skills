page</button></div><div class="theme-doc-markdown markdown">\<header\>\<h1\>The Database Module</h1></header><p>A <strong>module</strong> is a collection of functions and schema definitions, which can be written in TypeScript, C#, Rust, or C++. Modules define the structure of your database and the server-side logic that processes and handles client requests.</p>
<p>A <strong>database</strong> is a running instance of a module. While a module is the code you write (schema and reducers), a database is the actual deployed entity running on a SpacetimeDB <strong>host</strong> with stored data and active connections.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="module-vs-database">Module vs Database<a href="#module-vs-database" class="hash-link" aria-label="Direct link to Module vs Database" title="Direct link to Module vs Database" translate="no">​</a></h2>
<p>Understanding this distinction is important:</p>
\<ul\>
<li class="">A <strong>module</strong> is the code you write; it defines your schema (tables) and business logic (reducers, procedures, and views). Modules are compiled and deployed to SpacetimeDB. Rust, C#, and C++ modules compile to WebAssembly, while TypeScript modules run on V8.</li>
<li class="">A <strong>database</strong> is a <em>running instance</em> of a module; it has the module&#x27;s schema and logic, plus actual stored data.</li>
</ul>
<p>You can deploy the same module to multiple databases (e.g. separate environments for testing, staging, production), each with its own independent data. When you update your module code and re-publish, SpacetimeDB will update the database&#x27;s schema/logic — the existing data remains (though for complicated schema changes you may need to handle migrations carefully).</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="whats-in-a-module">What&#x27;s in a Module?<a href="#whats-in-a-module" class="hash-link" aria-label="Direct link to What&#x27;s in a Module?" title="Direct link to What&#x27;s in a Module?" translate="no">​</a></h2>
<p>A module contains:</p>
\<ul\>
<li class=""><strong><a class="" href="/docs/tables">Tables</a></strong> - Define your data structure and storage.</li>
<li class=""><strong><a class="" href="/docs/functions/reducers">Reducers</a></strong> - Server-side functions that modify your data transactionally.</li>
<li class=""><strong><a class="" href="/docs/functions/procedures">Procedures</a></strong> - Functions that can perform external operations like HTTP requests and return results.</li>
<li class=""><strong><a class="" href="/docs/functions/views">Views</a></strong> - Read-only computed queries over your data.</li>
</ul>
<p>The logic is contained within these three categories of server-side functions: reducers (transactional state changes), procedures (functions with external capabilities), and views (read-only queries).</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="database-names">Database Names<a href="#database-names" class="hash-link" aria-label="Direct link to Database Names" title="Direct link to Database Names" translate="no">​</a></h2>
<p>When you publish a module, you give the database a name. Database names must match the regex <code>/^[a-z0-9]+(-[a-z0-9]+)*$/</code>, i.e. only lowercase ASCII letters and numbers, separated by dashes.</p>
<p><strong>Examples of valid names:</strong></p>
\<ul\>
<li class=""><code>my-game-server</code></li>
<li class=""><code>chat-app-production</code></li>
<li class=""><code>test123</code></li>
</ul>
<p>Each database also receives a unique <strong>identity</strong> (a hex string) when created. Clients can connect using either the name or identity.</p>

<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="deleting-a-database">Deleting a Database<a href="#deleting-a-database" class="hash-link" aria-label="Direct link to Deleting a Database" title="Direct link to Deleting a Database" translate="no">​</a></h3>
<p>To permanently delete a database and all its data:</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> delete</span><span style="color:#FF79C6"> <</span><span style="color:#F1FA8C">DATABASE_NAM</span><span style="color:#F8F8F2">E</span><span style="color:#FF79C6">></span></span></code></pre>
<p>You&#x27;ll be prompted to confirm the deletion. Use <code>--yes</code> to skip the confirmation in scripts.</p>
<div class="theme-admonition theme-admonition-warning admonition_Ph9R alert alert--warning"><div class="admonitionHeading_kG9t"><span class="admonitionIcon_VA_f"><svg viewBox="0 0 16 16"><path fill-rule="evenodd" d="M8.893 1.5c-.183-.31-.52-.5-.887-.5s-.703.19-.886.5L.138 13.499a.98.98 0 0 0 0 1.001c.193.31.53.501.886.501h13.964c.367 0 .704-.19.877-.5a1.03 1.03 0 0 0 .01-1.002L8.893 1.5zm.133 11.497H6.987v-2.003h2.039v2.003zm0-3.004H6.987V5.987h2.039v4.006z"></path></svg></span>warning</div><div class="admonitionContent_STxx"><p>Deleting a database is permanent and cannot be undone. All data will be lost.</p></div></div>
<p>For more options, see the <a class="" href="/docs/cli-reference#spacetime-delete"><code>spacetime delete</code> CLI reference</a>.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="querying-with-sql">Querying with SQL<a href="#querying-with-sql" class="hash-link" aria-label="Direct link to Querying with SQL" title="Direct link to Querying with SQL" translate="no">​</a></h3>
<p>You can run SQL queries directly against your database:</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> sql</span><span style="color:#FF79C6"> <</span><span style="color:#F1FA8C">DATABASE_NAM</span><span style="color:#F8F8F2">E</span><span style="color:#FF79C6">></span><span style="color:#E9F284"> "</span><span style="color:#F1FA8C">SELECT * FROM user</span><span style="color:#E9F284">"</span></span></code></pre>
<h4 class="anchor anchorTargetStickyNavbar_Y_NL" id="owner-privileges">Owner Privileges<a href="#owner-privileges" class="hash-link" aria-label="Direct link to Owner Privileges" title="Direct link to Owner Privileges" translate="no">​</a></h4>
<p><strong>Important:</strong> When you run SQL queries as the database owner, you bypass table visibility restrictions. This means you can query private tables that normal clients cannot access.</p>
<p>To test queries as an unprivileged client would see them, use the <code>--anonymous</code> flag:</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> sql</span><span style="color:#BD93F9"> --anonymous</span><span style="color:#FF79C6"> <</span><span style="color:#F1FA8C">DATABASE_NAM</span><span style="color:#F8F8F2">E</span><span style="color:#FF79C6">></span><span style="color:#E9F284"> "</span><span style="color:#F1FA8C">SELECT * FROM user</span><span style="color:#E9F284">"</span></span></code></pre>
<p>This executes the query as an anonymous client, respecting table visibility rules.</p>
<p>For more SQL options, see the <a class="" href="/docs/cli-reference#spacetime-sql"><code>spacetime sql</code> CLI reference</a>.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="viewing-logs">Viewing Logs<a href="#viewing-logs" class="hash-link" aria-label="Direct link to Viewing Logs" title="Direct link to Viewing Logs" translate="no">​</a></h3>
<p>View logs from your database:</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> logs</span><span style="color:#FF79C6"> <</span><span style="color:#F1FA8C">DATABASE_NAM</span><span style="color:#F8F8F2">E</span><span style="color:#FF79C6">></span></span></code></pre>
<h4 class="anchor anchorTargetStickyNavbar_Y_NL" id="following-logs-in-real-time">Following Logs in Real-Time<a href="#following-logs-in-real-time" class="hash-link" aria-label="Direct link to Following Logs in Real-Time" title="Direct link to Following Logs in Real-Time" translate="no">​</a></h4>
<p>To stream logs as they&#x27;re generated (similar to <code>tail -f</code>):</p>
<p><code>spacetime logs --follow \<DATABASE_NAME\></code></p>
<p>This keeps the connection open and displays new log entries as they occur. Press Ctrl+C to stop following.</p>
<h4 class="anchor anchorTargetStickyNavbar_Y_NL" id="limiting-log-output">Limiting Log Output<a href="#limiting-log-output" class="hash-link" aria-label="Direct link to Limiting Log Output" title="Direct link to Limiting Log Output" translate="no">​</a></h4>
<p>To view only the last N lines:</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> logs</span><span style="color:#BD93F9"> --num-lines</span><span style="color:#BD93F9"> 100</span><span style="color:#FF79C6"> <</span><span style="color:#F1FA8C">DATABASE_NAM</span><span style="color:#F8F8F2">E</span><span style="color:#FF79C6">></span></span></code></pre>
<p>For more logging options, see the <a class="" href="/docs/cli-reference#spacetime-logs"><code>spacetime logs</code> CLI reference</a>.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="listing-your-databases">Listing Your Databases<a href="#listing-your-databases" class="hash-link" aria-label="Direct link to Listing Your Databases" title="Direct link to Listing Your Databases" translate="no">​</a></h3>
<p>To see all databases associated with your identity:</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> list</span></span></code></pre>
<p>This shows database names, identities, and host servers.</p>
