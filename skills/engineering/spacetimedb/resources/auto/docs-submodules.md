class="theme-doc-markdown markdown">\<header\>\<h1\>Submodules</h1></header><p>A <strong>submodule</strong> is a SpacetimeDB module that can be included in another module&#x27;s database. The submodule&#x27;s tables and functions register under a <strong>namespace</strong> you choose, keeping them separate from the consumer&#x27;s own tables and from other submodules.</p>
<p>Submodules let you package reusable database logic as a library that any consumer can integrate without coordinating table names.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="multiple-and-nested-submodules">Multiple and Nested Submodules<a href="#multiple-and-nested-submodules" class="hash-link" aria-label="Direct link to Multiple and Nested Submodules" title="Direct link to Multiple and Nested Submodules" translate="no">​</a></h2>
<p>Multiple submodules compose freely. Each gets its own namespace, so name collisions between submodules are impossible.</p>
<div class="theme-tabs-container tabs-container tabList_duiv"><ul role="tablist" aria-orientation="horizontal" class="tabs"><li role="tab" tabindex="0" aria-selected="true" class="tabs__item tabItem_a1H9 tabs__item--active">TypeScript</li></ul><div class="margin-top--md"><div role="tabpanel" class="tabItem_w6aI"><pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#FF79C6">import</span><span style="color:#BD93F9"> *</span><span style="color:#FF79C6"> as</span><span style="color:#F8F8F2"> authLib    </span><span style="color:#FF79C6">from</span><span style="color:#E9F284"> &#x27;</span><span style="color:#F1FA8C">auth_lib</span><span style="color:#E9F284">&#x27;</span><span style="color:#F8F8F2">;</span></span>

<span class="line"><span style="color:#F8F8F2">  players,</span></span>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="environment-variables">Environment variables<a href="#environment-variables" class="hash-link" aria-label="Direct link to Environment variables" title="Direct link to Environment variables" translate="no">​</a></h2>
<p>Only the root module can declare a nonempty <a class="" href="/docs/databases/environment-variables">environment</a>. Including a submodule with environment declarations causes publication to fail. A module with such declarations can still be published independently as a root module.</p>
<p>Submodules have no separate environment-variable namespace, and their host-dispatched entry points cannot read the root module&#x27;s environment. Root module code can pass configuration values to helpers explicitly. Ordinary helper calls retain the calling entry point&#x27;s access, including calls to helpers defined in submodules.</p>

<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> call</span><span style="color:#F1FA8C"> my-database</span><span style="color:#E9F284"> "</span><span style="color:#F1FA8C">myauth.verify_token</span><span style="color:#E9F284">"</span><span style="color:#E9F284"> &#x27;</span><span style="color:#F1FA8C">"abc123"</span><span style="color:#E9F284">&#x27;</span></span></code></pre>
<p>Both parts of the wire name are canonical: the namespace prefix is the canonical namespace name
(<code>myauth</code> here, or <code>my_auth</code> for a submodule registered as <code>myAuth</code>), and the function name after
<code>.</code> is the canonical snake_case form of the submodule&#x27;s export name -- <code>verifyToken</code> in TypeScript
is <code>verify_token</code> on the wire. Generated client bindings expose the camelCase accessors instead,
as shown above.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="namespace-name-rules">Namespace Name Rules<a href="#namespace-name-rules" class="hash-link" aria-label="Direct link to Namespace Name Rules" title="Direct link to Namespace Name Rules" translate="no">​</a></h2>
<p>Both the accessor name (the key you register the submodule under) and the canonical name (derived from it, or given explicitly via <code>name</code>) must be valid SpacetimeDB identifiers: start with a letter or underscore, continue with letters, digits, or underscores, maximum 63 characters, case-insensitive for resolution. Two submodules cannot share a canonical name, so <code>myAuth</code> and <code>my_auth</code> cannot both be registered under the default policy. A submodule can be registered under at most one namespace per consumer module.</p>
<p>The reserved namespaces <code>public</code>, <code>st</code>, <code>spacetimedb</code>, and <code>pg_*</code> cannot be used as submodule namespaces.</p>
