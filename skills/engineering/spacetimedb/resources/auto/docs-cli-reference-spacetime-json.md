tocMobile_xBih"><button type="button" class="clean-btn tocCollapsibleButton_Dk1U">On this page</button></div><div class="theme-doc-markdown markdown">\<header\>\<h1\><code>spacetime.json</code> Configuration File</h1></header>
<p>The <code>spacetime.json</code> file defines project-level configuration for the SpacetimeDB CLI. It eliminates repetitive CLI flags and enables multi-target workflows such as publishing multiple databases or generating bindings for multiple languages from a single project.</p>
<p>Commands that read <code>spacetime.json</code> include <a class="" href="/docs/cli-reference#spacetime-publish"><code>spacetime publish</code></a>, <a class="" href="/docs/cli-reference#spacetime-generate"><code>spacetime generate</code></a>, and <a class="" href="/docs/cli-reference#spacetime-dev"><code>spacetime dev</code></a>. Commands that operate on an already-published database, such as <a class="" href="/docs/cli-reference#spacetime-call"><code>spacetime call</code></a>, <a class="" href="/docs/cli-reference#spacetime-sql"><code>spacetime sql</code></a>, and <a class="" href="/docs/cli-reference#spacetime-logs"><code>spacetime logs</code></a>, can resolve their database and server from matching config targets. Commands that operate on a server rather than a named config database, such as <a class="" href="/docs/cli-reference#spacetime-list"><code>spacetime list</code></a>, <a class="" href="/docs/cli-reference#spacetime-rename"><code>spacetime rename</code></a>, and <a class="" href="/docs/cli-reference#spacetime-mcp"><code>spacetime mcp</code></a>, can also use the configured server when the config has a single unambiguous server.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="config-structure">Config structure<a href="#config-structure" class="hash-link" aria-label="Direct link to Config structure" title="Direct link to Config structure" translate="no">​</a></h2>
<p>The config is database-centric. The top-level object represents the root database, which is always required. The root database may have <code>children</code> that define additional database targets, each inheriting the root&#x27;s settings by default.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="generate-configuration">Generate configuration<a href="#generate-configuration" class="hash-link" aria-label="Direct link to Generate configuration" title="Direct link to Generate configuration" translate="no">​</a></h2>
<p>The <code>generate</code> key is an array of objects. Each object configures bindings generation for a specific language and output location.</p>
<table><thead><tr><th>Field</th><th>Type</th><th>Description</th></tr></thead>\<tbody\><tr><td><code>language</code></td><td>string</td><td>Target language: <code>typescript</code>, <code>csharp</code>, <code>rust</code>, <code>unrealcpp</code> (required)</td></tr><tr><td><code>out-dir</code></td><td>string</td><td>Output directory for generated files</td></tr><tr><td><code>namespace</code></td><td>string</td><td>C# namespace (<code>csharp</code> only)</td></tr><tr><td><code>unreal-module-name</code></td><td>string</td><td>Unreal module name (<code>unrealcpp</code> only)</td></tr><tr><td><code>uproject-dir</code></td><td>string</td><td>Unreal project directory (<code>unrealcpp</code> only)</td></tr><tr><td><code>include-private</code></td><td>boolean</td><td>Include private tables in generated code</td></tr></tbody></table>

<p>When <code>spacetime generate</code> runs, it deduplicates by module path. If multiple databases share the same module and generate config (for example, via inheritance), bindings are generated once.</p>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="children-and-inheritance">Children and inheritance<a href="#children-and-inheritance" class="hash-link" aria-label="Direct link to Children and inheritance" title="Direct link to Children and inheritance" translate="no">​</a></h2>
<p>The <code>children</code> array defines additional database targets. Each child inherits most fields from the root by default.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="what-children-inherit">What children inherit<a href="#what-children-inherit" class="hash-link" aria-label="Direct link to What children inherit" title="Direct link to What children inherit" translate="no">​</a></h3>
<p>All fields listed in the <a href="#fields-reference" class="">Fields reference</a> with "Yes" in the Inherited column are inherited. A child can override any inherited field by specifying it explicitly.</p>
<p>The following fields are never inherited:</p>
\<ul\>
<li class=""><code>database</code>: each child must define its own.</li>
<li class=""><code>generate</code>: tied to a specific module and output location. Inheriting generate targets is redundant when the child shares the parent&#x27;s module (deduplication already handles it) and dangerous when the child uses a different module (two modules would write bindings into the same output directory).</li>
<li class=""><code>children</code>: structural, not a database property.</li>
<li class=""><code>dev</code>: root-level only.</li>
</ul>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="source-conflict-rule">Source conflict rule<a href="#source-conflict-rule" class="hash-link" aria-label="Direct link to Source conflict rule" title="Direct link to Source conflict rule" translate="no">​</a></h3>
<p><code>module-path</code>, <code>bin-path</code>, and <code>js-path</code> are mutually exclusive module sources (mirroring the CLI&#x27;s existing conflict group for <code>--module-path</code>, <code>--bin-path</code>, and <code>--js-path</code>). If a child specifies any one of these, the other two are not inherited from the parent. This prevents a child from accidentally inheriting a <code>bin-path</code> that points to a different module&#x27;s precompiled binary.</p>

<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="behavior">Behavior<a href="#behavior" class="hash-link" aria-label="Direct link to Behavior" title="Direct link to Behavior" translate="no">​</a></h3>
<p>When running <code>spacetime dev</code>:</p>
\<ol\>
<li class="">Build all modules defined in the config.</li>
<li class="">Generate bindings for all databases.</li>
<li class="">Publish all databases.</li>
<li class="">Run the client dev server specified by <code>dev.run</code>.</li>
<li class="">Watch for changes and repeat steps 1-4.</li>
</ol>
<p>The <code>--server</code> flag overrides the server for all databases. The <code>--skip-publish</code> flag skips step 3, and <code>--skip-generate</code> skips step 2.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="config-auto-generation">Config auto-generation<a href="#config-auto-generation" class="hash-link" aria-label="Direct link to Config auto-generation" title="Direct link to Config auto-generation" translate="no">​</a></h3>
<p>If no config file exists, <code>spacetime dev</code> generates a <code>spacetime.json</code> with the server and module path, and a <code>spacetime.local.json</code> with the database name. The command prompts for the database name (pre-filled with the directory name as the default).</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="safety-prompt">Safety prompt<a href="#safety-prompt" class="hash-link" aria-label="Direct link to Safety prompt" title="Direct link to Safety prompt" translate="no">​</a></h3>
<p><code>spacetime dev</code> tracks which config file the publish targets were resolved from. If the database is defined in <code>spacetime.json</code> (which is checked into git and typically defines shared or production databases), the command prompts for confirmation before publishing. Databases defined in dev-specific or local config files (such as <code>spacetime.dev.json</code> or <code>spacetime.local.json</code>) do not trigger this prompt.</p>

<span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> publish</span><span style="color:#E9F284"> "</span><span style="color:#F1FA8C">world-*</span><span style="color:#E9F284">"</span></span></code></pre>
<p>When no database name is provided, all databases are selected. When a filter matches no databases, the CLI reports an error:</p>
<div class="language-text codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><div class="codeBlockContent_VOyQ"><pre tabindex="0" class="prism-code language-text codeBlock_evfK thin-scrollbar" style="color:#bfc7d5;background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="token-line" style="color:#bfc7d5"><span class="token plain">$ spacetime publish typo-name</span><br></span><span class="token-line" style="color:#bfc7d5"><span class="token plain">Error: No database &#x27;typo-name&#x27; found in spacetime.json.</span><br></span><span class="token-line" style="color:#bfc7d5"><span class="token plain">Use --no-config to ignore the config file.</span><br></span></code></pre></div></div>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="flag-overrides">Flag overrides<a href="#flag-overrides" class="hash-link" aria-label="Direct link to Flag overrides" title="Direct link to Flag overrides" translate="no">​</a></h2>
<p>All CLI flags besides the database selector act as overrides. They are classified as global, per-database, or per-generate-entry:</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="global-overrides">Global overrides<a href="#global-overrides" class="hash-link" aria-label="Direct link to Global overrides" title="Direct link to Global overrides" translate="no">​</a></h3>
<p>These apply to all selected databases:</p>
\<ul\>
<li class=""><code>--server</code>: target server</li>
<li class=""><code>--break-clients</code>: allow breaking changes</li>
<li class=""><code>--delete-data=\<mode\></code>: clear database data (<code>always</code>, <code>on-conflict</code>, or <code>never</code>)</li>
<li class=""><code>--yes</code>: skip confirmation prompts</li>
</ul>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="per-database-overrides">Per-database overrides<a href="#per-database-overrides" class="hash-link" aria-label="Direct link to Per-database overrides" title="Direct link to Per-database overrides" translate="no">​</a></h3>
<p>These produce an error if multiple databases are selected:</p>
\<ul\>
<li class=""><code>--module-path</code>: module source path</li>
<li class=""><code>--bin-path</code>: precompiled WASM path</li>
<li class=""><code>--js-path</code>: JS bundle path</li>
<li class=""><code>--build-options</code>: build flags</li>
<li class=""><code>--num-replicas</code>: replica count</li>
</ul>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="per-generate-entry-overrides">Per-generate-entry overrides<a href="#per-generate-entry-overrides" class="hash-link" aria-label="Direct link to Per-generate-entry overrides" title="Direct link to Per-generate-entry overrides" translate="no">​</a></h3>
<p>These produce an error if the selected database has multiple generate entries:</p>
\<ul\>
<li class=""><code>--lang</code>: target language</li>
<li class=""><code>--out-dir</code>: output directory</li>
<li class=""><code>--namespace</code>: C# namespace</li>
<li class=""><code>--unreal-module-name</code>: Unreal module name</li>
<li class=""><code>--uproject-dir</code>: Unreal project directory</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="--no-config"><code>--no-config</code><a href="#--no-config" class="hash-link" aria-label="Direct link to --no-config" title="Direct link to --no-config" translate="no">​</a></h2>
<p>The <code>--no-config</code> flag causes the CLI to ignore <code>spacetime.json</code> entirely, behaving as if no config file exists. This is useful for one-off operations, scripting, or commands such as <code>spacetime list</code> when you want the default server instead of the server configured for the current project.</p>
<pre tabindex="0" class="codeBlockStandalone_LlrK thin-scrollbar codeBlockContainer_hFbQ theme-code-block" style="--prism-color:#bfc7d5;--prism-background-color:#292d3e"><code class="codeBlockLines_JqGU"><span class="line"><span style="color:#50FA7B">spacetime</span><span style="color:#F1FA8C"> publish</span><span style="color:#F1FA8C"> my-db</span><span style="color:#BD93F9"> --module-path</span><span style="color:#F1FA8C"> ./module</span><span style="color:#BD93F9"> --no-config</span></span></code></pre>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="--env-and-environments"><code>--env</code> and environments<a href="#--env-and-environments" class="hash-link" aria-label="Direct link to --env-and-environments" title="Direct link to --env-and-environments" translate="no">​</a></h2>
<p>Config files support environment and local overrides via a naming convention:</p>
<table><thead><tr><th>File</th><th>Purpose</th><th>Checked in to git?</th></tr></thead>\<tbody\><tr><td><code>spacetime.json</code></td><td>Project defaults</td><td>Yes</td></tr><tr><td><code>spacetime.{env}.json</code></td><td>Environment-specific config</td><td>Yes</td></tr><tr><td><code>spacetime.local.json</code></td><td>User-specific overrides</td><td>No</td></tr><tr><td><code>spacetime.{env}.local.json</code></td><td>User + environment-specific overrides</td><td>No</td></tr></tbody></table>
<p>The <em>env</em> placeholder is set via the <code>--env</code> CLI flag (for example, <code>--env dev</code>). The <code>spacetime dev</code> command implicitly uses <code>--env dev</code>.</p>
<p>When <code>--env</code> is not specified, <code>spacetime publish</code> and <code>spacetime generate</code> load only the base config files (<code>spacetime.json</code> and <code>spacetime.local.json</code>).</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="precedence">Precedence<a href="#precedence" class="hash-link" aria-label="Direct link to Precedence" title="Direct link to Precedence" translate="no">​</a></h3>
<p>From highest to lowest priority:</p>
\<ol\>
<li class="">CLI flags (highest)</li>
<li class=""><code>spacetime.{env}.local.json</code></li>
<li class=""><code>spacetime.{env}.json</code></li>
<li class=""><code>spacetime.local.json</code></li>
<li class=""><code>spacetime.json</code></li>
<li class="">Built-in defaults (lowest)</li>
</ol>
<p>CLI flags only override config values when explicitly provided by the user. Default flag values do not override config file values.</p>
<h3 class="anchor anchorTargetStickyNavbar_Y_NL" id="override-behavior">Override behavior<a href="#override-behavior" class="hash-link" aria-label="Direct link to Override behavior" title="Direct link to Override behavior" translate="no">​</a></h3>

<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="config-file-discovery">Config file discovery<a href="#config-file-discovery" class="hash-link" aria-label="Direct link to Config file discovery" title="Direct link to Config file discovery" translate="no">​</a></h2>
<p>The CLI searches for <code>spacetime.json</code> starting from the current directory and walking up the directory tree until it finds one or reaches the filesystem root. All paths in the config are relative to the directory containing <code>spacetime.json</code>.</p>
<h2 class="anchor anchorTargetStickyNavbar_Y_NL" id="editor-support">Editor support<a href="#editor-support" class="hash-link" aria-label="Direct link to Editor support" title="Direct link to Editor support" translate="no">​</a></h2>
<p>The config file uses JSON5 syntax, which supports comments and trailing commas. The file uses a <code>.json</code> extension for broad editor compatibility.</p>
